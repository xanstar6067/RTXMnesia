## Состояние Unity-проекта

HDRP-база (`Assets/Editor/ConfigureHDRP.cs`, меню Tools > RTXMnesia > Configure HDRP, `Assets/Settings/*`, `SampleScene`), импортёры ресурсов и уровней (`Assets/Editor/Importer`), компоненты уровня, игрок и рантайм скриптов уровней (`Assets/Scripts`). Первый уровень: `Assets/AmnesiaImported/Levels/maps/main/ch01/00_rainy_hall.unity` (генерируется, не в git). В нём Play запускает скрипт уровня — вступление, пробуждение, события по зонам; пропы — физические тела с шарнирами, их можно брать, толкать, открывать (двери, ящики, рычаги, колёса), зажигать лампы, подбирать предметы; звук и музыка, частицы, ореолы ламп, контур и мерцание предметов, шрифты HUD как в оригинале. Вторая карта — `01_old_archives`, третья — хаб `02_entrance_hall`; дверь уровня и `ChangeMap` переводят на другую карту с экраном загрузки, при возвращении состояние карты восстанавливается, фонарь в руке работает.
Fixed Timestep = 1/60 (как шаг логики HPL2, `EngineInitVars mlUpdateRate`).
DLSS (вкладка RTX) — см. «DLSS и вкладка RTX»; аппаратная трассировка лучей (освещение «Трассировка лучей») — см. «Трассировка лучей». Подробности: `UnityProj/UMnesiaRTX/HDRP-SETUP.md`.
Стартовая сцена сборки — импортированное главное меню `Assets/AmnesiaImported/Levels/main_menu/main/menu_bg.unity`; новая игра загружает `00_rainy_hall`. Play открытой игровой карты в редакторе по-прежнему запускает её напрямую. Возврат в главное меню доступен из Esc с подтверждением. Импортированные игровые карты сами попадают в список сцен сборки (по имени их находит смена карты).
Headless-запуск Unity: `C:/Program Files/Unity/Hub/Editor/6000.6.2f1/Editor/Unity.exe -batchmode -nographics -quit -projectPath ... -executeMethod ...`.

Всё лежит **распакованным** (архивов нет), форматы открытые. Корень = виртуальная ФС движка; список папок — `resources.cfg`.

Расширения: `.dds` 1901, `.dae` 1467 (COLLADA 1.4.1, Maya), `.msh` 1462 (бинарный кэш меша HPL, дублирует .dae — берём `.dae`), `.snt` 979, `.ent` 909, `.mat` 860, `.tga` 467, `.ogg` 2889.

Форматы:
- **`.mat`** — XML: `<Main Type="SolidDiffuse" PhysicsMaterial="Rock">` + `<TextureUnits>` (`Diffuse`, `NMap`, `Specular`, `Height` → имена `.dds`). Spec-карта у Amnesia → нужно конвертить в Metallic/Smoothness/Mask для HDRP.
- **`.ent`** — XML: `<ModelData>` с `Mesh Filename=...dae`, SubMesh→материал, `<Shapes>` (коллизии: Box/Cylinder/…), далее `UserDefinedVariables` (тип сущности, масса, звуки).
- **`.map`** — XML: `<StaticObject>` (769 в одной карте), `<Entity>`, `<PointLight>`/`<SpotLight>`, `<Area>`, `<Billboard>`, `<ParticleSystem>`, `<Decal>`, `<Plane>`, `<Compound>`, `<Var>`; позиции/повороты/масштаб в атрибутах. Приложен встроенный геометрический кэш для декалей/комбинированных объектов.
- **`.hps`** — AngelScript, логика уровня (триггеры, таймеры, `SetPlayerActive`, `PlayMusic`, `AddTimer`, коллбэки областей). Нужен интерпретатор-замена на C# (или ручной порт).
- **Единицы/оси**: метры; осей Y-up (проверить при импорте — COLLADA up_axis и знак Z).

## Исходный код (src/AmnesiaTheDarkDescent)

- `amnesia/src/game/` — игровая логика, префикс `Lux*`: `LuxPlayer*`, `LuxEnemy_*` (Grunt, ManPig, WaterLurker), `LuxArea_*` (Ladder, Rope, Liquid, Script, Insanity…), `LuxHandObject_*` (лампа, масло, мили), `LuxInventory`, `LuxMapHandler`, `LuxScriptHandler`, `LuxInsanityHandler`, `LuxSaveHandler`, `LuxMusicHandler` и т.д. Это **спецификация поведения** — портируем на C#, не компилируем.
- `HPL2/core/` — движок: `include/` (рендер `graphics/`, физика `physics/` (Newton), `scene/`, `resources/` загрузчики форматов, `sound/`), `sources/`. Полезно читать загрузчики `.mat/.ent/.map/.msh` для точного формата и `graphics/` для понимания G-buffer/освещения.
- `HPL2/tools/` — редакторы (`mshconverter`, `texconverter`, `editors`) — справка по форматам.
- Сборка оригинала невозможна (нужен FBX SDK 2012, которого нет) — и не нужна. Код = GPLv3.

## Ключевые факты для плана

- Оригинальный рендер: OpenGL deferred, динамическое освещение, Newton physics, AngelScript, OpenAL.
- Основное освещение игры — динамические point/spot-света + SSAO + ambient; запечённого GI нет. Это хорошо ложится на HDRP (+ RTGI/RT shadows/RT reflections позже).
- Карты состоят из огромного числа статик-объектов, ссылающихся на `.dae`/`.mat` → импорт должен кэшировать и переиспользовать меши/материалы.

## Импортёры (Assets/Editor/Importer, namespace RTXMnesia.Importer)

Меню: **Tools > RTXMnesia > Import**. Лог: `UnityProj/UMnesiaRTX/Logs/AmnesiaImport.log`.
Batch-методы `RTXMnesia.Importer.ImportMenu.*` (Unity с этим проектом должен быть закрыт; проверять lock `Temp/UnityLockfile`):
`ConvertMaterialsBatch`, `ConvertModelsBatch` с `[-amnesiaFolder <папка в source>] [-forceTextures] [-describe a.dae,b.dae]`;
`RenderMaterialsBatch`/`RenderModelsBatch` — сцена-витрина + рендер в `Logs/<Kind>Preview.png` (без `-nographics`, нужен GPU).
Быстрая проверка компиляции без Unity: Roslyn `Editor/Data/DotNetSdk/.../csc.dll` + ссылки на `Managed/UnityEngine/*Module.dll` и HDRP dll из `Library/ScriptAssemblies` (фасады UnityEngine.dll/UnityEditor.dll не подключать).
Проверка скриптов сборки игрока: `-batchmode -nographics -quit -executeMethod RTXMnesia.EditorDev.BuildCheck.RunBatch` — компилирует скрипты для Windows, как сборка (без сцен), и выводит ошибки и предупреждения об устаревшем API (CS0618 / CS0612 / CS0619) наших сборок; устаревшие вызовы вызывают при сборке диалог Script Updating Consent. Свойства HDRP, объявленные устаревшими, заменять API `Light` (например, `HDAdditionalLightData.shapeRadius` → `Light.shapeRadius`).
Шейдеры, которые рантайм ищет по имени (`Shader.Find`), попадают в сборку только по ссылке из включённого ассета или из списка Always Included Shaders. `Assets/Editor/EnsureRuntimeShaders.cs` держит в этом списке HplBoxLight, HplEffectRenderer, HplFogArea, HplScreenEffects и HplGui (при загрузке редактора и перед каждой сборкой). Без него в сборке не было box-света, контура и мерцания предметов. Новый шейдер, который ищется по имени, добавлять в его список.
Полный импорт `static_objects` + `entities`: ~3 мин, ~1 GB в `Assets/AmnesiaImported`.

- `ResourceIndex` — поиск как `FileSearcher::GetFilePath` HPL2: индекс по имени, при дубликатах сравнение компонентов папок с конца в обоих направлениях. Путь из `.map/.ent/.dae` нельзя отбрасывать: `castlebase/wall/default.dae` и `castlebase/stairs/default.dae` — разные модели. Старые префиксы дисков экспортёра не мешают сравнению папок; для голого имени используется папка ссылающегося файла, затем порядок `resources.cfg`.
- `DdsDecoder` — DXT1/3/5, ATI2(BC5), несжатые 24/32 бит, кубкарты. Форматы в игре: DXT1 1131, DXT5 714, BGRA32 36, ATI2 12, кубкарт 4.
- `TextureConverter` — DDS → PNG в `Assets/AmnesiaImported/Textures/<путь>__<роль>.png`; роли: albedo, normal, mask, specular, height, emissive. Настройки импорта — `TextureImportRules` по роли из имени.
- `MaterialConverter` — `.mat` → HDRP материал в `Assets/AmnesiaImported/Materials/<путь>.mat`; существующие обновляются на месте (GUID сохраняется). Константы тюнинга вверху файла. Alpha-декали HDRP не меняют metallic/smoothness/AO, `_DecalBlend = 1`, `_MaskBlendSrc = 0`; после настроек вызывается `HDMaterial.ValidateMaterial`. Переимпорт также обновляет цветовые копии HDRP/Decal в `Levels/**/*_generated.asset`, сохраняя tint и GUID/local ID; карты пересобирать не нужно. Проверки: `RTXMnesia.EditorDev.DecalMaterialTests.RunBatch` (без GPU), `RunRenderBatch` (GPU, сравнение прозрачной декали со старой/исправленной конфигурацией и полного/половинного смешивания), результаты в `Logs/DecalCheck`.
- Прозрачные HDRP/Lit (Alpha / PremulAlpha, в том числе `trail_amnesia_floor`, `blood_pool_static`) — `_EnableBlendModePreserveSpecularLighting = 0`: весь фрагмент, включая блик, смешивается по альфе. Иначе даже при альфе 0 виден прямоугольник подмеша (проверено перед комнатой записки в `01_old_archives`). Переимпорт исправляет также прозрачные цветовые копии внутри карт. `DecalMaterialTests.RunRenderBatch` проверяет оба прозрачных режима; `RunArchivesRenderBatch` сохраняет сравнение указанной комнаты, временно меняя материалы только в памяти. `BuildRenderPlayerBatch` собирает отдельный release-плеер в `Logs/DecalCheck/Player/DecalCheck.exe`; запуск с `-batchmode -decalOutput <абсолютная папка> -logFile <лог>` проверяет рендер в билде. Его `HplDecalRenderProbe` компилируется только при `UNITY_EDITOR` / `RTXMNESIA_RENDER_TEST`, тестовая сцена и ресурсы — в игнорируемом `AmnesiaImported/Preview/DecalPlayer`, список сцен основной сборки не меняется.
- `ImageLoader` — .dds/.tga/.jpg/.png → пиксели «верхняя строка первой» (HPL2 грузит всё через DevIL с IL_ORIGIN_UPPER_LEFT). Текстура без расширения → перебор форматов, как `TextureManager::FindTexture2D`.
- `TextureConverter.Version` — при изменении математики конвертации увеличить: PNG старше момента смены версии перегенерируются.
- `ModelConverter` + `HplCollada` + `HplModelBuilder` — модели без скелета читаются собственным парсером Collada (1.4 и старый 1.3), сохраняются в `Models/<путь>.prefab` и `<путь>_meshes.asset`. Собственный масштаб узла запекается в вершины и снимается с узла; единицы файла применяются только для FBX COLLADA exporter. Встроенный импорт Unity (`ModelImportRules`) остаётся для скелетных моделей. При изменении сборки или выбора ресурсов повышать `HplModelBuilder.Version`, чтобы пересобрать старые префабы.
- Сохранение мешей (`HplModelBuilder.Version = 7`): файл `*_meshes.asset` не удаляется при пересборке; существующие подмеши обновляются на месте по имени с сохранением GUID/local ID, новые добавляются, затем файл явно сохраняется. Упакованные в карты сущности ссылаются на подмеши напрямую: прежнее удаление/создание файла оставляло коллизии, но убирало мебель и записки. Отсутствующий меш в префабе также делает кэш устаревшим. Восстановление всех уже импортированных сцен (основная игра, Justine, меню, dev_room) и рук: `RTXMnesia.EditorDev.ModelReferenceTests.RepairAllBatch`; независимый повторный аудит с диска — `AuditAllBatch`; `RunBatch` дважды пересобирает стол, шкаф, записку и бумагу и проверяет сохранение ID после принудительного переимпорта файла. При массовом восстановлении общий банк анимаций собирается один раз, `LevelConverter.ReuseAnimationBank` сбрасывается в `finally`.
- Коллизия статики: примитивный коллайдер отменяет mesh-коллизию только своего подмеша; наличие обычного `_collider`-меша отменяет визуальные mesh-коллайдеры всей модели. `Collides=false` отключает коллизии экземпляра. Коллайдеры `_charcollider` — на слое 30 (`HplPhysicsWorld.NoCollideLayer`): как `SetCollide(false)` в HPL2, их видит только проверка персонажа, тела проходят сквозь них, луч фокуса их пропускает (на `01_old_archives` рычаг стоял внутри такого коллайдера и бился о пределы). Изменение сборки → `HplModelBuilder.Version` = 6, `ModelImportRules.GetVersion` = 3.
- Кэш `.msh`: в оригинале `Main ForceCacheLoadingAndSkipSaving` по умолчанию true (`LuxConfigHandler.cpp:73`) — игра рисует `.msh`, если он есть, а не `.dae`. Часть кэшей записана другой версией загрузчика Collada (у `zimmarman_ground.dae` X узловых сдвигов Z_UP отрицается, у `zimmarman_shrubb_dead.dae` той же карты — нет). Поэтому сборщик (`HplModelBuilder.ApplyMeshCache`, чтение — `HplMsh`) ставит подмеш по матрице `.msh`, если вершины совпадают с кэшем, а матрица — нет (лог: «placed as in the mesh cache»). У сущностей трансформ подмеша всё равно задаёт `.ent`.

Проверенные по исходникам HPL2 конвенции:
- UV COLLADA: движок делает `v = 1 - v`, DDS грузится верхней строкой в v=0 → в Unity UV не трогаем, PNG сохраняем как DDS (верх = верх).
- Нормали: бинормаль движка смотрит «вниз по картинке» → зелёный канал инвертируем.
- Specular-карта: R = интенсивность, G = степень `exp2(G*10)+1`. В HDRP: Specular Color workflow, F0 = R × 0.08, smoothness = 1 − sqrt(sqrt(2/(n+2))).
- Height — в альфа-канале. Юнит `Alpha` = alpha test по альфе диффуза. `Illumination` = emissive (у ламп регулируется в игре).
- Имя материала у меша = имя текстуры из `<library_images>` `.dae` с расширением `.mat`.
- Height-карта Amnesia — это **глубина** (белое = глубже, relief mapping) → инвертируется для HDRP. Проверено численно: градиент инвертированной карты совпадает с normal map по знаку в обоих каналах (заодно подтверждает инверсию G).
- **Оси**: Unity-импорт Collada отражает X: HPL `(x,y,z)` → Unity `(-x,y,z)` (проверено на `corner_concave_round.dae`). Позиции из `.map`/`.ent` переводятся так же, повороты (Euler XYZ, радианы, M = Rz·Ry·Rx) — отражением: угол X сохраняется, Y и Z меняют знак; порядок вершин треугольников не меняется. Всё это — `Assets/Scripts/Hpl/HplSpace.cs`; проверено на уровне (стены стыкуются, двери/люстры на местах). Свет и камеры HPL смотрят в локальный −Z (Unity +Z) → `HplSpace.LookRotation`. UV из .map (плоскости, декали, билборды): v = 1 − v.
- **Z_UP Collada**: собственный парсер повторяет HPL2: вершины/нормали `(x,y,z) → (-x,z,y)`, translate/scale `(x,z,y)`, rotate и matrix без перестановки. Затем применяется общее отражение X HPL→Unity. Старые поправки к встроенному импорту для нескелетных моделей больше не используются.
- Блендинг Mul/MulX2 (в HDRP нет; декали грязи и сырости `static_objects/decals`, лужи, бутылки, стёкла — ~30 материалов, на `00_rainy_hall` ~290 экземпляров `dirt_floor01`) — свой шейдер `Assets/Shaders/HplMultiply.shader`: множитель на освещённый цвет (HPL2 умножает альбедо в G-buffer — разница только в бликах), считается в гамме как в HPL2 (t·цвет экземпляра, ×2 для MulX2, клэмп для Mul), декали — до остальной прозрачности (очередь 2900) и с alpha test 0.01; туман HPL2 накладывается после декалей → множитель ослабляется непрозрачностью тумана (глобал `_HplFog` из `HplLighting.SetMultiplyFog`). Цвет декали карты для него не клэмпится (1.5 у `dirt_floor01_272`). Декаль Add → HDRP/Unlit additive, Alpha → HDRP/Decal. Без своего шейдера эти материалы выглядели белыми прямоугольниками.
- Вода — `Assets/Shaders/HplWater.shader` (см. «Дополнения 6.5 в)»). TODO: DissolveAlpha, кубкарты отражений непрозрачных и полупрозрачных материалов (заменяются HDRP/RT). ~10 моделей с материалом без .mat (кости, паук) — вероятно, материал задаётся в `.ent` (`SubMesh Material=`).
- `.ent` (сущности): `ModelData` = Mesh + SubMesh (материал-override), Shapes, Bodies (масса, физ. материал, какие подмеши привязаны), Joints (двери — JointHinge), Bones, Animations; `UserDefinedVariables EntityType="SwingDoor|..."` + звуки/поведение. Префабы из .ent делать на шаге 4 вместе с механиками.
  Важно: SubMesh в `.ent` хранит трансформ подмеша относительно сущности, он **заменяет** трансформ узла Collada (масштаб узла остаётся). Пример: дверь `castle` развёрнута там на 180°. Внутри `.ent` есть свои свет/билборды/частицы/звуки (`ModelData/Entities`), их позиции × масштаб экземпляра.

## Игрок (шаг 4, Assets/Scripts/Player, namespace RTXMnesia.Player)

Порт по исходникам, числа — только из `game.cfg` через `HplConfig` (`GetFloat("Player_Body","Mass")` как `cConfigFile`), в коде их нет.
- `HplCharacterBody` — порт `iCharacterBody` (CharacterBody.cpp): не Rigidbody, а вертикальный цилиндр, который двигается скоростями по направлениям (ускорение/торможение/разворот), гравитацией и силами, и выталкивается из мира после каждого шага; ступени — лучами (AccurateClimbing: 3 луча), камера на высоте стоячего тела + `CameraPosAdd`, сглаживание по `CameraSmoothPosNum` шагам. Формы — выпуклые MeshCollider-цилиндры на слое 2 (Ignore Raycast: их не видят запросы по умолчанию); неактивный размер (присед/стоя) — trigger. Не портировано: прилипание к движущимся телам (GravityAttachment), соединение с телом (Push).
- `HplPhysics.CheckShapeWorldCollision` — аналог `iPhysicsWorld::CheckShapeWorldCollision` (другие персонажи — игрок и враги — тоже препятствия, свои формы пропускаются; `collideCharacters: false` = `abCollideCharacter=false` — так проверяет голова наклона `cLuxPlayerLean`, иначе она упиралась в собственное тело игрока и Q/E не работали): OverlapBox + `Physics.ComputePenetration`, вектор выталкивания = покомпонентный максимум по контактам; с одним коллайдером до 4 итераций (PhysX даёт одно разделение на пару, Newton — список контактов). Тела с `CollideCharacter=false` и триггеры игнорируются. Поправка: если коллайдер выталкивает вбок, а на 3 см выше форма от него свободна, — вместо толчка подъём на нужную высоту (бинарный поиск, `LiftOverLowEdge`). Иначе ковры 1–2 см и пороги останавливают игрока: PhysX-меш толкает и по нормали низкой боковой грани, а подъём на ступени HPL2 видит только высоту > 2.5 см; Newton поднимал на такие края.
- `PlayerMoveNormal` — `cLuxMoveState_Normal`: ходьба/бег/присед/прыжок (сила прыжка + ослабление гравитации 0.22 с), покачивание головы и шаги на минимуме, отскок головы при приземлении, урон от падения. `PlayerLean` — `cLuxPlayerLean` (до 0.5 м и 15°, голова-цилиндр останавливается о стены).
- `AmnesiaPlayer` — `cLuxPlayer` + `cLuxInputHandler`:
  - логика 60 Гц разделена на `StepLogic` и `StepPhysics`. На уровне со скриптом их вызывает `HplMap` в порядке движка (`steppedByMap`), иначе FixedUpdate;
  - камера интерполируется между шагами;
  - мышь — каждый кадр: пиксели × чувствительность / (1.7 × высота экрана) × 2 рад, сглаживание как `GetSmoothMousePos` (веса 0.7^возраст в шагах 60 Гц — не зависит от FPS), питч ±70°;
  - смещения головы `HeadPosAdd` (Main/Bob/Lean/Script/ScreenShake/…) как `MoveHeadPosAdd`: x — вдоль правой оси тела, z — вдоль forward, без зеркала;
  - для скриптов: `active` (неактивный игрок не получает ввода), затухания FOV/aspect/крена как `cLuxPlayer::UpdateCamera`, `PlayerLookAt` (порт `cLuxPlayerLookAt`; углы считаются в терминах HPL2: yaw_HPL = π − yaw, pitch_HPL = −pitch, крен совпадает), здоровье/рассудок/масло с событиями для эффектов;
  - клавиши: WASD, Shift, Space, Ctrl (переключает присед), Q/E наклон, ЛКМ взаимодействие, ПКМ бросок, R — вращать взятый предмет мышью, колесо — дальность; F2 свободная камера (`FlyCamera`), Esc — меню паузы (`HplGameUi`, без карты — отпускает мышь), Tab — инвентарь, J — журнал, M — задания, N — последний текст;

## Физика сущностей (шаг 4.2, Assets/Scripts/Dynamics, namespace RTXMnesia.Dynamics)

Порт Newton-обёртки HPL2 (`iPhysicsBody`, `iPhysicsJoint*`, `iPhysicsWorld`) поверх PhysX.
- Пространство: позиции/направления HPL → Unity `(−x, y, z)`; осевые векторы (ω, момент) → `(x, −y, −z)`; кватернион `(x, −y, −z, w)`; матрица `S·M·S`, S = diag(−1,1,1,1) — `HplSpace`. `HplMatrix` — `cMatrixf`/`cMath` (MatrixRotate XYZ = Rz·Ry·Rx, GetRight/Up/Forward — строки, `GetAngleDistance`, `HplPid` = `cPidController`). Логику с углами писать в пространстве HPL через `Hpl*`-аксессоры тела, а не переводить формулы.
- `HplPhysicsBody` (Rigidbody): масса 0 = кинематическое, interpolation только в Play, итерации решателя 12/4. `AddImpulse` = `ForceMode.VelocityChange` (`NewtonBodyAddImpulse` принимает Δv), в точке — масса × Δv. Damping Unity = clamp(d, 0.001, 1) × 0.02 × 60. Ограничение скорости повторяет ошибку HPL2 (длина сравнивается с max²). Статическое движение (`StaticLinearMove`/`StaticAngularMove`) — кинематический MovePosition/MoveRotation, поворот `RotateXYZ(ω·dt)·R` в пространстве HPL.
- Слои: `CollideNonCharacter=false` → слой 30 (`NoCollideLayer`, не сталкивается ни с чем); `CollideCharacter=false` → `Physics.IgnoreCollision` с формами персонажа (`SetCharacterShapes`).
- Комбинирование трения/упругости: порядок приоритетов Average < Min < Multiply < Max совпадает с Unity.
- `HplJoint`: Hinge → `HingeJoint`, остальные → `ConfigurableJoint`. Угол шарнира HPL = −(правый поворот ребёнка вокруг пина HPL) = AngleAxis в Unity вокруг отражённого пина = `HingeJoint.angle` (проверено `PhysicsTests`), лимиты PhysX = [min°, max°]. Диапазоны за ±π или min > max — мягкий лимит коррекцией скорости. Slider — connected anchor в центре диапазона, симметричный `linearLimit`. Ball — twist ±MaxTwist, swing по конусу, 0 = свободно. Перед шагом: обновление лимитов (допуск 0.002 рад / 0.0005 м), LimitAutoSleep, Sticky, события MinLimitReached/MaxLimitReached; после — разрыв по `currentForce` ≥ BreakForce.
- `HplPhysicsWorld`: `AddEntity` создаёт тела, затем джоинты; поиск тела по Rigidbody/коллайдеру/данным; `Step` для edit/batch.
- `HplBodyContacts` ([ExecuteAlways]) — `OnCollisionEnter` для пропов, реагирующих на удар; скорость до удара — `PreviousVelocityAt`.
- ContinuousCollision из `.ent`: динамическим телам — `ContinuousDynamic` (протяжка), кинематическим — `ContinuousSpeculative`. Спекулятивный режим пропускал тонкий пол под быстро вращающимися осколками и накачивал скорость удерживаемому предмету, вдавленному в пол.
- Прогон шага: в Play FixedUpdate делает часть до симуляции, корутина `WaitForFixedUpdate` — после. В edit/batch `Physics.simulationMode = Script` и `HplMap.Step` вызывает `Physics.Simulate`.
- Проверка: `-executeMethod RTXMnesia.EditorDev.PhysicsTests.RunBatch` — синтетические шарнир (знак угла, лимиты, закрытие [0°, 2°], мягкий лимит 120°) и слайдер [0, 0.5].

## Скрипты уровней (шаг 5, Assets/Scripts/ScriptApi, Effects, Ui, Levels)

**Порт уровня.** Класс `: HplScript` с атрибутом `[HplMapScript("maps/main/chXX/<карта>.map")]` в `Assets/Scripts/Levels/ChXX/`. `HplMap` находит его по пути карты, переимпорт не нужен. Журнал — `docs/ScriptPort/chXX/<карта>.md`, статусы функций — `docs/ScriptPort/api.md`.
- Функции движка — в `HplScript*.cs` с оригинальными именами и параметрами (порт `LuxScriptHandler.cpp`). Порт читается как `.hps`.
- Сверка порта с оригиналом: `tools/Check-ScriptPort.ps1 -Map <карта> -Port <файл .cs>` — функции, строки, число вызовов каждой функции, числа и коллбэки из `.map`; у готовых портов 0 ошибок и 0 предупреждений, оставшиеся расхождения объясняются в журнале карты.
- Колбэки вызываются по имени, как в AngelScript. В порте имена писать через `nameof(...)`; динамические имена остаются строками.
- Преобразования AngelScript → C#:
  - `int x = RandFloat(...)` → `(int)RandFloat(...)` (отбрасывание);
  - `or`/`and` → `||`/`&&`;
  - `0.7` → `0.7f`.
- Глобальные переменные скрипта — поля класса. Локальные и глобальные переменные хранятся строками, как в HPL2 (`HplMath`: atoi/atof, `%.20f`).
- Части движка, которых ещё нет (мульти-слайдеры, кнопки), — `NotPorted`: одно предупреждение `[Script] X: skipped, needs …` на функцию. Состояние (двери, лампы, предметы, квесты) при этом хранится, `Get*` возвращают заданное.
- Ошибки, которые пишет сам движок (`Error()` HPL2 — в `hpl.log`, игра продолжается; например, скрипт просит свет, которого нет в карте), — `HplLog.Error` → предупреждение `[Script] ERROR: …`. Ошибка Unity при включённом в консоли Error Pause ставит Play на паузу. Настоящие ошибки Unity (`HplLog.PortError`, исключения) — только для ошибок порта.

- Тела `<сущность>_<тело>`, свет по имени, PlayerStart.

- Шаг 60 Гц:
  1. таймеры (перед ними очищается список мерцания рендерера эффектов, как в `cLuxMapHandler::Update`);
  2. логика активных сущностей: коллбэки столкновений и взгляда, затем `OnUpdate` пропов;
  3. игрок (`StepLogic`): движение, состояние (фокус и контур предмета), голова, наклон, взгляд, в конце коллбэки «Player», текст фокуса;
  4. HUD;
  5. эффекты;
  6. тело игрока (`StepPhysics`);

  9. свет (`AmnesiaLight.UpdateLight`: `FadeTo`, мерцание, его звуки и частицы);
  10. звук (`HplSoundHandler.Step`: звуковые сущности мира, записи, музыка);
  11. `StepPostUpdate` игрока (силы удержания);
  12. удаление сущностей, помеченных на уничтожение (их звуковые сущности уничтожаются, прикреплённые звуки остаются на месте и доигрывают; их системы частиц гаснут на месте).

- `OnStart`/`OnEnter` — после постановки игрока.

**Коллбэки столкновений** (`HplCollideCallbacks`, порт `iLuxCollideCallbackContainer`).
- Тест — `Physics.ComputePenetration` по текущим transform, без `Collider.bounds`: bounds обновляются только синхронизацией PhysX и отстают у тела, которое двигает код.
- Сохранена особенность HPL2: тело i владельца сравнивается с телом i другой сущности; области и персонажи отдают своё единственное тело для любого i.

**Эффекты** (`HplEffects`, порт `cLuxEffectHandler`) рисует `HplScreenEffectsPass`: HDRP custom pass AfterPostProcess, создаётся в рантайме, глобальные настройки HDRP не нужны. Шейдер `Assets/Shaders/HplScreenEffects.shader`.
- Рендерер эффектов (`HplEffectRenderer`, порт `cLuxEffectRenderer`, проход `HplEffectRendererPass` BeforePostProcess, шейдер `Assets/Shaders/HplEffectRenderer.shader`): контур предмета в фокусе (только предметы, с которыми можно взаимодействовать; маска видимых пикселей вместо stencil, увеличенный на 2 см объект синим 0.5 вне маски, два размытия на ¼ разрешения, сложение вне маски в прямоугольнике объекта) и мерцание предметов ближе 4 м (диффуз × (0.5, 0.5, 1) × rim × пульсация). Свечение врагов в темноте (`AddEnemyGlow`) не рисуется: альфа считается в `HplEnemy`.
- Порядок HPL2: ImageTrail → RadialBlur → Sepia (1D LUT `colorconv_sepia.tga`, по каналам) → затемнение (× (1 − alpha)) и вспышки (+).
- Расчёт в sRGB-значениях, как в гамма-рендере HPL2.
- След адаптирован к динамическому FPS: эталонный вес при 60 Гц `a60 = exp(-amount × 60 × 0.015)`, вес нового кадра `1 − (1 − a60)^(frameTime × 60)`. frameTime — реальное время между рендерами; накопление в RGBA16F, без залипания 8-битного буфера на высоком FPS.
- Тряска экрана — `HeadPosAdd.ScreenShake`.
- Голоса (`PlayVoiceEffect`) — потоки GUI (или 3D в позиции) через обработчик звука; реплика идёт, пока её запись жива (время клипа считает обработчик), затем следующая и колбэк окончания.

**DLSS и вкладка RTX** (2026-10-18) — `Hpl/HplDlss.cs`, вкладка «RTX» (шестая, `HplPauseMenu.Rtx`, `MenuControl.RtxTab`, списки `DlssMode` / `DlssPreset` в `HplGraphicsOptions`), поля `dlssMode` / `dlssPreset` в `HplUserSettings` (общие, PlayerPrefs).
- Модуль `com.unity.modules.nvidia` (встроенный DLSS HDRP: только Super Resolution / DLAA; Frame Generation и Ray Reconstruction в Unity нет). Ассет HDRP (`ConfigureHDRP` задаёт то же): динамическое разрешение включено (Hardware), единственный апскейлер — DLSS, оптимальные настройки, резкость 0, mip bias. Камера использует DLSS, только пока разрешает динамическое разрешение: `HplDlss.ConfigureCamera` в `beginContextRendering` (через `HplGraphics`) включает его игровым камерам (кроме зеркал воды) и ставит им AA None — DLSS сам делает временное сглаживание.

Модель: «Авто» или пресет NVIDIA (F — CNN, J / K — трансформер, L / M — трансформер 2); недоступные режиму (`GetAvailableDLSSPresetsForQuality`; на RTX 5080: DLAA F J K, Качество / Баланс J K, Производительность J K M, Макс. F J K L) серые, при смене режима неподходящая модель сбрасывается в «Авто». Пресеты в HDRP — на проект: `HplDlss` пишет их в поле `m_RenderPipelineSettings` ассета в памяти (сеттер вызывал бы OnValidate и пересоздание пайплайна), в редакторе при выходе из Play возвращает прежние — в ассет не сохраняются.
- Вкладка: слева DLSS, модель (серая при выключенном DLSS), строка «Рендер W x H / Вывод W x H» последней камеры DLSS или причина недоступности; справа «Трассировка лучей» — подсказка включить освещение «Трассировка лучей» / недоступна без DXR / настройки появятся позже. Многострочный текст — `DrawLines` (GUI-текст рисует одну строку).
- После апскейла: проход `HplScreenEffectsPass` (AfterPostProcess) работает в выходном разрешении — его буферы без dynamic scale, радиальное размытие и снимок меню берут `camera.pixelWidth`, а не `actualWidth`. Проходы до апскейла (box-свет, туман областей, контур / мерцание, вода, ореолы) читают пиксели по `_ScreenSize` рендера и не менялись. Не перенесено: маски реактивности для полупрозрачных (частицы, ореолы, Mul-декали без векторов движения — возможен лёгкий шлейф).

В `MenuPreview.RunBatch` — вкладка RTX: оба списка, выбор «Производительность», применение (камера рендерит ниже выходного размера), «DLSS» в сглаживании, снимки `Options_RTX_*.png`, `Options_1_DlssAA.png`.

**Трассировка лучей** (2026-10-18) — `Hpl/HplRayTracing.cs`; освещение «Трассировка лучей» (вкладка «Графика», `lighting` = 1, только при `SystemInfo.supportsRayTracing`) включает DXR, настройки эффектов — справа на вкладке RTX (видны только при этом освещении; все новые RT-настройки добавлять туда же).
- Ассет HDRP (`ConfigureHDRP` задаёт то же): `supportRayTracing`, экранные тени (`supportScreenSpaceShadows`), 16 слотов экранных теней. Камеры: `HplRayTracing.ConfigureCamera` в `beginContextRendering` (через `HplGraphics`) переопределяет frame settings RayTracing / ScreenSpaceShadows игровых камер (зеркала воды никогда не трассируют). При классическом освещении лучи не идут.
- RT-тени (`rtShadows` в `HplUserSettings`: выкл / низкое / среднее / высокое / ультра = до 4 / 8 / 12 / 16 источников, 1 / 1 / 2 / 4 луча на пиксель, по умолчанию «Среднее»): каждый кадр источники карты с тенями в поле зрения сортируются по расстоянию от камеры до их радиуса (уже трассируемые получают запас 1 м, чтобы не переключались каждый кадр), ближайшим ставится `useRayTracedShadows`, денойзер и `Light.shapeRadius` = 4 см (мягкость; у HPL2 размера источника нет), остальные остаются на картах теней; при выключении радиус возвращается. Настройка «Тени: выкл» на «Графике» выключает и RT-тени. Выбор источников сбрасывается в `Apply`, иначе смена настроек в том же кадре не действовала.
- Тени от всех источников (`rtAllShadows`, по умолчанию вкл, недоступно при выключенных RT-тенях) — в выбор RT-теней входят и источники без `CastShadows` (большинство свечей; на стартовом виде `00_rainy_hall` 11 → 53 источника в кадре). Пока такой источник трассируется, у него включены тени с картой минимального разрешения и обновлением по запросу (`ShadowUpdateMode.OnDemand`): HDRP рисует карту теней и для RT-источников, так она рисуется один раз; выпав из выбора, источник снова без теней. Свет в руке, box-свет и свет темноты игрока в общий выбор не входят. Настройка «Тени: выкл» на «Графике» выключает и их.
- Тени от фонаря (`rtLanternShadows`, по умолчанию вкл): источники предмета в руке (`AmnesiaLight.handHeld`, ставит `PlayerHands.CreateHandLight`; у фонаря их два) трассируются всегда, пока горят, вне общего числа: общий выбор получает min(уровень, 16 − источников в руке) слотов. Руки и модель фонаря теней не отбрасывают (`HandsConverter`), копия света для рук — без теней.
- RTAO (`rtAo`: выкл / низкое / среднее / высокое = уровни качества RTAO HDRP 0–2, по умолчанию «Среднее»): компонент `ScreenSpaceAmbientOcclusion` (rayTracing) в глобальном Volume настроек (`HplRayTracing.ApplyVolume` из `HplGraphics.ApplyVolume`), при классике он неактивен. HDRP применяет AO только к непрямому свету, которого в картах HPL2 нет, поэтому `directLightingStrength` = 0.35 (затенение и прямого света ламп), а box-свет умножается на AO кадра (`_HplBoxAo` из `HplBoxLightPass`, текстура `_AmbientOcclusionTexture`, которую HDRP оставляет глобальной после проходов освещения) — как SSAO у box-света HPL2.
- RT-отражения (`rtReflections`: выкл / низкое / среднее / высокое, по умолчанию «Среднее»): компонент `ScreenSpaceReflection` с трассировкой лучей (режим Performance, своё качество вместо уровней ассета: минимальная гладкость 0.55 / 0.45 / 0.35, начало затухания + 0.1, длина луча 10 / 25 / 50 м, «низкое» — половинное разрешение, денойзер). Гладкость материалов HPL2 после пересчёта спекулярной карты 0.3–0.6, а порог HDRP по умолчанию 0.9 не отражал бы ничего. Ассет поддерживает SSR (`supportSSR`) только ради этих отражений: frame setting SSR включается лишь у камер с RT-отражениями, классика и зеркала воды без SSR. В отражениях нет box-света, тумана и полупрозрачных (свои шейдеры); вода отражает по-прежнему своей камерой-зеркалом.
- RTGI (`rtGi`: выкл / низкое / среднее / высокое, по умолчанию «Среднее» — ремастер): компонент `GlobalIllumination` с трассировкой лучей (Performance, своё качество: длина луча 50 м, денойзер; «низкое» — половинное разрешение и половинный денойзер, «среднее» — половинное разрешение и второй проход денойзера, «высокое» — полное разрешение). Ассет поддерживает SSGI (`supportSSGI`) только ради него: frame setting SSGI — лишь у камер с RTGI. Свет в точках попадания лучей (отражения, GI) берётся из кластера источников: `LightCluster.cameraClusterRange` = 40 м (у HDRP 10), до 16 источников на ячейку (`maxLightsPerClusterCell`, предел HDRP 24). Отражённый свет дают только HDRP-источники и эмиссия; box-свет (custom pass) не отражается. На стартовых видах `00` / `01` прибавка средней яркости 2–3%.
- Path tracing (`rtPathTracing`: выкл / 64 / 256 / 1024 сэмпла, по умолчанию выкл; левая колонка вкладки RTX, только при RT-освещении): компонент `PathTracing` HDRP (глубина 4, предел яркости 10, денойзер OptiX пакета `com.unity.rendering.denoising` 1.0.5 по окончании накопления, асинхронно). HDRP копит по сэмплу за кадр игрового цикла и начинает заново при любом изменении: камера, трансформы объектов в структуре лучей (критеры, физика), CRC материалов. Поэтому кадр чистый только пока всё стоит; полоса внизу — индикатор накопления HDRP. В path tracing нет custom pass: box-света (пол верхнего яруса `01_old_archives` тёмный), тумана мира и областей. Чтобы стоящий игрок не сбрасывал накопление, камера (`AmnesiaPlayer.UpdateCameraTransform`: положение, поворот, FOV, aspect), руки (`PlayerHands.UpdateTransform`) и свет темноты (`PlayerDarkness`) пишутся только при изменении больше 0.1 мм / 0.001°, эмиссия пропов (`HplProp.SetIlluminationAmount`) — только при новом значении.
- Структура лучей без поддельных эффектов: рендереры шейдеров `RTXMnesia/*` (частицы, ореолы, Mul-декали, вода) и меш-декали (`DBufferMesh`) получают `rayTracingMode = Off` (`HplRayTracing.Exclude` при загрузке сцены; частицы и билборды — при создании, билборды всегда). Без этого path tracer рисовал их чёрными, а билборды, меняющие цвет каждый шаг, сбрасывали накопление.
- Генерация кадров: во встроенном HDRP нет ни DLSS-G, ни FSR 3 FG. Решение пользователя — NVIDIA Smooth Motion (драйвер, RTX 40/50): включается вручную в NVIDIA App для `UMnesiaRTX.exe` (API NVIDIA App его не переключает, сборки в списке приложений нет), на вкладке RTX — подсказка. Свой плагин Streamline DLSS-G — отдельная большая задача.
- Сравнение по C (`Effects/HplRtxCompare.cs`, не клавиша HPL2, не настраивается; только при DXR, не в паузе и не на титульном экране): кадр сохраняется (`HplScreenEffectsPass`, проход «Raw copy» до эффектов HPL), на следующем обновлении освещение переключается классика ↔ трассировка лучей (`HplGraphics.Apply` копии настроек, не сохраняется — окно настроек применяет выбранное снова), за 0.9 с наклонная линия (белая, с зелёным свечением) проходит слева направо: слева новый живой кадр, справа сохранённый (проход «Compare wipe»); надпись нового освещения — слева вверху HUD. Подсказка о клавише — на вкладке RTX.
- Цена в редакторе (RTX 5080, 1080p, `00_rainy_hall`): ~1.4 мс на трассируемый источник (12.9 мс без RT-теней, 22.5 — 8 источников, 38 — «Ультра»); RT-отражения +1.5–2.5 мс, RTGI +1.5–3 мс; «Ультра» с тенями от всех источников (16 трассируемых) — ~48 мс кадр. В шрифтах игры нет «—»: в текстах интерфейса — двоеточие или дефис.
- Что лучи не видят: box-свет, туман мира и областей рисуются custom pass поверх кадра; частицы, ореолы, Mul-декали и вода — свои шейдеры без RT-проходов (тени не отбрасывают; для отражений / GI — решать на их этапах). Ray Reconstruction в Unity нет — шум убирает денойзер HDRP.
- Проверка: `RTXMnesia.EditorDev.RtPreview.RunBatch` (без -quit/-nographics, GPU с DXR; `-amnesiaMap`, `-playView`, `-rtSize`) — классика и все уровни RT-теней: камера трассирует только при RT-освещении, число трассируемых источников (= min(уровень, с тенями в кадре)), экранные тени, радиус источника, отличие картинки (если в кадре есть источники с тенями), время кадра; все уровни RTAO (компонент Volume, качество, отличие картинки); box-свет рисуется с RTAO не слабее половины классического (кадр с проходом box-света против кадра без него; вид решает, сколько его видно); все уровни RT-отражений (компонент, трассировка, SSR камеры, отличие картинки); все уровни RTGI (компонент, кластер, SSGI камеры, прибавка яркости); классика без SSR и SSGI; тени от всех источников (добавленные источники трассируются с картой по запросу, отличие картинки, после выключения снова без теней); тени фонаря (фонарь горит — его источники трассируются, отличие картинки, убран — нет); path tracing (компонент, 64 сэмпла за реальные кадры, отличие от растрового RT, выключение); сравнение по C (снимок, переключение, надпись, ход и конец шторки, обратное переключение; снимок середины `<карта>_compare_wipe.png`); возврат настроек; снимки и отчёт — `Logs/RtCheck`. В `MenuPreview.RunBatch` — списки «Тени (трассировка)», «Затенение (RTAO)», «Тени от всех источников», «Тени от фонаря», «Отражения (трассировка)», «Глобальное освещение (RTGI)» и «Path tracing» на вкладке RTX (подсказка о клавише C — в левой колонке под DLSS) при RT-освещении, применение, возврат классики; `MenuPreview` сам сохраняет и возвращает PlayerPrefs настроек при любом исходе (в том числе по тайм-ауту, 420 с: первый RT-кадр компилирует шейдеры трассировки).

**Вода** — `ScriptApi/HplLiquidArea.cs` (`cLuxArea_Liquid`, область `Liquid` — у `HplArea.Liquid`) и `Dynamics/HplBuoyancy.cs` (`NewtonBodyAddBuoyancyForce`).
- Каждый полный шаг: тела мира (с массой, сталкивающиеся, активные), игрок и враги, чьи AABB Newton пересекают коробку области. Newton расширяет AABB выпуклых форм на `DG_MAX_COLLISION_PADDING` = 1/8 м, затем HPL2 проверяет точные габариты и форму — поэтому выходящее тело ещё 12.5 см в выборке и его флаг сбрасывается; только скачок дальше (телепорт) оставляет флаг (стартовая точка сбрасывает его у игрока, как `PlaceAtStartNode`).

Игрок вошёл: `IsInWater`, скорость × `PlayerSpeedMul`, шаги по `StepType` материала, всплеск по скорости сил тела. Враг вошёл: поверхность и материал для всплесков шагов.
- Плавучесть Newton (исходник из ScummVM `engines/hpl1/.../newton/physics/dgBody.cpp`): подъём −g·плотность·объём под плоскостью в центре этого объёма, затухание GetMax(GetMin(x, 1), 10) и GetMax(GetMin(x, 0.25), 2) — всегда 10·v и 2·ω, вязкости карты на него не влияют; тела ≤ 0.01 кг без силы; плотность × `BuoyancyDensityMul` тела (0 — тонет: части трупов). Объём — по треугольникам коллайдеров (коробка точно, сфера / капсула — низкополигональные, меш — по мешу), отсечение плоскостью, тетраэдры с вершиной на плоскости.

**Верёвки, связи, липкие зоны, слизь**
- Верёвка: область Rope → `HplRope` (`ScriptApi/HplRope.cs`, порт `cLuxRope` / `cLuxAreaRopeLoader`): свойства из переменных области или из файла `RopeFile` (`misc/*.rope`). После сборки карты (`AfterWorldLoad`, один раз) — физическая верёвка от области до PosNode `EndPosNode`, концы на телах `StartBody` / `EndBody` (имя тела, иначе главное тело пропа с таким именем). У сущности нет тел и взаимодействия, её активность ничего не меняет (как в HPL2); бокс области выключен.
- Физика — `Dynamics/HplPhysicsRope.cs` (`iPhysicsRope` + `iVerletParticleContainer`, в пространстве HPL2): первая частица неподвижна, остальные падают с гравитацией мира; шаг: проверка сна (раз в 1/3 с), мотор или авто-движение меняют полную длину (частицы добавляются / убираются у начала, первый сегмент — остаток деления), Verlet с демпфированием, концы следуют за телами, 3 итерации ограничений длины, PID-сила (p = Strength, d = Strength·0.1·Stiffness) тянет тело конца к его частице (сила × масса, момент × инерция). `HplPhysicsWorld`: верёвки до тел и после них. Звук мотора: `.snt` у первой частицы, FadeIn 5 / FadeOut 10 по скорости. Столкновений частиц нет (в оригинале отключены). Отличие: при нулевой длине сегмента HPL2 делит на ноль, здесь ограничение пропускается.
- Отрисовка — `World/HplRopeGraphics.cs` (`cRopeEntity`): квад на сегмент, повёрнутый к каждой камере (`beginCameraRendering`), UV повторяются LengthTileAmount раз на сегмент, первый (короче) обрезается. Отличия: нормаль смотрит на камеру (в оригинале — от камеры), смещения концов берутся из интерполированных поз тел кадра.
- Ресурсы: `RopeConverter` (меню Import > Rope resources, batch `RTXMnesia.Importer.RopeConverter.ConvertBatch` — все карты; импорт уровня добавляет свою) → игнорируемый `Resources/HplRopes.asset` (`HplRopeAssets`): файлы `.rope` и материалы (`textures/ropes/*.mat`, обычный `MaterialConverter`) по тексту ссылки области. Переимпорт карт не нужен.
- Interact connections — `ScriptApi/HplInteractConnections.cs` (`cLuxInteractConnection_Rope` / `_MoveObject`), список у `HplProp`: колесо при повороте (`InteractConnectionTurn`, доля диапазона) и рычаг / колесо на пределе (`InteractConnectionLimit`) ведут мотор верёвки к нужной длине или MoveObject к состоянию; только при взаимодействии (по умолчанию) — и тогда отпущенное колесо следует за верёвкой / MoveObject. Обновляются в шаге пропа перед `UpdatePropSpecific`.
- Липкая зона — `ScriptApi/HplStickyArea.cs` (`cLuxArea_Sticky`, у `HplArea.Sticky`): тело с массой, активное, сталкивающееся, чей центр масс (CheckCenterInArea) или AABB внутри зоны, чьё имя содержит AttachableBodyName и форма касается зоны, после AttachFunction (может разрешить `SetAllowStickyAreaAttachment`) становится статичным без гравитации и за PoseTime встаёт в позу зоны (цель — позиция зоны минус локальный центр масс, без поворота, как в оригинале), затем звук и частицы. Состояние захвата игрока отпускает тело. Отцепляется взаимодействием (`CanDetach` и поза завершена: `PropObject` / `PropSwingDoor` проверяют `HplMap.BodyIsInDetachableStickyArea` и зовут `DetachBodyFromStickyArea`) или скриптом. Последнее тело не берётся снова, пока не выйдет: сбрасывается, когда широкая фаза Newton (AABB + 1/8 м) ещё возвращает его, а точная проверка — нет. Зона и прикреплённая сущность сохраняются целиком. Не перенесено: тела персонажей (в HPL2 тоже проверяются; у игрока здесь нет физического тела).
- Урон слизи — `HplArea` с типом SlimeDamage (`cLuxArea_SlimeDamage`): раз в Min..MaxCheckAttackTime, если зона касается текущей формы игрока, — урон Min..MaxAttackDamage (брызги крови, поворот головы), звук и частицы `game.cfg` `Slime`, тряска экрана (amount, 0.5, 0.1, 0.3), коллбэк (зона), выключение при DisableAfterAttack. - Вода — `Assets/Shaders/HplWater.shader` (`water_surface_frag.glsl`), материалы Water (18) — `MaterialConverter.CreateWater`: две волны нормалей, диффуз по первой, преломление из color pyramid HDRP со смещением по нормали / глубине, отражение: кубкарта (роль текстуры `CubeMap`, полоса 6×1 → Cubemap Unity, выборка направлением HPL2), мировое (`World/HplWaterReflection.cs`: зеркальная камера HDRP с косой ближней плоскостью на воде для ближайшей видимой односторонней поверхности в пределах ReflectionFadeEnd, ½ экрана, вода в отражении не рисуется, экранные эффекты в ней пропускаются) или его нет (поддельное освещение оригинала); Fresnel, затухание отражения по глубине, туман HPL2 (`_HplFogColor`). Цвет — в гамме, как HPL2. Неодносторонние (банки с жидкостью) — без отражения (HPL2 очищает текстуру).

- Гамма — `HplUserSettings.gamma` / `Gamma`: последний проход `HplScreenEffectsPass` (sRGB^(1/гамма), как гамма-рамп SDL); HUD и меню (overlay) не затрагиваются.
- Экранные значения и гамма 2.2: HPL2 перемножает альбедо, свет, туман и эффекты как сырые значения экрана и пишет их прямо в гамма-2.2 монитор (значение = линейное^(1/2.2)). Кусочная sRGB-кривая (кодировка свопчейна SDR, `Color.linear`, HDR-декодирование) в тёмном сильно отличается (линейное 0.0002: значение 0.021 против 0.0026; цвет 0.1: 0.0063 против 0.0100), а тёмные комнаты живут именно там. Поэтому пространство эффектов в `HplScreenEffects.shader` — чистая степень 2.2 (`HPL_DISPLAY_GAMMA`, `ToEffectSpace` / `FromEffectSpace`), цвет тумана — `HplLighting.Radiance` через `pow 2.2`. SDR: последний проход (Gamma, теперь всегда, и при гамме 1.0) отдаёт свопчейну `SRGBToLinear(значение^(1/гамма))`, чтобы его кусочная кодировка показала ровно значение. HDR: яркость = линейный буфер × paper white (тождество); проход «HDR display» (`HplHdr.DisplayGamma` = настройка «Глубина теней» вкладки HDR, `hdrShadows` 2.0–3.2, по умолчанию 2.4 — BT.1886 для тёмных комнат; яркость = paper white × значение^гамма; 2.2 — пропуск прохода; выше — глубже тени: у LCD-панелей без локального затемнения чёрный в HDR 0.3–0.5 нит и тёмные тона видны голубовато-серой пеленой). Освещение и смешение тумана по-прежнему в линейном буфере, albedo-текстуры декодируются аппаратно (кусочно: тёмные тексели чуть светлее), эмиссия материалов не пересчитана (см. `Radiance` — только туман и области тумана). Проверка: `HdrTests.RunRenderBatch` (GPU, `-batchmode` без -nographics; Unity с проектом закрыт; источник — Texture2DArray, как `TEXTURE2D_X`).
- Клавиши — `Ui/HplKeyBindings.cs`: 18 настраиваемых действий `cLuxInputHandler` (без «Lean» и геймпада), умолчания из `default_user_keys.cfg`, выбор пользователя — в профиле (`user_keys.json`), без профиля — PlayerPrefs; игрок, журнал / инвентарь, `ParseString` ($ButX) читают их; `CrosshairToggle` (X) переключает прицел. Экран — `Ui/HplKeyConfig.cs` + `HplPauseMenu.KeyConfig` (`cLuxMainMenu_KeyConfig`): категории, основная / дополнительная клавиша, ожидание ввода (Esc отменяет), повторы и пустые — красным только внутри категории (первое действие категории не проверяется на пустоту, как в оригинале), «по умолчанию» и OK с предупреждением.
- Комментарии разработчиков — `Props/PropCommentaryIcon.cs` (`cLuxCommentaryIcon`) + `HplEffects.PlayCommentary` (`cLuxEffect_PlayCommentary`): значки активны при настройке «Комментарии» (`HplUserSettings.ShowCommentary`, карта переключает их в шаге), текст фокуса «Автор\n"Тема"», взаимодействие запускает / останавливает GUI-поток (мир и музыка 0.15, голоса 0.1, глобальная громкость id 5), шестерня крутится, частицы `ps_commentary_icon.ps`. Данные `.comment` — `CommentaryConverter` → игнорируемый `Resources/HplCommentary.asset`; звуки `commentary/` — в банке звуков (потоковые).

**Прогон** — `PlayerSimulation`: на уровне с `HplMap` шаги идут через карту, сообщения `[Script…]` копируются в лог.
- Флаги:
  - `-scriptDebug` — области вступления активны сразу, вступление пропускается;
  - `-noScript`;
  - `-globals "имя=значение;…"` — глобальные переменные до старта карты (возвращение на хаб, например `key_study_1=key_study_1` — событие стража на `02_entrance_hall`);
  - `-seed N` — повторяемые `RandFloat`.
- Команды:
  - `watch t интервал` — шаги со строкой состояния скрипта: игрок, FOV/aspect/крен, затемнение/след/сепия, реплика, сообщения, таймеры;
  - `fx sepia|trail|fade|blur|flash|off значение`;
  - `goto x y z yaw`;
  - `start Зона`;
  - `interact`, `release`, `throw`, `scroll n`, `rotate on|off`, `mouse x y t [log]` (единицы мыши HPL за шаг, y вниз), `mouseuntil x y Переменная значение [t]` — так же, пока локальная переменная карты не примет значение (не дольше t с, по умолчанию 10; иначе предупреждение);
  - `aim Сущность [Тело]` — повернуть камеру на тело; `body Сущность` — состояние пропа/двери/лампы, тела, джоинты;
  - `call Функция аргументы` — вызвать функцию скрипта уровня.
  - `particles` — системы частиц: число частиц по эмиттерам, состояние, расстояние.
  - `sanity [значение]` — задать рассудок и вывести освещённость, темноту, удар / утечку / покачивание / обморок, эффект безумия и три главных источника света у игрока; `lightsoff` — скрыть весь свет сцены (проверка темноты, лучше с `-noScript`); `active Сущность true|false` — включить сущность (карты без порта скрипта); `fitsup dy` — помещается ли тело выше и что ему мешает; `health` — здоровье, ранение, брызги / вспышка, состояние смерти и чекпоинт (урон — `call GivePlayerDamage 60 claws true false`); `enemy [Имя]` — враги: состояние, чувства, путь, анимация, страх и музыка врагов (строка `watch` тоже показывает активных врагов); `insanity [Имя|random|stop]` — запустить / остановить событие безумия и вывести состояние обработчика; `ropes` — верёвки (длина, частицы, мотор, концы) и что держат липкие зоны.
  - `sounds` — играющие записи (имя, тип, расстояние, время), звуковые сущности, музыка, глобальные громкость и скорость.
  - `overlaps Сущность` — пересечения коллайдеров её тел между собой и с миром (глубина, направление, слой).
  - `hide lights|passes|volumes|<часть имени шейдера>` — выключить весь свет, custom pass, Volume или рендереры с таким шейдером (бисекция проблем рендера).
  - `walkto Имя [падение_м]` — пешком (поиск по сетке + настоящий контроллер игрока, двери открываются перед проходом, лёгкие ящики сдвигаются) к сущности или области; `pull Рычаг` — дойти до рычага и потянуть мышью, пока не сменится состояние; флаг `-noEnemyAI` отключает ИИ врагов. Автоматический обход карты: `RTXMnesia.EditorDev.JustineWalkthrough.RunBatch -amnesiaMap maps/ptest/01_cells.map [-walk doors|all|none] [-walkfrom Старт -walkdrop 25] [-open "moveobject,…"]` → `Logs/Justine_Walk_<карта>.txt` (журнал: `docs/ScriptPort/justine/walkthrough.md`).

## Проверка импорта геометрии

- `HplMeshAudit.Run` (меню Tools > RTXMnesia > Import > Audit level meshes against MSH) сравнивает меши уровня с бинарными `.msh` v7 из `source/`, проверяет исходные пути моделей, матрицы всех статических объектов и подмешей сущностей, положения тел и соответствие mesh-коллизии визуальному мешу. Отчёт: `Logs/HplMeshAudit.txt`. Это независимая проверка; `.msh` не являются источником импорта.
- Порядок треугольников: сборщик отражает X и меняет COLLADA-тройку `(a,b,c)` на `(a,c,b)`. HPL2 `CreateVertexBuffer` сохраняет `(c,b,a)`: это тот же обход с циклически сдвинутой первой вершиной. При сверке `.msh` сравнивать ориентированные тройки с учётом циклического сдвига, а не индексы побайтно.
- Проверять не только успешный batch-импорт, но и контрольные рендеры, соответствие пути модели записи карты и проход игрока. Геометрически правильный меш может оказаться неверно выбранным одноимённым ресурсом.
- Проверка `00_rainy_hall` 2026-10-14: исправлены 123 подмены статических моделей. 124 модели / 274 подмеша совпадают с MSH по вершинам и ориентированным треугольникам; 925 экземпляров / 1413 матриц подмешей проверены; 471 проверка выбора одноимённых ресурсов прошла. Две разницы матриц исходных префабов относительно MSH (`candlestick_wall`, `armour_rusty_complete/podium`) остаются явно отмеченными в отчёте: в этой сцене их заменяют трансформы `.ent`, и итоговая расстановка совпадает. Прогон игрока по лестнице PlayerStartArea_x2 вниз и вверх успешен.
