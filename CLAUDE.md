## Состояние Unity-проекта

HDRP-база (`Assets/Editor/ConfigureHDRP.cs`, меню Tools > RTXMnesia > Configure HDRP, `Assets/Settings/*`, `SampleScene`), импортёры ресурсов и уровней (`Assets/Editor/Importer`), компоненты уровня, игрок и рантайм скриптов уровней (`Assets/Scripts`). Первый уровень: `Assets/AmnesiaImported/Levels/maps/main/ch01/00_rainy_hall.unity` (генерируется, не в git). В нём Play запускает скрипт уровня — вступление, пробуждение, события по зонам; пропы — физические тела с шарнирами, их можно брать, толкать, открывать (двери, ящики, рычаги, колёса), зажигать лампы, подбирать предметы; звук и музыка, частицы, ореолы ламп, контур и мерцание предметов, шрифты HUD как в оригинале. Вторая карта — `01_old_archives`, третья — хаб `02_entrance_hall`; дверь уровня и `ChangeMap` переводят на другую карту с экраном загрузки, при возвращении состояние карты восстанавливается, фонарь в руке работает.
Fixed Timestep = 1/60 (как шаг логики HPL2, `EngineInitVars mlUpdateRate`).
Hardware RT не включён. Подробности: `UnityProj/UMnesiaRTX/HDRP-SETUP.md`.
Стартовая сцена сборки — импортированное главное меню `Assets/AmnesiaImported/Levels/main_menu/main/menu_bg.unity`; новая игра загружает `00_rainy_hall`. Play открытой игровой карты в редакторе по-прежнему запускает её напрямую. Возврат в главное меню доступен из Esc с подтверждением. Импортированные игровые карты сами попадают в список сцен сборки (по имени их находит смена карты).
Headless-запуск Unity: `C:/Program Files/Unity/Hub/Editor/6000.6.2f1/Editor/Unity.exe -batchmode -nographics -quit -projectPath ... -executeMethod ...`.

Расширения: `.dds` 1901, `.dae` 1467 (COLLADA 1.4.1, Maya), `.msh` 1462 (бинарный кэш меша HPL, дублирует .dae — берём `.dae`), `.snt` 979, `.ent` 909, `.mat` 860, `.tga` 467, `.ogg` 2889.

Форматы:
- **`.mat`** — XML: `<Main Type="SolidDiffuse" PhysicsMaterial="Rock">` + `<TextureUnits>` (`Diffuse`, `NMap`, `Specular`, `Height` → имена `.dds`). Spec-карта у Amnesia → нужно конвертить в Metallic/Smoothness/Mask для HDRP.
- **`.ent`** — XML: `<ModelData>` с `Mesh Filename=...dae`, SubMesh→материал, `<Shapes>` (коллизии: Box/Cylinder/…), далее `UserDefinedVariables` (тип сущности, масса, звуки).
- **`.map`** — XML: `<StaticObject>` (769 в одной карте), `<Entity>`, `<PointLight>`/`<SpotLight>`, `<Area>`, `<Billboard>`, `<ParticleSystem>`, `<Decal>`, `<Plane>`, `<Compound>`, `<Var>`; позиции/повороты/масштаб в атрибутах. Приложен встроенный геометрический кэш для декалей/комбинированных объектов.
- **`.hps`** — AngelScript, логика уровня (триггеры, таймеры, `SetPlayerActive`, `PlayMusic`, `AddTimer`, коллбэки областей). Нужен интерпретатор-замена на C# (или ручной порт).
- **Единицы/оси**: метры; осей Y-up (проверить при импорте — COLLADA up_axis и знак Z).

## Ключевые факты для плана

- Оригинальный рендер: OpenGL deferred, динамическое освещение, Newton physics, AngelScript, OpenAL.
- Основное освещение игры — динамические point/spot-света + SSAO + ambient; запечённого GI нет. Это хорошо ложится на HDRP (+ RTGI/RT shadows/RT reflections позже).
- Карты состоят из огромного числа статик-объектов, ссылающихся на `.dae`/`.mat` → импорт должен кэшировать и переиспользовать меши/материалы.

## Импортёры (Assets/Editor/Importer, namespace RTXMnesia.Importer)

Меню: **Tools > RTXMnesia > Import**. Лог: `UnityProj/UMnesiaRTX/Logs/AmnesiaImport.log`.
Batch-методы `RTXMnesia.Importer.ImportMenu.*` (Unity с этим проектом должен быть закрыт; проверять lock `Temp/UnityLockfile`):
`ConvertMaterialsBatch`, `ConvertModelsBatch` с `[-amnesiaFolder <папка в source>] [-forceTextures] [-describe a.dae,b.dae]`;
`RenderMaterialsBatch`/`RenderModelsBatch` — сцена-витрина + рендер в `Logs/<Kind>Preview.png` (без `-nographics`, нужен GPU).
Быстрая проверка компиляции без Unity: Roslyn `Editor/Data/DotNetSdk/.../csc.dll` + ссылки на `Managed/UnityEngine/*Module.dll` и HDRP dll из `Library/ScriptAssemblies` (фасады UnityEngine.dll/UnityEditor.dll не подключать).
Проверка скриптов сборки игрока: `-batchmode -nographics -quit -executeMethod RTXMnesia.EditorDev.BuildCheck.RunBatch` — компилирует скрипты для Windows, как сборка (без сцен), и выводит ошибки и предупреждения об устаревшем API (CS0618 / CS0612 / CS0619) наших сборок; устаревшие вызовы вызывают при сборке диалог Script Updating Consent. Свойства HDRP, объявленные устаревшими, заменять API `Light` (например, `HDAdditionalLightData.shapeRadius` → `Light.shapeRadius`).
Полный импорт `static_objects` + `entities`: ~3 мин, ~1 GB в `Assets/AmnesiaImported`.

- `ResourceIndex` — поиск как `FileSearcher::GetFilePath` HPL2: индекс по имени, при дубликатах сравнение компонентов папок с конца в обоих направлениях. Путь из `.map/.ent/.dae` нельзя отбрасывать: `castlebase/wall/default.dae` и `castlebase/stairs/default.dae` — разные модели. Старые префиксы дисков экспортёра не мешают сравнению папок; для голого имени используется папка ссылающегося файла, затем порядок `resources.cfg`.
- `DdsDecoder` — DXT1/3/5, ATI2(BC5), несжатые 24/32 бит, кубкарты. Форматы в игре: DXT1 1131, DXT5 714, BGRA32 36, ATI2 12, кубкарт 4.
- `TextureConverter` — DDS → PNG в `Assets/AmnesiaImported/Textures/<путь>__<роль>.png`; роли: albedo, normal, mask, specular, height, emissive. Настройки импорта — `TextureImportRules` по роли из имени.
- `MaterialConverter` — `.mat` → HDRP материал в `Assets/AmnesiaImported/Materials/<путь>.mat`; существующие обновляются на месте (GUID сохраняется). Константы тюнинга вверху файла.
- `ImageLoader` — .dds/.tga/.jpg/.png → пиксели «верхняя строка первой» (HPL2 грузит всё через DevIL с IL_ORIGIN_UPPER_LEFT). Текстура без расширения → перебор форматов, как `TextureManager::FindTexture2D`.
- `TextureConverter.Version` — при изменении математики конвертации увеличить: PNG старше момента смены версии перегенерируются.
- `ModelConverter` + `HplCollada` + `HplModelBuilder` — модели без скелета читаются собственным парсером Collada (1.4 и старый 1.3), сохраняются в `Models/<путь>.prefab` и `<путь>_meshes.asset`. Собственный масштаб узла запекается в вершины и снимается с узла; единицы файла применяются только для FBX COLLADA exporter. Встроенный импорт Unity (`ModelImportRules`) остаётся для скелетных моделей. При изменении сборки или выбора ресурсов повышать `HplModelBuilder.Version`, чтобы пересобрать старые префабы.
- Коллизия статики: примитивный коллайдер отменяет mesh-коллизию только своего подмеша; наличие обычного `_collider`-меша отменяет визуальные mesh-коллайдеры всей модели. `Collides=false` отключает коллизии экземпляра. Коллайдеры `_charcollider` — на слое 30 (`HplPhysicsWorld.NoCollideLayer`): как `SetCollide(false)` в HPL2, их видит только проверка персонажа, тела проходят сквозь них, луч фокуса их пропускает (на `01_old_archives` рычаг стоял внутри такого коллайдера и бился о пределы). Изменение сборки → `HplModelBuilder.Version` = 5, `ModelImportRules.GetVersion` = 3.

Проверенные по исходникам HPL2 конвенции:
- UV COLLADA: движок делает `v = 1 - v`, DDS грузится верхней строкой в v=0 → в Unity UV не трогаем, PNG сохраняем как DDS (верх = верх).
- Нормали: бинормаль движка смотрит «вниз по картинке» → зелёный канал инвертируем.
- Specular-карта: R = интенсивность, G = степень `exp2(G*10)+1`. В HDRP: Specular Color workflow, F0 = R × 0.08, smoothness = 1 − sqrt(sqrt(2/(n+2))).
- Height — в альфа-канале. Юнит `Alpha` = alpha test по альфе диффуза. `Illumination` = emissive (у ламп регулируется в игре).
- Имя материала у меша = имя текстуры из `<library_images>` `.dae` с расширением `.mat`.
- Height-карта Amnesia — это **глубина** (белое = глубже, relief mapping) → инвертируется для HDRP. Проверено численно: градиент инвертированной карты совпадает с normal map по знаку в обоих каналах (заодно подтверждает инверсию G).
- **Оси**: Unity-импорт Collada отражает X: HPL `(x,y,z)` → Unity `(-x,y,z)` (проверено на `corner_concave_round.dae`). Позиции из `.map`/`.ent` переводятся так же, повороты (Euler XYZ, радианы, M = Rz·Ry·Rx) — отражением: угол X сохраняется, Y и Z меняют знак; порядок вершин треугольников не меняется. Всё это — `Assets/Scripts/Hpl/HplSpace.cs`; проверено на уровне (стены стыкуются, двери/люстры на местах). Свет и камеры HPL смотрят в локальный −Z (Unity +Z) → `HplSpace.LookRotation`. UV из .map (плоскости, декали, билборды): v = 1 − v.
- **Z_UP Collada**: собственный парсер повторяет HPL2: вершины/нормали `(x,y,z) → (-x,z,y)`, translate/scale `(x,z,y)`, rotate и matrix без перестановки. Затем применяется общее отражение X HPL→Unity. Старые поправки к встроенному импорту для нескелетных моделей больше не используются.
- Блендинг Mul/MulX2 (в HDRP нет; декали грязи и сырости `static_objects/decals`, лужи, бутылки, стёкла — ~30 материалов, на `00_rainy_hall` ~290 экземпляров `dirt_floor01`) — свой шейдер `Assets/Shaders/HplMultiply.shader`: множитель на освещённый цвет (HPL2 умножает альбедо в G-buffer — разница только в бликах), считается в гамме как в HPL2 (t·цвет экземпляра, ×2 для MulX2, клэмп для Mul), декали — до остальной прозрачности (очередь 2900) и с alpha test 0.01; туман HPL2 накладывается после декалей → множитель ослабляется непрозрачностью тумана (глобал `_HplFog` из `HplLighting.SetMultiplyFog`). Цвет декали карты для него не клэмпится (1.5 у `dirt_floor01_272`). Декаль Add → HDRP/Unlit additive, Alpha → HDRP/Decal. Без своего шейдера эти материалы выглядели белыми прямоугольниками.
- TODO: вода, DissolveAlpha, кубкарты отражений (заменяются HDRP/RT). ~10 моделей с материалом без .mat (кости, паук) — вероятно, материал задаётся в `.ent` (`SubMesh Material=`).
- `.ent` (сущности): `ModelData` = Mesh + SubMesh (материал-override), Shapes, Bodies (масса, физ. материал, какие подмеши привязаны), Joints (двери — JointHinge), Bones, Animations; `UserDefinedVariables EntityType="SwingDoor|..."` + звуки/поведение. Префабы из .ent делать на шаге 4 вместе с механиками.
  Важно: SubMesh в `.ent` хранит трансформ подмеша относительно сущности, он **заменяет** трансформ узла Collada (масштаб узла остаётся). Пример: дверь `castle` развёрнута там на 180°. Внутри `.ent` есть свои свет/билборды/частицы/звуки (`ModelData/Entities`), их позиции × масштаб экземпляра.

## Игрок (шаг 4, Assets/Scripts/Player, namespace RTXMnesia.Player)

Порт по исходникам, числа — только из `game.cfg` через `HplConfig` (`GetFloat("Player_Body","Mass")` как `cConfigFile`), в коде их нет.
- `HplCharacterBody` — порт `iCharacterBody` (CharacterBody.cpp): не Rigidbody, а вертикальный цилиндр, который двигается скоростями по направлениям (ускорение/торможение/разворот), гравитацией и силами, и выталкивается из мира после каждого шага; ступени — лучами (AccurateClimbing: 3 луча), камера на высоте стоячего тела + `CameraPosAdd`, сглаживание по `CameraSmoothPosNum` шагам. Формы — выпуклые MeshCollider-цилиндры на слое 2 (Ignore Raycast: их не видят запросы по умолчанию); неактивный размер (присед/стоя) — trigger. Не портировано: прилипание к движущимся телам (GravityAttachment), соединение с телом (Push).
- `HplPhysics.CheckShapeWorldCollision` — аналог `iPhysicsWorld::CheckShapeWorldCollision` (другие персонажи — игрок и враги — тоже препятствия, свои формы пропускаются): OverlapBox + `Physics.ComputePenetration`, вектор выталкивания = покомпонентный максимум по контактам; с одним коллайдером до 4 итераций (PhysX даёт одно разделение на пару, Newton — список контактов). Тела с `CollideCharacter=false` и триггеры игнорируются. Поправка: если коллайдер выталкивает вбок, а на 3 см выше форма от него свободна, — вместо толчка подъём на нужную высоту (бинарный поиск, `LiftOverLowEdge`). Иначе ковры 1–2 см и пороги останавливают игрока: PhysX-меш толкает и по нормали низкой боковой грани, а подъём на ступени HPL2 видит только высоту > 2.5 см; Newton поднимал на такие края.
- `PlayerMoveNormal` — `cLuxMoveState_Normal`: ходьба/бег/присед/прыжок (сила прыжка + ослабление гравитации 0.22 с), покачивание головы и шаги на минимуме, отскок головы при приземлении, урон от падения. `PlayerLean` — `cLuxPlayerLean` (до 0.5 м и 15°, голова-цилиндр останавливается о стены).
- `AmnesiaPlayer` — `cLuxPlayer` + `cLuxInputHandler`:
  - логика 60 Гц разделена на `StepLogic` и `StepPhysics`. На уровне со скриптом их вызывает `HplMap` в порядке движка (`steppedByMap`), иначе FixedUpdate;
  - камера интерполируется между шагами;
  - мышь — каждый кадр: пиксели × чувствительность / (1.7 × высота экрана) × 2 рад, сглаживание как `GetSmoothMousePos` (веса 0.7^возраст в шагах 60 Гц — не зависит от FPS), питч ±70°;

## Физика сущностей (шаг 4.2, Assets/Scripts/Dynamics, namespace RTXMnesia.Dynamics)

Порт Newton-обёртки HPL2 (`iPhysicsBody`, `iPhysicsJoint*`, `iPhysicsWorld`) поверх PhysX.
- Пространство: позиции/направления HPL → Unity `(−x, y, z)`; осевые векторы (ω, момент) → `(x, −y, −z)`; кватернион `(x, −y, −z, w)`; матрица `S·M·S`, S = diag(−1,1,1,1) — `HplSpace`. `HplMatrix` — `cMatrixf`/`cMath` (MatrixRotate XYZ = Rz·Ry·Rx, GetRight/Up/Forward — строки, `GetAngleDistance`, `HplPid` = `cPidController`). Логику с углами писать в пространстве HPL через `Hpl*`-аксессоры тела, а не переводить формулы.
- `HplPhysicsBody` (Rigidbody): масса 0 = кинематическое, interpolation только в Play, итерации решателя 12/4. `AddImpulse` = `ForceMode.VelocityChange` (`NewtonBodyAddImpulse` принимает Δv), в точке — масса × Δv. Damping Unity = clamp(d, 0.001, 1) × 0.02 × 60. Ограничение скорости повторяет ошибку HPL2 (длина сравнивается с max²). Статическое движение (`StaticLinearMove`/`StaticAngularMove`) — кинематический MovePosition/MoveRotation, поворот `RotateXYZ(ω·dt)·R` в пространстве HPL.
- Слои: `CollideNonCharacter=false` → слой 30 (`NoCollideLayer`, не сталкивается ни с чем); `CollideCharacter=false` → `Physics.IgnoreCollision` с формами персонажа (`SetCharacterShapes`).
- Комбинирование трения/упругости: порядок приоритетов Average < Min < Multiply < Max совпадает с Unity.
- `HplJoint`: Hinge → `HingeJoint`, остальные → `ConfigurableJoint`. Угол шарнира HPL = −(правый поворот ребёнка вокруг пина HPL) = AngleAxis в Unity вокруг отражённого пина = `HingeJoint.angle` (проверено `PhysicsTests`), лимиты PhysX = [min°, max°]. Диапазоны за ±π или min > max — мягкий лимит коррекцией скорости. Slider — connected anchor в центре диапазона, симметричный `linearLimit`. Ball — twist ±MaxTwist, swing по конусу, 0 = свободно. Перед шагом: обновление лимитов (допуск 0.002 рад / 0.0005 м), LimitAutoSleep, Sticky, события MinLimitReached/MaxLimitReached; после — разрыв по `currentForce` ≥ BreakForce.
- `HplPhysicsWorld`: `AddEntity` создаёт тела, затем джоинты; поиск тела по Rigidbody/коллайдеру/данным; `Step` для edit/batch.
- `HplBodyContacts` ([ExecuteAlways]) — `OnCollisionEnter` для пропов, реагирующих на удар; скорость до удара — `PreviousVelocityAt`.
- ContinuousCollision из `.ent`: динамическим телам — `ContinuousDynamic` (протяжка), кинематическим — `ContinuousSpeculative`. Спекулятивный режим пропускал тонкий пол под быстро вращающимися осколками и накачивал скорость удерживаемому предмету, вдавленному в пол.
- Прогон шага: в Play FixedUpdate делает часть до симуляции, корутина `WaitForFixedUpdate` — после. В edit/batch `Physics.simulationMode = Script` и `HplMap.Step` вызывает `Physics.Simulate`.
- Проверка: `-executeMethod RTXMnesia.EditorDev.PhysicsTests.RunBatch` — синтетические шарнир (знак угла, лимиты, закрытие [0°, 2°], мягкий лимит 120°) и слайдер [0, 0.5].

## Пропы и взаимодействие (шаг 4.3, Assets/Scripts/Props, namespace RTXMnesia.Props)

- Звуки пропов как в оригинале: двери (закрыть/открыть, запереть/отпереть, «заперто», повреждение/поломка), лампа (огниво), подбор предмета (`ui/pick_<PickSound>`), дверь уровня (заперто), рычаг/колесо (пределы, «застрял»), разбивание, эффекты (`EffectsOn/OffSound`, свои звуковые сущности `.ent` гаснут/загораются с эффектами и активностью), статическое движение (`StaticMoveStart/Stop/LoopSound`). `HplEntity.PlaySound` = `iLuxEntity::PlaySound`, `PlaySoundAt` = звук в точке.

## Звук (часть шага 6, Assets/Scripts/Sound, namespace RTXMnesia.Sound)

- Импорт: `SoundConverter` (меню **Tools > RTXMnesia > Import > Sounds**, batch `ImportMenu.ConvertSoundsBatch`, сам вызывается импортом уровня) копирует все `.ogg`/`.wav` из `sounds/`, `music/` и голоса папки языка (`lang/rus`) как есть в `Assets/AmnesiaImported/Sounds/<путь>` (~2150 файлов, ~320 МБ; повторно копируются только изменённые) и собирает `Sounds/sounds.asset` (`HplSoundBank`): клипы по имени и все 979 `.snt` (`cSoundEntityData`, булевы как `cString::ToBool`: не "true" = false; битые байты читаются как Latin-1, как TinyXML). - `HplSoundEntity` — порт `cSoundEntity`: старт при первом обновлении, Loop/Interval/Random, Start/Stop-звуки, выход за MaxDistance останавливает петлю и возвращает её внутри, `RemoveWhenOver`, следует за `Parent`. - `HplMusicHandler` — `cMusicHandler` (главная песня, затухающие, позиции продолжения) + `cLuxMusicHandler` (приоритеты 0–10, после остановки/конца играет следующая зацикленная; громкость × `Sound/InGameMusicVolume`). - Звуки физики (`Dynamics/HplSurfaceSounds`): удары (`Impact` материала по скорости сближения до шага, не более 6 за 0.4 с), скольжение (`Scrape`, высота по скорости, MinScrapeContacts, остановка через 8 шагов без скольжения), перекатывание (`Roll` по осям RollAxis), правило приоритетов материалов как в `ContactsProcessCallback`; контакты из `HplBodyContacts` (Enter/Stay) всех тел, пара тел — один раз; контакты PhysX с зазором > 2 мм (contact offset) не считаются касанием. ## Частицы (Assets/Scripts/Particles, namespace RTXMnesia.Particles)

- Импорт: `ParticleConverter` (меню **Tools > RTXMnesia > Import > Particles (.ps)**, batch `ImportMenu.ConvertParticlesBatch`, сам вызывается импортом уровня) — все `.ps` из `particles/` (226 систем, 390 эмиттеров) → `Particles/particles.asset` (`HplParticleBank`, поиск по имени как `FileSearcher`). Разбор как `cParticleEmitterData_UserData::LoadFromElement` с правилами `cString` (вектор с неверным числом значений → значение по умолчанию; булевы — только "true"). Материалы эмиттеров (кадры `MaterialNum` > 1: `имя01`, `имя02`…) → `Particles/Materials/<путь>.mat` на шейдере `Assets/Shaders/HplParticle.shader`: текстура × цвет вершины в гамме, режимы Add / Mul / MulX2 / Alpha / PremulAlpha (как `deferred_transparent_frag.glsl`), `DepthTest`, затухание полупрозрачного в тумане HPL2 (глобал `_HplTranslucentFog` от `HplLighting.SetTranslucentFog`). Refraction не портирована.
- Рантайм — порт `cParticleSystem` / `iParticleEmitter` / `cParticleEmitter_UserData`: `HplParticleWorld` (список мира, `cWorld::UpdateParticles`, удаление мёртвых), `HplParticleSystem` (цвет, затухание по расстоянию, `Kill`, прогрев `WarmUpTime`, следует за узлом-родителем или стоит по матрице), `HplParticleEmitter` (частицы в пространстве HPL — мира или системы для `CoordSystem="Local"`, шаг 60 Гц, сон эмиттера, который не видно, столкновения лучом). Сохранены ошибки оригинала (удалённая частица ещё обновляется в своём шаге, а переставленная на её место пропускает шаг; `SubDiv "1 n"` без разбиения; луч локального эмиттера бросается в локальных координатах как в мировых). Beam HPL2 тоже не рисует.
- Рисование: меш эмиттера на шаг (скрытый несохраняемый объект под `HplParticles (runtime)`), квады разворачиваются к камере в вершинном шейдере (Point — смещение во view-пространстве со спином, Line — вдоль направления движения во view-пространстве, Axis — готовые мировые вершины), так что один меш годится для всех камер; цвет системы и затухание по расстоянию (`FadeAtDistance`) — тоже в шейдере, полностью погасшая система не рисуется.
- Источники: системы карты и `.ent` (`HplMap` создаёт их при сборке и в `CreateEntity`, следуют за узлом; неактивная сущность — система не обновляется и не видна), скрипты (`CreateParticleSystemAtEntity(Ext)` — на теле крепления, `DestroyParticleSystem` = `Kill`), эффекты пропов (`SetEffectsActive`: включение создаёт системы заново по сохранённым данным — цвет экземпляра теряется, как в HPL2; выключение — `Kill` с затуханием или удаление), разбивание (`PropObject` BreakPS, двери Break/DamagePS), удары материалов (`CreateImpactEffect` в `HplSurfaceSounds`), мерцание света (FlickerOn/OffPS). Уничтоженный проп гасит свои системы (`KillParticleSystems`), системы на нём остаются на месте.
- Проверено (`particles` в `PlayerSimulation`): на `00_rainy_hall` 92 системы — туман, пыль, свечи, струя и брызги воды, капли; снимки.

## Скрипты уровней (шаг 5, Assets/Scripts/ScriptApi, Effects, Ui, Levels)

**Порт уровня.** Класс `: HplScript` с атрибутом `[HplMapScript("maps/main/chXX/<карта>.map")]` в `Assets/Scripts/Levels/ChXX/`. `HplMap` находит его по пути карты, переимпорт не нужен. Журнал — `docs/ScriptPort/chXX/<карта>.md`, статусы функций — `docs/ScriptPort/api.md`.
- Функции движка — в `HplScript*.cs` с оригинальными именами и параметрами (порт `LuxScriptHandler.cpp`). Порт читается как `.hps`.
- Сверка порта с оригиналом: `tools/Check-ScriptPort.ps1 -Map <карта> -Port <файл .cs>` — функции, строки, число вызовов каждой функции, числа и коллбэки из `.map`; у готовых портов 0 ошибок и 0 предупреждений, оставшиеся расхождения объясняются в журнале карты.
- Колбэки вызываются по имени, как в AngelScript. В порте имена писать через `nameof(...)`; динамические имена остаются строками.
- Преобразования AngelScript → C#:
  - `int x = RandFloat(...)` → `(int)RandFloat(...)` (отбрасывание);
  - `or`/`and` → `||`/`&&`;
  - `0.7` → `0.7f`.
- Глобальные переменные скрипта — поля класса. Локальные и глобальные переменные хранятся строками, как в HPL2 (`HplMath`: atoi/atof, `%.20f`).
- Части движка, которых ещё нет (мульти-слайдеры, кнопки), — `NotPorted`: одно предупреждение `[Script] X: skipped, needs …` на функцию. Состояние (двери, лампы, предметы, квесты) при этом хранится, `Get*` возвращают заданное.
- Ошибки, которые пишет сам движок (`Error()` HPL2 — в `hpl.log`, игра продолжается; например, скрипт просит свет, которого нет в карте), — `HplLog.Error` → предупреждение `[Script] ERROR: …`. Ошибка Unity при включённом в консоли Error Pause ставит Play на паузу. Настоящие ошибки Unity (`HplLog.PortError`, исключения) — только для ошибок порта.

**`HplMap` (порт `cLuxMap` и порядка обновления).**
- Реестр сущностей скрипта, имена без учёта регистра:
  - области, кроме PlayerStart/PathNode/PosNode;
  - пропы и враги из `.ent` с Lux-типами; StaticProp не сущность.
- Тела `<сущность>_<тело>`, свет по имени, PlayerStart.
- Таймеры: `cLuxMap::UpdateTimers` — сначала все счётчики, потом вызовы; добавленные в колбэке не срабатывают в тот же шаг.
- Шаг 60 Гц:
  1. таймеры (перед ними очищается список мерцания рендерера эффектов, как в `cLuxMapHandler::Update`);
  2. логика активных сущностей: коллбэки столкновений и взгляда, затем `OnUpdate` пропов;
  3. игрок (`StepLogic`): движение, состояние (фокус и контур предмета), голова, наклон, взгляд, в конце коллбэки «Player», текст фокуса;
  4. HUD;
  5. эффекты;
  6. тело игрока (`StepPhysics`);
  7. физика: `HplPhysicsWorld.BeforeSimulate` → симуляция (контакты → звуки поверхностей) → `AfterSimulate` (разрыв джоинтов, их звуки, остановка скольжения, перекатывание);
  8. частицы (`HplParticleWorld.Update`: шаг систем, удаление мёртвых, меши эмиттеров);
  9. свет (`AmnesiaLight.UpdateLight`: `FadeTo`, мерцание, его звуки и частицы);
  10. звук (`HplSoundHandler.Step`: звуковые сущности мира, записи, музыка);
  11. `StepPostUpdate` игрока (силы удержания);
  12. удаление сущностей, помеченных на уничтожение (их звуковые сущности уничтожаются, прикреплённые звуки остаются на месте и доигрывают; их системы частиц гаснут на месте).
- Сборка: свет регистрируется и инициализируется до пропов; затем связи билбордов со светом, пропы (`PropFactory` + `Load`), тела остальных сущностей; шаблоны (`EntityTemplates`) пропускаются.
- `OnStart`/`OnEnter` — после постановки игрока.
- Флаги: `scriptDebug` (`ScriptDebugOn`), `logDebugMessages` (`AddDebugMessage` в консоль; в HPL2 видно только в отладке), `runScript`.

**Коллбэки столкновений** (`HplCollideCallbacks`, порт `iLuxCollideCallbackContainer`).
- Тест — `Physics.ComputePenetration` по текущим transform, без `Collider.bounds`: bounds обновляются только синхронизацией PhysX и отстают у тела, которое двигает код.
- Сохранена особенность HPL2: тело i владельца сравнивается с телом i другой сущности; области и персонажи отдают своё единственное тело для любого i.

**Эффекты** (`HplEffects`, порт `cLuxEffectHandler`) рисует `HplScreenEffectsPass`: HDRP custom pass AfterPostProcess, создаётся в рантайме, глобальные настройки HDRP не нужны. Шейдер `Assets/Shaders/HplScreenEffects.shader`.
- Рендерер эффектов (`HplEffectRenderer`, порт `cLuxEffectRenderer`, проход `HplEffectRendererPass` BeforePostProcess, шейдер `Assets/Shaders/HplEffectRenderer.shader`): контур предмета в фокусе (только предметы, с которыми можно взаимодействовать; маска видимых пикселей вместо stencil, увеличенный на 2 см объект синим 0.5 вне маски, два размытия на ¼ разрешения, сложение вне маски в прямоугольнике объекта) и мерцание предметов ближе 4 м (диффуз × (0.5, 0.5, 1) × rim × пульсация). Свечение врагов в темноте (`AddEnemyGlow`) не рисуется: альфа считается в `HplEnemy`.
- Порядок HPL2: ImageTrail → RadialBlur → Sepia (1D LUT `colorconv_sepia.tga`, по каналам) → затемнение (× (1 − alpha)) и вспышки (+).
- Расчёт в sRGB-значениях, как в гамма-рендере HPL2.
- След адаптирован к динамическому FPS: эталонный вес при 60 Гц `a60 = exp(-amount × 60 × 0.015)`, вес нового кадра `1 − (1 − a60)^(frameTime × 60)`. frameTime — реальное время между рендерами; накопление в RGBA16F, без залипания 8-битного буфера на высоком FPS.
- Тряска экрана — `HeadPosAdd.ScreenShake`.
- Голоса (`PlayVoiceEffect`) — потоки GUI (или 3D в позиции) через обработчик звука; реплика идёт, пока её запись жива (время клипа считает обработчик), затем следующая и колбэк окончания.

Дневники группируются по серии, обычное чтение — 18 строк и [new_page], озвучка — [voice …] и автопереход по завершению SoundEntry. DiaryCallback получает номер внутри серии с 1; ReturnOpenJournal(false) отменяет автооткрытие текущего подбора, следующий подбор снова включает его. AddNote / AddDiary из API только добавляют данные. Подбор Note открывает текст при amount > 0 (>= 2 с озвучкой), Diary — озвученное чтение, если callback не отменил. Выполненные задания скрыты, данные сохраняются; сохранения прохождения и процент завершения пока не реализованы. Запреты вступления действуют на горячие клавиши. Проверки: JournalTests.Run (36), MenuPreview — 7 Play-снимков разделов и страниц плюс прежние 50 InventoryTests / 27 PauseTests. Документация: docs/ScriptPort/journal.md, docs/UiPort.md.

**Главное меню (пункт 5 исходного плана интерфейса)** — `HplMainMenu`, общий HplGameUi / HplPauseMenu в режиме titleScreen. Оригинальная декоративная сцена main_menu/main/menu_bg.map, русский логотип из lang/rus, музыка game_menu.ogg; новая игра / общие настройки / подтверждённый выход. LevelConverter.ConvertMenuBackground создаёт камеру на CameraPos (локальный −Z HPL, без игрока); HplMap.menuBackground обновляет мир / частицы / звук, без скрипта уровня и без присвоения игрового GameUi. Новая игра и возврат из Esc идут через асинхронную загрузку с затемнением; у новой игры — MainFadeOutTimeSlow, зум FOV и ZoomSound из menu.cfg. Повторный ввод блокируется. До проверки доступности целевой сцены данные не очищаются; перед активацией сбрасываются HplGame и временные PlayerStateVars, timeScale = 1. Звуки старой сцены освобождаются при выгрузке. Отмена выхода сохраняет текущую паузу и прогресс; предупреждение о несохранённом прохождении — из локализации оригинала. Настройки PlayerPrefs сохраняются независимо. «Продолжить» и «Загрузить игру» — см. «Сохранения»; профили, пользовательские истории и сложный режим ещё не подключены. Проверки: MainMenuTests (19, с «Продолжить» / «Загрузить игру»), MainMenuPreview.RunBatch — 23 условия настоящего Play-цикла меню → первая карта → меню → вторая новая игра → «Сохранить и выйти» → «Продолжить» с восстановленным состоянием плюс 27/50/36 прежних проверок; 8 снимков в Logs/MainMenuCheck (сохранения прогона — в Logs/MainMenuCheck/Saves). **Общее состояние игры** — `HplGame`: глобальные переменные, квесты, подсказки, предметы по имени, записи журнала и последний текст.

**Сохранения** — `Assets/Scripts/Save` (namespace `RTXMnesia.Save`): `HplSaveHandler` (`cLuxSaveHandler`), `HplSaveGame` (`CreateSaveGameData` / `LoadSaveGameData`), `HplSaveData` (классы файла — `cLuxSaveGame_SaveData` и save data классы), `HplFieldBag` (простые поля объекта текстом).
- Папка — своя: `Документы/RTXMnesia/Saves/<main|justine>`, никогда не `Документы/Amnesia` оригинала. Batch-прогоны редактора (тесты, симуляции, снимки, где скрипты карт вызывают `AutoSave`) пишут в `Logs/BatchSaves` проекта; `HplSaveHandler.FolderOverride` — для тестов. Профилей нет.
- Файл — JSON (`JsonUtility`, версия формата `SaveGame.CurrentVersion`), записывается сразу через временный файл; имя как в оригинале: `AutoSave_<DisplayNameEntry карты или NULL>_Г_М_Д_ч_м_с_n.sav`, не больше `Saving/MaxAutoSaves` (20) — самые старые по дате создания удаляются. В списке загрузки — `GetProperSaveName` («AutoSave - <название уровня> - Д/М-Г чч:мм:сс»), новые сверху.
- Когда: `AutoSave` из скриптов карт (почти все карты в `OnEnter`); «Сохранить и выйти» в меню паузы (нет у мёртвого игрока) — сохранение и титульный экран; «Выход» из игры сначала сохраняет, как `cLuxMainMenu::OnQuit` при закрытии окна. Титульный экран: «Продолжить» (новейшее сохранение, с подтверждением) и «Загрузить игру» (список, клик выбирает, повторный клик / OK — подтверждение и загрузка) — только когда сохранения есть.
- Что пишется (как `cLuxSaveGame_SaveData`): текущая карта целиком (`HplSavedMaps.CaptureCurrent`, `cLuxSavedMap`): все сущности со своими простыми полями класса и базовых классов (отражением; активность, эффекты, лампы — через их методы), тела и джоинты пропов; враги — тело, рыскание, звуковое состояние, патруль по id узлов, текущая анимация с временем, поля мовера и путь (состояние ставится, а не входится, как в HPL2); созданные скриптом и осколки — по `.ent`; чекпоинт, коллбэк фонаря, туман, переменные, таймеры, use-item коллбэки, свет, звуки и системы частиц, физические верёвки (частицы, длина, мотор, концы), что держат липкие зоны, interact connections пропов. Плюс кэш посещённых карт, игрок (`Carry` + позиция, взгляд, `active`, затухания FOV / aspect / крена, скорость события, страх, вода, монеты), инвентарь (и флаг запрета), журнал, глобальные переменные, подсказки, музыка (текущая песня с позиции, приоритеты), эффекты (затемнение, след, сепия, размытие, вспышка, очередь реплик и коллбэк, глобальные громкость / скорость), безумие (ожидание, использованные события, выключенные наборы), экран загрузки.
- Загрузка: файл читается, сохранение ждёт (`BeginLoad`) сцену своей карты (`HplMapChange.FindScene`), сцена грузится как при выходе в меню; `HplMap.Build` забирает его, `Begin` вызывает `LoadGame` вместо `OnStart` / `OnEnter`. Сущности сцены, которых нет в сохранении (подобраны, разбиты, уничтожены), удаляются. Поля C#-класса скрипта уровня начинаются заново — как глобальные переменные AngelScript, которые HPL2 тоже не сохраняет.
- Отличия и что не перенесено: состояние игрока всегда Normal (в оригинале тоже TODO для режима движения; лестница и т. п. не восстанавливаются); идущие флешбэк, обморок и смерть не восстанавливаются, поэтому их записи глобальной громкости (1, 2, 4) при загрузке пропускаются вместе с оригинальными 5 и 6; сообщения состояний врагов, снимок экрана (`abSaveSnapshot`), быстрые сохранение / загрузка (в HPL2 только отладочные), профили и сложный режим.
- Проверка: `RTXMnesia.EditorDev.SaveTests.RunBatch` (`-batchmode -nographics -quit`) на `10_daniels_room` — изменённое состояние карты, сущностей и модулей пишется в `Logs/SaveCheck`, сцена открывается заново и загружает его; имена, новейший файл, список, предел автосохранений.

**Флешбэки** — `PlayerFlashback` (порт `cLuxPlayerFlashback`) и `HplArea` с типом Flashback: проверка пересечения с телом игрока раз в 0.1 с, отключение области, отложенные вспышки, сепия / радиальное размытие, громкость мира (запись 1), множители движения из `game.cfg`, голоса с субтитрами и коллбэк; очередь ждёт 6 с после окончания. `GetFlashbackIsActive` возвращает состояние помощника; во время флешбэка темнота не снижает рассудок. `FlashbackConverter` переносит все `source/flashbacks/*.flash` в игнорируемый `Resources/HplFlashbacks.asset` (`HplFlashbackAssets`), обновляя ассет на месте, и вызывается импортом уровня. Меню Import > Flashbacks (.flash), batch: `-batchmode -nographics -quit -executeMethod RTXMnesia.Importer.FlashbackConverter.ConvertBatch`; переимпорт карт не нужен. Проверка: `PlayerSimulation.RunBatch` на `02_entrance_hall`, вход в AreaFlashBack (Unity ≈ −33.25, 0, 9.75), `watch` / `sounds` / `shot`; регрессии `MapChangePreview.RunBatch` и `MainMenuPreview.RunBatch` (без -quit/-nographics). Флешбэк и вспышка эмоции сбрасывают врагов (`Reset` → ожидание). Процент завершения и журнал прогресса ещё не подключены.

**Смена карты** — `HplMap.ChangeMap` / `CheckMapChange` (порт `cLuxMapHandler`) + `HplMapChange`.
- Каждая карта — своя сцена со своими игроком, эффектами и звуком; в HPL2 они одни на всю игру. `ChangeMap`: стартовый звук, затемнение 1.5 с, игрок неактивен, обновление карты (таймеры, сущности) остановлено. Когда затемнение закончилось: FadeIn 2 с, игрок активен; та же карта — только перенос к стартовой точке. Другая карта: `OnLeave`, сохранение в `HplSavedMaps`, мировые звуки затухают (0.5), карта замораживается, сцена грузится асинхронно под экраном загрузки.
- Переносится (`HplMapChange.Arrival`): `AmnesiaPlayer.Carry` (множители скоростей, здоровье, рассудок, масло, огниво, фонарь, присед, смещения головы, предмет в руке; FOV / aspect / крен сбрасываются, как `cLuxPlayer::OnMapLeave`), `HplEffects.Carry` (затемнение, след, вспышка, тряска; сепия и радиальное размытие гаснут за 1 с), играющая музыка (объект `HplMusicHandler` целиком, без паузы; `OnMapLeave` дожимает затухания) и глобальные громкость / скорость звука. Голоса и GUI-звуки при смене сцены обрываются.
- В новой карте `HplMap.Begin` → `Arrive`: перенос, игрок у стартовой точки (`PlacePlayerAtStartPos`: неизвестная — ошибка и первая по имени), чекпоинт `_auto`, `OnStart` при первом посещении, `OnEnter`; затем экран загрузки держит карту на паузе (timeScale 0, ввод игрока заблокирован).
- Сцена карты ищется по имени файла среди сцен сборки (`HplMapChange.FindScene`); нет в сборке — ошибка настройки в лог, игра остаётся на месте. `HplSavedMaps` (порт `cLuxSavedGameMapCollection` / `cLuxSavedGameMap`): при уходе с карты сохраняются локальные переменные, таймеры, use-item коллбэки, коллбэки столкновений игрока и сущностей, свет карты, звуки и системы частиц из скрипта, связи сущностей, отключённые сущности, запертые двери и двери уровня, подобранные предметы, разбитые контейнеры, погашенные лампы; сущности FullGameSave (MoveObject, созданные скриптом, липкие зоны и то, что они держат) — целиком (тела, джоинты, поля пропа), interact connections пропов. Верёвки в кэш карты не попадают (в HPL2 тоже): при возвращении они снова как в карте. При возвращении `LoadMap` повторяет `ToMap` в оригинальном порядке, затем только `OnEnter`. Ключ сущности — ID карты.

**Экран загрузки** — `HplLoadScreen` (порт `cLuxLoadScreenHandler`), объект переживает смену сцены.
- `SetupLoadScreen`: категория / запись текста, `alRandomNum` нумерованных записей (не повторяются, пока не показаны все), картинка `graphics/general/game_loading_*.jpg`. Шрифт и раскладка — `menu.cfg` LoadScreen на виртуальном 800×600.
- После загрузки текст держится `GetStringDuration × TextDurationMul` минус время загрузки (Esc / Space / Tab / ЛКМ / ПКМ пропускают), картинка и красное «Загрузка» гаснут (0.33/с), текст съезжает к `TextAloneY`, затем затемнение `FadeOutTime` и звук конца.
- Ресурсы: `LoadScreenConverter` → игнорируемый `Resources/HplLoadScreen.asset` (вызывается импортом уровня, меню Import > Load screen resources).

**Руки и фонарь** — `PlayerHands` (порт `cLuxPlayerHands`, `iLuxHandObject`, `cLuxHandObject_LightSource`) и `PlayerLantern` (`cLuxPlayerLantern`).
- `HandsConverter` (меню Import > Player hands and hand objects) → игнорируемый `Resources/HplHands.prefab` (`HplHandsData`): `models/player/hands/hands.ent` (скелетная модель через импорт Unity как Legacy, анимации `.dae_anim` копируются как `.dae` и сохраняются клипами с именами из `.ent`) и все `models/hand_objects/*/*.ho` с сущностью модели (свет, билборды — общая сборка `LevelConverter.BuildEntitiesPrefab`). Переимпорт карт не нужен.
- Руки следуют за камерой, поворот сглажен по `HandsRotationSmoothNum` шагам (веса растут квадратично), смещения головы Bob / ScreenShake / Hurt × `HandsPosAddMul` вычитаются. Смена предмета: holster → draw → idle (`CrossFade` 0.2 с, неповторяющиеся клипы держат последний кадр). Источник света: свет, билборды и подсветка материала проявляются / гаснут за FadeIn/OutTime, мерцание включается после проявления, маятник `Sway*` (угол взгляда, скорость игрока, трение, пределы), подмеш `SkipSwaySubMesh` не качается.
- Фонарь: F / предмет инвентаря / `SetLanternActive`; без предмета — подсказка LanternNoItem, без масла — LanternNoOil и звук; расход `LowerOilSpeed`/с (не во время вспышки эмоции), кончилось масло — звук и выключение; `LanternLitCallback` карты. Собственный свет `cLuxPlayerLantern` (Radius 0.0001) ничего не освещает и не создаётся. На лестнице фонарь запрещён (`PlayerState.AllowLantern`).

Руки — на слое рендеринга 7 (`HplLighting.HandsRenderingLayer`), свет предмета в руке его не освещает (маска младших 8 бит слоёв без 7, `HplLighting.SetLightLayers` через `HDAdditionalLightData.lightlayersMask`), а копия света с `shapeRadius` = расстоянию до кости крепления освещает только руки на уровне HPL2. Свет карты освещает и руки. В HDRP-ассете включены Light Layers (`ConfigureHDRP`).

**Рассудок и темнота** — помощники игрока в порядке `cLuxPlayer` (`AmnesiaPlayer.StepLogic`): `PlayerLightLevel`, `PlayerInDarkness` (`Player/PlayerDarkness.cs`), `PlayerSanity`, `PlayerCamDirEffects`, `PlayerInsanityCollapse` (`Player/PlayerSanity.cs`); числа — `game.cfg` `Player_Darkness` / `Player_Sanity` / `Player_General`.
- Освещённость (`cLuxPlayerLightLevel` + `cLuxMapHelper::GetLightLevelAtPos`): дважды в секунду в пяти точках тела сумма по свету (`AmnesiaLight.LightLevelAt`: box — max цвета внутри коробки; точечный и прожектор (фрустум `spotFov`/`spotAspect`/`spotNearClip` из импорта) — max цвета × (1 − d / (r + RadiusAdd)), прожектор с тенями — при прямой видимости), обычная и с RadiusAdd; горящий фонарь +1. Реестр — `AmnesiaLight.All`.
- Темнота (`cLuxPlayerInDarkness`): при обычной освещённости ≤ AmbientLightMinLightLevel загорается слабый синеватый свет на 0.3 м ниже камеры (без теней, не сохраняется; у HDRP-света `shapeRadius` = радиус и ×4 к канделам — так спад 1/(d² + r²) у игрока даёт яркость HPL2); при расширенной ≤ MinLightLevel рассудок падает SanityLossPerSecond × множитель (растёт 0.1/с), подсказка DarknessDecrease раз в 3 с (не во время вспышки эмоции и при SetSanityDrainDisabled).
- Рассудок (`cLuxPlayerSanity`): удар (`GiveSanityDamage`) — звук и наезд камеры (след, FOV, aspect); потеря с эффектом — сердцебиение и звуки утечки; ниже SanityEffectsStart — эффект безумия; ниже SanityVeryLowLimit — подсказка, след 1.6, дыхание; восстановление до SanityRegainLimit; через SanityLowLimitMaxTime ниже SanityLowLimit — SanityLowNewSanityAmount. Враги в поле зрения (`UpdateCheckEnemySeen`: до 35 м, во фрустуме, 2 из 5 лучей) — NearEnemyDecrease и подсказка EnemySeen; жуки — с критерами.
- Эффект безумия (`cLuxPostEffect_Insanity`, `HplEffects.Insanity`): проход в `HplScreenEffects.shader` до следа (приоритет 25), карты амплитуд и зума `shaders/posteffect_insanity_*.jpg` → `PostEffectsConverter` → игнорируемый `Resources/HplPostEffects.asset` (вызывается импортом уровня, меню Import > Post effect resources).
- Покачивание взгляда (`cLuxPlayerCamDirEffects`) при рассудке ≤ StartSwayMaxSanity: шаг мыши — среднее последних SwayMaxSavedPositions шагов; мышь здесь каждый кадр, поэтому ввод кадра копится в шаг, а среднее применяется с долей кадра в шаге.

Обморок поднимает тревогу у активных врагов (`AlertOfPlayerPresence`).
- События безумия — см. «События безумия».

**События безумия** — `Effects/HplInsanity.cs` (`cLuxInsanityHandler` и `iLuxInstanityEvent`), `HplArea` с типом Insanity (`cLuxArea_Insanity`); числа — `game.cfg` `Insanity`.

Переимпорт карт не нужен.
- Выбор: случайное неиспользованное событие включённого набора с MaxSanity ≥ рассудка (все использованы — сброс); после события ожидание `TimeBetween_*` по рассудку (`MaxSanity_*`). Новое событие возможно без ожидания, при рассудке ≤ `MaxSanity_LongWait` и без текущего.
- Типы: Bugs (жуки на HUD с краёв экрана к центру: блуждание + точка роя, проявление, исчезновение после Duration, петля GUI-потока), Particles (система у камеры, следует за ней, GUI-поток), SoundStream (GUI-поток после задержки; затемнение — модулятивный цвет FadeColor × a + белый × (1 − a) или картинка; субтитр шрифтом 18 от x = 250, пока не играет голос; DisablePlayer), Steps (звуковые сущности в случайном направлении, всё ближе и чаще).

**Верёвки, связи, липкие зоны, слизь**
- Верёвка: область Rope → `HplRope` (`ScriptApi/HplRope.cs`, порт `cLuxRope` / `cLuxAreaRopeLoader`): свойства из переменных области или из файла `RopeFile` (`misc/*.rope`). - Физика — `Dynamics/HplPhysicsRope.cs` (`iPhysicsRope` + `iVerletParticleContainer`, в пространстве HPL2): первая частица неподвижна, остальные падают с гравитацией мира; шаг: проверка сна (раз в 1/3 с), мотор или авто-движение меняют полную длину (частицы добавляются / убираются у начала, первый сегмент — остаток деления), Verlet с демпфированием, концы следуют за телами, 3 итерации ограничений длины, PID-сила (p = Strength, d = Strength·0.1·Stiffness) тянет тело конца к его частице (сила × масса, момент × инерция). `HplPhysicsWorld`: верёвки до тел и после них. Звук мотора: `.snt` у первой частицы, FadeIn 5 / FadeOut 10 по скорости. Столкновений частиц нет (в оригинале отключены). Отличие: при нулевой длине сегмента HPL2 делит на ноль, здесь ограничение пропускается.
- Отрисовка — `World/HplRopeGraphics.cs` (`cRopeEntity`): квад на сегмент, повёрнутый к каждой камере (`beginCameraRendering`), UV повторяются LengthTileAmount раз на сегмент, первый (короче) обрезается. Отличия: нормаль смотрит на камеру (в оригинале — от камеры), смещения концов берутся из интерполированных поз тел кадра.

- Липкая зона — `ScriptApi/HplStickyArea.cs` (`cLuxArea_Sticky`, у `HplArea.Sticky`): тело с массой, активное, сталкивающееся, чей центр масс (CheckCenterInArea) или AABB внутри зоны, чьё имя содержит AttachableBodyName и форма касается зоны, после AttachFunction (может разрешить `SetAllowStickyAreaAttachment`) становится статичным без гравитации и за PoseTime встаёт в позу зоны (цель — позиция зоны минус локальный центр масс, без поворота, как в оригинале), затем звук и частицы. Последнее тело не берётся снова, пока не выйдет: сбрасывается, когда широкая фаза Newton (AABB + 1/8 м) ещё возвращает его, а точная проверка — нет. Зона и прикреплённая сущность сохраняются целиком. **Титры, NPC, анимации и прикреплённые пропы**
- Титры — `Ui/HplCredits.cs` (`cLuxCredits`): `StartCredits` включает контейнер Credits — карта, скрипт и игровые модули стоят (`timeScale` 0, ввод игрока и меню паузы заблокированы, HUD скрыт), идут только движковые звуковые записи и музыка (`HplSoundHandler.StepEngine`, без `cLuxMusicHandler`); финальная песня — напрямую `cMusicHandler::Play` (`HplMusicHandler.PlayDirect`). Текст `Ending/MainCredits` переносится по 750 при размере 17 (строки с `*` — заголовки шрифтом `menu.fnt`), прокручивается ScrollSpeed, у конца песня гаснет, затемнение и проявление «Конец» (`General/TheEnd`) с кодом концовки основной игры (tyr299 / odn314 / lke271), Exit — последнее затемнение и главное меню кампании со сбросом игры (как выход из паузы). Exit / прыжок / ЛКМ / ПКМ / Tab пропускают прокрутку и «Конец», не раньше 3 с. Особенности оригинала: конец прокрутки считается своими высотами строк 17 / 19 (пустые дважды), а не рисуемыми; таймер сбрасывается только с началом затемнения — «Конец» можно пропустить сразу. Раскладка — `menu.cfg` Credits на 800×600. `AddKeyPart` хранит части (`HplCredits.KeyParts`, сброс с новой игрой), их проверка в HPL2 закомментирована.
- Анимации пропов — `HplProp` (`iLuxProp` + `cMeshEntity`): скелетная модель сущности с анимациями `.ent` (импорт Enemies теперь берёт все анимированные `.ent`: Агриппа, Александр, пленники, паук, крысы) играет первую анимацию по кругу со случайного места (`RandomizeAnimationStart`), `PlayAnimation` — переход затуханием, неповторяющаяся по окончании зовёт коллбэк (имя пропа). Поза — после физики, как у врагов (`HplMeshAnimation`: `Play`, `PlayFadeTo`, `Stop`); события PlaySound — звуковая сущность у первой кости. Неактивный проп не обновляется. Сохраняются все состояния анимаций (`cEngineAnimationState_SaveData`: активность, цикл, вес, шаг затухания, время, скорость). Кости ищутся по имени HPL2 — `id` узла Collada (`HplEnemyAssets.Enemy.FindNode`: импорт сохраняет пути имён узлов; у Агриппы два узла с именем `CenterHead`).
- NPC — `Props/PropNPC.cs` (`cLuxProp_NPC`): `Awake` экземпляра (без эффектов — Idle / SleepIdle), `SetNPCAwake` с эффектами — Awake / Sleep, затем петля; в области `FollowPlayerArea` (проверка дважды в секунду) голова поворачивается к игроку: угол в плоскости xz меша до MaxHeadAngle, скорость HeadMoveSpeedMul × разница (до HeadMoveMaxSpeed), поворот костей MoveHeadBones × MoveHeadBoneMuls после позы анимации (pre-transform: локальная × поворот; в отражённом пространстве Unity — минус угол вокруг отражённой оси). Ось — «вверх» скелета в пространстве кости, как в HPL2 точкой (0,1,0) с учётом позиции кости. `SetNPCFollowPlayer`. Взаимодействия нет. Область ищется при первом обновлении.
- Прикреплённые пропы — `HplProp.AddAndAttachProp` (`iLuxProp`): `.ent` создаётся в начале координат, не сохраняется сам (`HplEntity.IsSaved`), тела статичны, без столкновений и неактивны, первое тело каждый шаг пропа = главное тело × смещение × его локальная поза (пока главное тело не спит). `RemoveAttachedPropFromProp` уничтожает, уничтожение родителя уничтожает прикреплённые. Родитель сохраняет список (имя, файл, смещение) и создаёт их заново при загрузке; в кэш карты, как и в HPL2, не попадают. Особенность: устаревшая `AddAttachedPropToProp` передаёт fRotZ как z позиции.
- Проверки: `RTXMnesia.EditorDev.CreditsPreview.RunBatch` (без -quit/-nographics) — 12 условий Play на `29_orb_chamber` (снимки `Logs/CreditsCheck`); `RTXMnesia.EditorDev.NpcAnimationTests.RunBatch` (`-batchmode -nographics -quit`) — 30 условий: Агриппа на `21` (сон, пробуждение, Idle, поза скелета, голова и её отключение, сохранение состояний), ритуальный пленник на `24` (первая анимация, squirm и коллбэк `PrisonerSquirmOver`, неизвестная анимация), Александр на `29`, мясо на грузе верёвки `21` (создание, слежение, удаление, уничтожение с родителем, особенность `AddAttachedPropToProp`).
- Не перенесено: крысы и пауки-критеры (`CritterBug` / `CritterSpider`) только играют первую анимацию, без поведения.

**Прогон** — `PlayerSimulation`: на уровне с `HplMap` шаги идут через карту, сообщения `[Script…]` копируются в лог.
- Флаги:
  - `-scriptDebug` — области вступления активны сразу, вступление пропускается;
  - `-noScript`;
  - `-globals "имя=значение;…"` — глобальные переменные до старта карты (возвращение на хаб, например `key_study_1=key_study_1` — событие стража на `02_entrance_hall`);
  - `-seed N` — повторяемые `RandFloat`.
- Команды:
  - `watch t интервал` — шаги со строкой состояния скрипта: игрок, FOV/aspect/крен, затемнение/след/сепия, реплика, сообщения, таймеры;
  - `fx sepia|trail|fade|blur|flash|off значение`;
  - `goto x y z yaw`;
  - `start Зона`;
  - `interact`, `release`, `throw`, `scroll n`, `rotate on|off`, `mouse x y t [log]` (единицы мыши HPL за шаг, y вниз);
  - `aim Сущность [Тело]` — повернуть камеру на тело; `body Сущность` — состояние пропа/двери/лампы, тела, джоинты;
  - `call Функция аргументы` — вызвать функцию скрипта уровня.
  - `particles` — системы частиц: число частиц по эмиттерам, состояние, расстояние.
  - `sanity [значение]` — задать рассудок и вывести освещённость, темноту, удар / утечку / покачивание / обморок, эффект безумия и три главных источника света у игрока; `lightsoff` — скрыть весь свет сцены (проверка темноты, лучше с `-noScript`); `active Сущность true|false` — включить сущность (карты без порта скрипта); `fitsup dy` — помещается ли тело выше и что ему мешает; `health` — здоровье, ранение, брызги / вспышка, состояние смерти и чекпоинт (урон — `call GivePlayerDamage 60 claws true false`); `enemy [Имя]` — враги: состояние, чувства, путь, анимация, страх и музыка врагов (строка `watch` тоже показывает активных врагов); `insanity [Имя|random|stop]` — запустить / остановить событие безумия и вывести состояние обработчика; `ropes` — верёвки (длина, частицы, мотор, концы) и что держат липкие зоны.
  - `sounds` — играющие записи (имя, тип, расстояние, время), звуковые сущности, музыка, глобальные громкость и скорость.
  - `overlaps Сущность` — пересечения коллайдеров её тел между собой и с миром (глубина, направление, слой).
  - `hide lights|passes|volumes|<часть имени шейдера>` — выключить весь свет, custom pass, Volume или рендереры с таким шейдером (бисекция проблем рендера).
- Строка состояния включает состояние игрока, прицел и текст фокуса.
- Пример: вступление `00_rainy_hall` — `-seed 1 -script "watch 80 2; shot awake"` (~70 с до первого квеста).

## Проверка импорта геометрии

- `HplMeshAudit.Run` (меню Tools > RTXMnesia > Import > Audit level meshes against MSH) сравнивает меши уровня с бинарными `.msh` v7 из `source/`, проверяет исходные пути моделей, матрицы всех статических объектов и подмешей сущностей, положения тел и соответствие mesh-коллизии визуальному мешу. Отчёт: `Logs/HplMeshAudit.txt`. Это независимая проверка; `.msh` не являются источником импорта.
- Порядок треугольников: сборщик отражает X и меняет COLLADA-тройку `(a,b,c)` на `(a,c,b)`. HPL2 `CreateVertexBuffer` сохраняет `(c,b,a)`: это тот же обход с циклически сдвинутой первой вершиной. При сверке `.msh` сравнивать ориентированные тройки с учётом циклического сдвига, а не индексы побайтно.
- Проверять не только успешный batch-импорт, но и контрольные рендеры, соответствие пути модели записи карты и проход игрока. Геометрически правильный меш может оказаться неверно выбранным одноимённым ресурсом.
- Проверка `00_rainy_hall` 2026-10-14: исправлены 123 подмены статических моделей. 124 модели / 274 подмеша совпадают с MSH по вершинам и ориентированным треугольникам; 925 экземпляров / 1413 матриц подмешей проверены; 471 проверка выбора одноимённых ресурсов прошла. Две разницы матриц исходных префабов относительно MSH (`candlestick_wall`, `armour_rusty_complete/podium`) остаются явно отмеченными в отчёте: в этой сцене их заменяют трансформы `.ent`, и итоговая расстановка совпадает. Прогон игрока по лестнице PlayerStartArea_x2 вниз и вверх успешен.
