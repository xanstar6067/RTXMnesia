# Улучшенное освещение: что сделано и как настраивать карты

Инструкция для того, кто ставит свет на следующих картах (человек или ИИ-агент). Оверлей
`maps/main/ch01/01_old_archives` — образец (частично проверен); `00_rainy_hall` — первичная настройка.
Точный статус и журнал карт — [maps.md](maps.md).

## Зачем это

Свет HPL2 рисовали руками под дешёвый deferred-рендер 2010 года:

- у большинства источников нет теней, спад внутри радиуса почти плоский, за радиусом света нет вовсе;
- отражённого света (GI) не было, поэтому по комнатам расставлены **заполняющие** источники — точки в воздухе
  без лампы, «чтобы не было черно»;
- источники ламп вынесены из огня в комнату (свеча — на 0.4 м вбок, факел — на 1.64 м от стены), чтобы стена
  рядом не пересвечивалась;
- лунный свет окна — точка или короткий конус в метре перед окном.

В классике это незаметно. С тенями, RT-тенями и RTGI каждый такой трюк виден: тени падают из центра комнаты
или из пустоты, стены светятся без причины. Поэтому есть режим **«Освещение: Улучшенное»** (вкладка «Графика»,
`HplUserSettings.lightingSet` = 1). Классика при этом не меняется никогда (решение пользователя 2026-10-21).
Цель — постановка света «как если бы игру делали сейчас»: каждый настоящий источник светит из своего огня или
окна и отбрасывает тень, отражённый свет даёт RTGI, а заполняющий свет остаётся только там, где без него черно.

## Что делается само на всех картах (код, не оверлей)

`Assets/Scripts/World/HplEnhancedLighting.cs`, `ApplyRules`. Эти пункты **не нужно** повторять в оверлее карты.

1. **Лампы** (сущности с `EntityType="Lamp"`: свечи, факелы, люстры, подсвечники, печи):
   - источник переносится в пламя (по системам частиц огня в `.ent`; у люстры — в центр её пламён), в тело
     огня, а не в начало частиц (факел и печь +15 см, свеча +1.5 см);
   - яркость физическая: число пламён × 15 кд за свечу (`CandleCandela`; факел — 10 свечей, печь / костёр — 20,
     прочий огонь — 3, фонарь в руке — 10). Затухание и мерцание лампы её масштабируют;
   - дальность — до освещённости 0.25 лк (`VisibleLux`), не больше 25 м: свеча 7.75 м вместо 1.7, факел 24.5 вместо 3.4;
   - мягкость RT-тени — размер пламени (свеча 1.2 см, факел 6 см, печь 15 см; у люстры — разброс пламён);
   - лампы всегда с тенями: лучами, если есть свободный RT-слот, иначе картой теней низкого разрешения.
     Сама модель лампы тень не отбрасывает. Bias карты теней ламп: normal 4, slope 0, ближняя плоскость 2 см;
   - воск зажжённой свечи светится изнутри (отдельный рендерер, свет на слое воска; материалы —
     `Tools > RTXMnesia > Build candle wax materials`).
2. **Заполняющий свет**: свет самой карты (не сущности) без `CastShadows` считается заполняющим и никогда
   не получает тени, в том числе RT-тени «от всех источников». Так RT-слоты достаются настоящим огням, а не
   точкам в воздухе (именно они давали тени «из центра комнаты»).
3. Вся геометрия карты отбрасывает тень обеими сторонами граней. Стены между комнатами с рельефом улучшенных
   текстур разносятся по своим комнатам (`HplEnhancedRelief.SeparateSharedWalls`), иначе швы светились светом
   соседней комнаты.
4. **Логика игры видит классику.** Освещённость для рассудка, темноты и врагов (`AmnesiaLight.LightLevelAt`)
   считается по классическим позициям и яркостям; добавленные оверлеем источники в неё не входят. Поэтому
   оверлей не меняет геймплей, и его можно смело править.

## Что делает оверлей карты (ручная работа по картам)

Файл: `UnityProj/UMnesiaRTX/Assets/Resources/HplEnhancedLighting/<путь .map без расширения>.json`,
например `.../maps/main/ch01/01_old_archives.json`, для Justine — `.../maps/ptest/01_cells.json`.
Это наши данные, они в git (вместе с `.meta`, который создаёт Unity). Применяется сразу при загрузке карты и
при смене настроек, снимается без перезагрузки.

```json
{
  "lights": [ { "name": "PointLight_35", "when": "gi", "intensity": "0", "shadows": "off", "note": "почему" } ],
  "add":    [ { "name": "Window_sky_17", "type": "rect", "position": "37.40 0.675 17", "target": "30 0.675 17",
                "size": "1.1 1.47", "color": "0.55 0.65 0.78", "intensity": "90", "range": "12",
                "shadows": "on", "note": "почему" } ]
}
```

Все значения — строки; пустое или отсутствующее поле — без изменений. Координаты — **как в `.map` (HPL2)**,
не Unity (в Unity ось X отражена).

`lights` — изменить свет карты по имени (`Name` в `.map`):

| Поле | Смысл |
|---|---|
| `intensity` | **множитель** яркости; `"0"` — источник не рисуется (так «убирают» свет) |
| `range` | новый радиус, м |
| `position`, `target` | перенос и поворот: источник смотрит на `target` |
| `shadows` | `"on"` / `"off"`; `off` — без теней, и без RT-теней «от всех источников» |
| `sourceRadius` | радиус источника для мягкой RT-тени, м |
| `when` | запись действует только в режиме: `rt` / `raster` (трассировка вкл / выкл), `gi` / `nogi` (RTGI вкл / выкл); пусто — всегда |
| `note` | почему так — обязательно, программа его не читает |

Для одного источника можно дать несколько записей с разными `when` (пример — `PointLight_35`: при RTGI 0, без
него 0.7).

`add` — новый источник (под объектом «Enhanced lights» карты, в сохранения не попадает):

| Поле | Смысл |
|---|---|
| `type` | `point`, `spot`, `rect` (прямоугольный, для окон и проёмов) |
| `position`, `target` | где стоит и куда смотрит; `rect` светит в сторону `target` |
| `size` | у `rect` — ширина и высота, м |
| `angle` | у `spot` — внешний угол, градусы |
| `color` | цвет sRGB, `"r g b"` 0–1 |
| `intensity` | кандела у `point` / `spot`, **ниты** у `rect` |
| `range`, `shadows`, `sourceRadius`, `when`, `note` | как выше; без `shadows` добавленный свет без теней |
| `follow` | имя света карты: добавленный свет повторяет его яркость и видимость (лампа зажжена / потушена, мерцание, `FadeLightTo` скрипта) |

### Правила, которые нельзя нарушать

- **Свет карты не удалять и не переименовывать.** «Убрать» — это `"intensity": "0"`. Скрипты карты
  (`.hps` и порт `Assets/Scripts/Levels/...`) гасят, зажигают и затухают свет по имени (`FadeLightTo`,
  `SetLightVisible`, `"LightOff_"+i`). Множитель 0 сохраняется при затухании.
- **Источники ламп в оверлее не трогать** (имена вида `<сущность>_PointLight_1`): их уже ведёт общее правило.
  Если с конкретной лампой что-то не так — это вопрос к правилу, запишите в журнал.
- **Классику не менять**: ни `.map`, ни импорт, ни `AmnesiaLight` под классический режим.
- Ресурсы Amnesia не коммитить. Оверлей JSON — можно и нужно.
- `CLAUDE.md` и `AGENTS.md` должны оставаться побайтно одинаковыми.
- Box-свет (`BoxLight`, окружающий свет яруса) — не HDRP-источник, оверлей на него не рассчитан: не трогать (см. «Не сделано»).

## Как проходить карту

1. **Список источников.** `python tools/List-MapLights.py maps/main/ch01/<карта>.map` (с `--box xmin zmin xmax zmax`
   — одна комната). Покажет весь свет с позициями, радиусами, цветом и тенями (`fill?` — заполняющий),
   лампы-сущности (их не трогать), окна (откуда должен идти свет неба / луны) и имена света, которые использует
   скрипт. Комнаты удобно определять по координатам стен и окон.
2. **Классифицировать каждый источник карты** (не ламп):
   - *лунный / дневной свет окна* — точка или конус в метре перед окном → перенести к стеклу (`position` у стекла,
     `target` вглубь комнаты, `shadows: on`, `sourceRadius` ≈ 0.35 — размер проёма, `range` ≈ 10, `intensity` ≈ 2.5);
   - *окно без источника* или окно, которое должно светить всей площадью → `add` типа `rect` в плоскости стекла
     (`size` — размер проёма; ночное небо: `color` 0.55 0.65 0.78, 90–150 нит, `range` 12–14, `shadows: on`);
     у эркера — в его устье, у заколоченного окна — за досками (доски дадут полосы);
   - *заполняющий посреди комнаты* → при RTGI выключить (`when: gi`, `intensity: 0`), без RTGI оставить слабее
     (`when: nogi`, 0.6–0.7), всегда `shadows: off`;
   - *заполняющий в нише окна* (подсветка проёма) → `intensity` 0.3, `shadows: off`;
   - *заполняющий «свет факела на весь зал»* рядом с лампами (как `LightOff_1…4`) → как заполняющий посреди комнаты;
   - *источник у реального огня, не лампы* (печь, камин, костёр карты) → оставить, `range` / `sourceRadius`
     по размеру огня;
   - *цветной «декоративный» свет* (лужи, слизь, магия) → обычно оставить, при необходимости ослабить.
3. **Не убирать заполняющий свет, пока нет настоящего источника.** Если комната без него чёрная (проба `nofill`),
   сначала поставьте источник окна / проёма, потом гасите заполняющий. Где источников нет совсем (подвал без
   окон), заполняющий остаётся — запишите это в журнал.
4. **Проверка рендерами** (Unity с проектом должен быть закрыт):
   ```
   powershell -File tools/Run-EnhancedLightingPreview.ps1 -Map maps/main/ch01/01_old_archives.map `
     -Views "stove:30 -2 24 34 -1 17;hall:-5 -2 10 -9 0 5" -Modes "classic_rt,enhanced_rt,enhanced_raster"
   ```
   Вид — `имя:ноги_x y z цель_x y z` в координатах `.map` (ноги — на полу, камера на высоте глаз); после вида
   `|режим,режим` — свои режимы. Режимы: `classic_*` / `enhanced_*`, `_rt` — с трассировкой, `_raster` — без;
   добавки: `nofill` — без заполняющего света (хватает ли RTGI), `only` — весь свет выключен, кроме зажжённых ламп
   (`-Lit лампа,лампа`) и фонаря, `lantern` — фонарь в руке, `noshadow` — без его RT-теней, `tex` — улучшенные
   текстуры, `mats` — материалы у цели вида, `walls` — модули стен у цели. Результат —
   `UnityProj/UMnesiaRTX/Logs/EnhancedLighting/<карта>_<вид>_<режим>.png` и `<карта>_report.txt` (средняя яркость,
   время кадра, источники у вида: тип, яркость, тени, трассируется ли). Скрипт сам проверяет, что
   ProjectSettings не изменились.
   Проверка отключает скрипт карты, автосохранения, AI и эффекты безумия только в памяти тестовой сцены
   (сцена не сохраняется). RTGI в снимках — среднее, флаг `nogi` отключает его. Перед снимками проверяются
   три цикла переключения классика → улучшенное → классика: восстановление позиций, поворотов, яркости,
   радиусов, цвета, флагов теней исходных источников и отсутствие накопления добавленных. На `00_rainy_hall`
   дополнительно проверяются затухания молнии, видимость окна и сохранение погашенного света при переключении.
5. **Что искать на снимках:** тени должны падать от огня или окна, а не из воздуха; стена рядом с лампой не
   должна быть темнее дальней; нет света сквозь стены и пол; комната не чёрная там, где в классике был виден путь
   (это игра — игроку нужно видеть дорогу, но темнее классики допустимо); с RTGI и без него (`enhanced_raster`)
   картинка разумная.
6. **Записать в журнал** [maps.md](maps.md): карта, какие комнаты, что сделано с какими источниками и почему,
   что оставлено и что не проверено. В каждой записи оверлея — `note`.

## Не сделано (план модернизации, на 2026-10-22)

- Box-свет (окружающий свет ярусов) не заменён окружением / GI: в path tracing и в отражениях его нет.
- Эмиссия материалов не участвует в освещении специально (кроме воска свечей).
- Без RT нет SSGI и дешёвых теней (кэшированные карты, PCSS, контактные тени, тень фонаря) — пока вместо
  RTGI слабый заполняющий свет (`nogi`).
- Нет системы анализа источников (выбор теней по доле света, а не по расстоянию до камеры).
- Нет нового определения темноты по «датчику» Даниэля (видимый свет улучшенного режима).
