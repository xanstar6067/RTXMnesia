# Улучшенные текстуры

Прототип настоящего геометрического рельефа для этого набора: [EnhancedRelief.md](EnhancedRelief.md).

Первый материал — `static_objects/castlebase/wall/castlebase_wall`, PBRify 4K, 2026-10-19.
Переключение: **Настройки → Графика → Текстуры → Классические / Улучшенные → OK**.
Черновик и «Отмена» работают через существующую систему настроек; выбор сохраняется как
`HplUserSettings.textures` (0 / 1). Освещение выбирается независимо от текстур.
Подключён полный готовый пакет PBRify из `sourceRTXRemix`: 497 RGB + 119 cutout наборов,
всего 616 комплектов для 630 материалов (121 cutout). Один набор может обслуживать несколько материалов.
Материалы без готовой замены сохраняют классический вид.

## Исходные данные и импорт

Исходники эксперимента, включая workflow и контрольные суммы:
`sourceRTXRemix/static_objects/castlebase/wall/castlebase_wall/pbrify-x4-20261019-181639/`.
Оригиналы в `source/`, установленная игра и классические Unity-материалы не изменяются.
Все исходные результаты нейрогенерации и workflow сохраняются в `sourceRTXRemix` для правок.
Предыдущие производные Enhanced PNG тоже не удаляются; актуальные материалы используют DDS.
Обе папки ресурсов и весь `Assets/AmnesiaImported/` исключены из git.

Меню: **Tools → RTXMnesia → Import → Enhanced textures: castlebase wall (PBRify)**.
Batch-метод: `RTXMnesia.Importer.EnhancedMaterialConverter.ConvertBatch`.
Для массового пакета: **Enhanced textures: all completed PBRify sets**, batch-метод
`RTXMnesia.Importer.EnhancedMaterialConverter.ConvertReadyBatch`.
Он берёт снимок завершённых `result.json` из `pbrify-x4-batch-v1` и `pbrify-alpha-x4-batch-v1`, проверяет SHA256 всех карт и
исходной albedo, точные ссылки материалов и поддерживаемый тип. Незавершённые задания
фонового генератора не подключаются. Генератор продолжает работу независимо от импорта.
Для повторяемого снимка можно передать `-enhancedResults <абсолютный txt со списком result.json>`.
Перед batch-запуском редактор проекта должен быть закрыт.

Перед первым импортом полного пакета выполнить `tools/Prepare-EnhancedTextures.py` через Python с Pillow
(подходит standalone Python ComfyUI). Скрипт проверяет SHA256, размеры, принадлежность исходникам,
неизменность alpha и создаёт DDS через установленный в RTX Remix NVIDIA `nvtt_export.exe`.
Путь экспортёра можно задать `--nvtt`. Неизменённые комплекты с валидной сигнатурой пропускаются.
Список `Logs/EnhancedFull/results.txt` фиксирует снимок; `__prepared.json` связывает DDS с исходными SHA256.
Unity нельзя открывать, пока упаковка не завершилась: это исключает импорт недописанного DDS.
После успешной проверки DDS упаковщик удаляет только собственные временные mask/normal PNG
из `Logs/EnhancedFull/Packing`. Исходные PNG и workflow не затрагиваются.

Результаты генерируются отдельно:

- `Assets/AmnesiaImported/Enhanced/<путь текстуры>__*.dds` — карты;
- `Assets/AmnesiaImported/Resources/HplEnhancedMaterials/<путь материала>.mat` — отдельные материалы;
- `Assets/AmnesiaImported/Resources/HplEnhancedTextures.asset` — каталог пар материалов.

При миграции прежние улучшенные материалы перемещаются через AssetDatabase с сохранением GUID.
Повторный импорт обновляет ассеты на месте, сохраняя GUID и ссылки. Каталог дополняется,
а не обнуляется: при добавлении следующих материалов нужно добавлять пары.
Пересобирать игровые карты для этой замены не требуется. Для готового плеера нужна новая сборка.

## PBR и конвенции

Используется **HDRP/Lit**, непрозрачный или alpha-test по оригиналу. Камень — диэлектрик:
metallic = 0, обычный F0 HDRP. Старые HPL specular-карты к новому материалу не примешиваются.

| Карта эксперимента | Назначение в HDRP | Цветовое пространство |
|---|---|---|
| albedo | Base Color RGB; cutout alpha из оригинала | sRGB, BC7 |
| normal_ogl | Normal RG с исправленным G, сила 1 | linear, BC5 |
| roughness R | Mask A = 1 − roughness | linear, BC7 |
| height R | Height, белое = выше, только если используется | linear, BC4 |

Mask R = 0 (metallic), G = 1 (AO отсутствует), B = 1 (маска detail).
Выбор красного канала scalar-карт явный: выходы модели RGB немного различаются по каналам.
Карты до 4096 по большей стороне, Repeat, полная mip-цепочка Kaiser, Trilinear.
Cutout mip-уровни сохраняют alpha coverage на исходном пороге 0.5; базовая alpha перенесена nearest ×4.
Нативный `IHVImageFormatImporter` импортирует уже сжатые DDS без повторного пережатия в Unity.
Сжатие выполняется на GPU экспортёром NVIDIA. BC7 DDS сохраняются с `--save-flip-y`:
это необходимо для совпадения ориентации с проверенным PNG-импортом Unity. Флаг применяется
только к BC7: BC4/BC5 Unity разворачивает сама. Для обновления подготовленных v2 DDS есть
`--upgrade-native-orientation`: перестановка сжатых блоков/индексов без потери качества (NumPy).
Качество и анизотропия продолжают управляться общими графическими настройками.
`EnhancedDdsImportRules` включает streaming mips, отключает CPU-копию, сохраняет действие общего mip limit.
Флаг sRGB задаётся явно через путь `m_sRGBTexture` в `SerializedObject` (им пользуется
пользуется Inspector этой версии Unity): у IHV нет публичного setter, а linear DX10-заголовок
сам по себе не отключает исходный sRGB-флаг импортёра.
В **Графика → Бюджет видеопамяти** доступен список 2 / 4 / 8 / 10 / 12 / 16 ГБ,
по умолчанию 2 ГБ. Выбор сохраняется в глобальном `textureMemoryBudgetGb`, применяется
к `QualitySettings.streamingMipmapsMemoryBudget` при OK; «Отмена» отбрасывает черновик.
Это бюджет потоковой загрузки текстур, а не предел всей графической памяти игры.

**Имя `normal_ogl` в этом эксперименте не соответствует фактическому знаку Y.**
На исходных PNG корреляция `∂height/∂imageX` с normal R = −0.721455,
`∂height/∂imageY` с normal G = −0.727695 (Y изображения направлен вниз).
Для согласования с Y-up tangent normal Unity импортёр разворачивает G ровно один раз
явной инверсией G во временном PNG перед BC5-сжатием (старый PNG-путь — `TextureImporter.flipGreenChannel`).
Height не инвертируется. PNG эксперимента не меняется.
Для первого массового снимка из 32 наборов также проверены градиенты высоты и нормали:
корреляции X −0.893…−0.398, image Y −0.879…−0.390; G разворачивается один раз.
Это решение относится к проверенному выводу NormalV3; для следующего workflow конвенцию
нужно проверять заново, а не выбирать по имени файла.

В workflow SaveTexture выбран `linear`, но сам LoadImage читает байты входного PNG без
декодирования sRGB, а сохранение `linear` записывает их без дополнительной функции переноса.
Поэтому albedo импортируется как sRGB, scalar-карты и нормали — как linear.

Высота используется как **pixel displacement (POM)** с амплитудой 2 см и 8–32 шагами.
Это сдержанный исходный масштаб для предсказанной моделью карты. Геометрия, силуэт,
коллизии и геометрические RT-тени от неё не меняются. POM не является настоящим
displacement для path tracing. RTGI/отражения используют PBR-свойства HDRP/Lit.
Albedo по-прежнему содержит нарисованные тени оригинала; этот эксперимент не выполняет delighting.

В массовом импорте сохраняются исходные emissive-карты, их цвет и интенсивность, UV,
двусторонность и прочие свойства вне заменяемого PBR-набора. Светящиеся непрозрачные
окна остаются светящимися. Дерево получает амплитуду 0.5 см. Физика `Glass` POM не отключает: так помечены и непрозрачные
оконные стены (`castlebase_wall_win` — камень вокруг стёкол, 2026-10-21; прозрачное стекло не Solid и сюда не попадает). У материалов без
исходного Height (в частности `cell_wall_noheight`, `castlebase_wall_windows`) POM отключён. Несколько материалов
с одной albedo используют один комплект новых карт, но отдельные материалы и пары каталога.
У cutout POM отключён, чтобы не сдвигать силуэт вырезов. У металлов сохраняется исходный
Specular Color workflow/F0: PBRify не генерирует metallic-карту, поэтому металл не объявляется
диэлектриком и не получает выдуманную metalness. Меняются albedo, normal и roughness.
Вода, специальные/полупрозрачные материалы, декали, интерфейс и не сгенерированные наборы
остаются классическими. Полный импорт означает все готовые наборы, а не замены отсутствующих ресурсов.
Общие исходники разных режимов не перезаписывают друг друга: например, `sketch_castle`
используется cutout-рисунком и непрозрачным `sketch_roll`; у второго производные карты
получают суффикс `__opaque`. Материалы по-прежнему отдельные.

## Переключение

`HplEnhancedTextures` загружает каталог из Resources. В нём классические ссылки и строковые
Resources-пути улучшенных материалов: новые 4K-карты не загружаются всем пакетом при старте.
Материалы в `Resources/HplEnhancedMaterials` попадают в сборку вместе с зависимыми DDS и
загружаются по запросу для используемых рендереров. Рантайм меняет только `Renderer.sharedMaterials`
при применении настроек и загрузке сцены.
Неактивные объекты также обрабатываются. Исходные материалы не редактируются и `.material`
не вызывается. Неподдерживаемые материалы остаются прежними.

Цветовые копии/клоны непрозрачного HDRP/Lit распознаются по точной ссылке на исходную
albedo, не по имени. Для них создаётся кэшированный улучшенный вариант с исходными tint
и UV scale/offset. Обратная таблица возвращает **точные исходные ссылки**, сохраняя
чужие слоты, null и MaterialPropertyBlock. Выход из Play освобождает временные варианты.
При смене набора сбрасывается накопление path tracing, чтобы неподвижная камера
не продолжала накапливать изображение прежних материалов.

Для объектов, создаваемых после `sceneLoaded`, есть `HplEnhancedTextures.Apply(renderer,
HplGraphics.Textures == 1)`. Это вызывается для новых рук/фонаря и объектов `CreateEntity`.
Обход учитывает неактивные и DontDestroyOnLoad рендереры. Затухание модели следует текущему
набору и возвращает точный актуальный материал. На смене карты кэш отпускается, неиспользуемые
ресурсы выгружаются; возврат к классике также отпускает новые материалы.

## Проверки

- `RTXMnesia.EditorDev.EnhancedTextureTests.RunBatch` (`-batchmode -nographics -quit`):
  повторный импорт и GUID; SHA256 классических материалов, карт и meta; настройки PBR;
  меню/JSON; пять циклов переключения; tint/UV/null/чужие слоты/MaterialPropertyBlock;
  все рендереры обеих первых карт и точное восстановление ссылок.
- `RunRenderBatch` (`-batchmode -quit`, GPU): освещение атласа, classic/enhanced/restored,
  сравнение пикселей и снимки первой карты. Не сохраняет сцены.
- `RunPlayBatch` (`-batchmode`, **без `-quit`**): применение через настоящее событие настроек,
  загрузка второй карты с выбранными улучшенными текстурами, возврат к классике.
  Временно подставляет выбор в PlayerPrefs для загрузки карты и восстанавливает точное исходное
  значение в `finally`; файлы профиля не меняет. Процесс сам завершает работу.
- `RTXMnesia.EditorDev.BuildCheck.RunBatch`: компиляция скриптов Windows-плеера и obsolete API.
- `RunFullBatch` / `RunReadyBatch` (`-batchmode -nographics -quit -enhancedResults <txt>`):
  импорт фиксированного полного снимка, GUID и SHA256 всех классических зависимостей,
  свойства emission/UV/culling/alpha, нативные форматы и streaming всех карт, отсутствие
  прямых новых ссылок в каталоге и обратимое переключение всех импортированных игровых сцен.
  `-enhancedAuditOnly` проверяет уже импортированный снимок и обновляет настройки DDS без
  повторной конвертации исходников; перед этим полный `ConvertReadyBatch` должен завершиться успешно.
- `EnhancedCompressionProbe.RunGpuBatch`: сравнение DDS на GPU с проверенным PNG
  по цвету и вертикальной ориентации.

Отчёты и PNG: `UnityProj/UMnesiaRTX/Logs/EnhancedTextureCheck/`, логи batch-запусков в `Logs/`.
