# DLSS, улучшенное освещение, трассировка лучей

> Вынесено из CLAUDE.md (2026-10-25) без изменений текста; перекрёстные ссылки «см. «Раздел»» ищи по заголовкам в `docs/Reference/`. Индекс — в CLAUDE.md.

**DLSS и вкладка «Изображение»** (2026-10-18, вкладка с 2026-10-21 вместо «RTX») — `Hpl/HplDlss.cs`, вкладка «Изображение» (`HplPauseMenu.ImageTabItems`, списки `ImageMethod` / `DlssPreset` в `HplGraphicsOptions`), поля `dlssMode` / `dlssPreset` в `HplUserSettings` (общие, PlayerPrefs).
- Модуль `com.unity.modules.nvidia` (встроенный DLSS HDRP: только Super Resolution / DLAA; Frame Generation и Ray Reconstruction в Unity нет). Ассет HDRP (`ConfigureHDRP` задаёт то же): динамическое разрешение включено (Hardware), единственный апскейлер — DLSS, оптимальные настройки, резкость 0, mip bias. Камера использует DLSS, только пока разрешает динамическое разрешение: `HplDlss.ConfigureCamera` в `beginContextRendering` (через `HplGraphics`) включает его игровым камерам (кроме зеркал воды) и ставит им AA None — DLSS сам делает временное сглаживание.
- Режимы: выкл / DLAA (без масштабирования) / Качество / Баланс / Производительность / Макс. производительность (на 1920×1080 рендер 1920 / 1344 / 1152 / 960 / 672 — HDRP округляет 0.667 до 0.70). Модель: «Авто» или пресет NVIDIA (F — CNN, J / K — трансформер, L / M — трансформер 2); недоступные режиму (`GetAvailableDLSSPresetsForQuality`; на RTX 5080: DLAA F J K, Качество / Баланс J K, Производительность J K M, Макс. F J K L) серые, при смене режима неподходящая модель сбрасывается в «Авто». Пресеты в HDRP — на проект: `HplDlss` пишет их в поле `m_RenderPipelineSettings` ассета в памяти (сеттер вызывал бы OnValidate и пересоздание пайплайна), в редакторе при выходе из Play возвращает прежние — в ассет не сохраняются.
- Вкладка: слева DLSS, модель (серая при выключенном DLSS), строка «Рендер W x H / Вывод W x H» последней камеры DLSS или причина недоступности; справа «Трассировка лучей» — подсказка включить освещение «Трассировка лучей» / недоступна без DXR / настройки появятся позже. Многострочный текст — `DrawLines` (GUI-текст рисует одну строку).
- После апскейла: проход `HplScreenEffectsPass` (AfterPostProcess) работает в выходном разрешении — его буферы без dynamic scale, радиальное размытие и снимок меню берут `camera.pixelWidth`, а не `actualWidth`. Проходы до апскейла (box-свет, туман областей, контур / мерцание, вода, ореолы) читают пиксели по `_ScreenSize` рендера и не менялись. Не перенесено: маски реактивности для полупрозрачных (частицы, ореолы, Mul-декали без векторов движения — возможен лёгкий шлейф).
- Проверка: `RTXMnesia.EditorDev.DlssPreview.RunBatch` (без -quit/-nographics, нужна RTX; `-amnesiaMap`, `-playView`, `-dlssSize 1920x1080`) — 21 условие: DLSS обнаружен, работает на камере только в выбранных режимах, масштаб рендера, AA камеры заменён, модель записана в пайплайн, эффекты (сепия, размытие, след) после апскейла, возврат настроек; снимки и отчёт — `Logs/DlssCheck`. В `MenuPreview.RunBatch` — вкладка «Изображение»: список «Метод» и модель, выбор «Производительность», применение (камера рендерит ниже выходного размера), «DLSS» в сглаживании, снимки `Options_RTX_*.png`, `Options_1_DlssAA.png`.
- Frame Generation: во встроенном модуле Unity нет (HDRP в режиме поддержки, новых функций не будет). Возможные пути: NVIDIA Smooth Motion драйвера (RTX 50, без интеграции) или свой нативный плагин Streamline (DX12, Reflex, перехват swap chain, HUD-less цвет — HUD и меню сейчас Screen Space Overlay поверх кадра) — отдельная задача.

**Улучшенное освещение** (2026-10-21, решение пользователя: классику не трогать, постановку света менять в отдельном режиме) — `World/HplEnhancedLighting.cs`, настройка «Освещение: Улучшенное» вкладки «Графика» (`HplUserSettings.lightingSet` = 1, `HplGraphics.Lighting`; не путать с `lighting` — переключателем трассировки).
- Инструкция по постановке света на картах (что делает код сам, формат оверлея, правила, порядок прохода, эталонные значения) — `docs/EnhancedLighting/README.md`, журнал карт — `docs/EnhancedLighting/maps.md`, задание для агента — `docs/EnhancedLighting/agent-task.md`. Список света карты — `python tools/List-MapLights.py <карта>.map [--box xmin zmin xmax zmax]`, рендеры — `tools/Run-EnhancedLightingPreview.ps1` (обёртка над `EnhancedLightingPreview`, сверяет ProjectSettings).
- Оверлей карты — наши данные в git: `Assets/Resources/HplEnhancedLighting/<путь .map без расширения>.json`. `lights` меняют свет карты по имени (`intensity` — множитель, 0 — не рисуется; `range`; `position` / `target` — перенос и поворот; `shadows` on / off — off: заполняющий свет без теней, и без RT-теней «от всех источников»; `sourceRadius` — мягкость RT-тени; `specular` off — без блика, у добавленных `rect` по умолчанию: у всех источников окон и проёмов, иначе при гладкости камня ~0.5 откосы ниш и подоконники сверкали белым), `add` добавляет источники (`point` / `spot` / `rect`; кандела, у `rect` — ниты; `size`, `angle`, `color`, `follow` — следовать яркости и видимости света карты: лампа зажжена / потушена, мерцание). Координаты — как в `.map` (HPL2), значения — строки, пустое — без изменений. `when`: `rt` / `raster` / `gi` / `nogi` (ограничение записи режимом трассировки или отражённым светом: `gi` — RTGI или SSGI, `nogi` — ни того, ни другого); `note` — пояснение. Почему каждая правка — в `note`.
- Общие правила для всех карт (до оверлея карты, `ApplyRules`): у ламп (`EntityType="Lamp"`) HPL2 ставит источник не в пламя (свеча `candlestick01` — 0.4 м вбок, факел `torch_static01` — 1.64 м от стены в комнату, настенный подсвечник — 1.26 м, люстры — 0.5–1.6 м; так стена не пересвечивалась и комната освещалась ровно) — с физическим спадом и тенями свет шёл из пустоты. В улучшенном источник переносится в пламя (системы частиц огня `.ent`; у люстры — в центр пламён), яркость физическая — по числу пламён в «свечах» (`CandleCandela` = 15 кд — классическая свеча у самого огня; факел 10, печь / костёр 20, прочий огонь 3, фонарь в руке `LanternCandles` = 10; яркость делится между светами лампы, затухание и мерцание её масштабируют, радиус HPL2 — нет, `AmnesiaLight.enhancedCandela`), дальность — до освещённости `VisibleLux` = 0.25 лк (не больше 25 м: свеча 7.75 м вместо 1.7, факел 24.5 вместо 3.4), мягкость RT-тени — размер пламени по файлу частиц (свеча 1.2 см, факел 6 см, печь 15 см) или разброс пламён люстры (до 0.5 м), лампы всегда с тенями (карта теней низкого разрешения, RT при свободном слоте). Свет ставится в тело пламени, а не в начало частиц (факел и печь +15 см, свеча +1.5 см: иначе он сидел в чаше факела). Сама модель лампы тень не отбрасывает. У ламп `ShadowNormalBias` = 4, slope 0, ближняя плоскость 2 см: стены HPL2 — две рельефные половины спина к спине, швы обеих сторон в одной плоскости, и факел за стеной светил по швам соседней комнаты (растр; RT не затронут). Вся геометрия карты в улучшенном отбрасывает тень обеими сторонами граней. С улучшенными текстурами стена между комнатами — два модуля рельефа спина к спине в одной плоскости, а швы утоплены на 2 см: швы одной стороны выходили сквозь камни другой в соседнюю комнату, и её факел светил по ним (оранжевые трещины в тёмной комнате, с RT особенно; растр и RT). `HplEnhancedRelief.SeparateSharedWalls` (после применения текстур к сценам) находит такие пары (противоположные нормали, одна плоскость, пересечение) и сдвигает рендерер каждого модуля в свою комнату на глубину шва + 4 мм, вместе с декалями карты на нём (сборщик сцен снимает с этих декалей статический батчинг); коллизии не меняются, классика возвращает позиции. Проба: режим `walls` — границы модулей стены у цели, `nolift` — без сдвига, в строке отчёта `shared walls separated / decals`. Воск свечей светится (`SplitWax`): воск находится по форме меша (от фитиля вниз до расширения подсвечника) и становится отдельным рендерером с полупрозрачным материалом воска (thin object, без эмиссии HPL2 — иначе воск потушенных люстр светился; профиль `Resources/HplEnhancedLighting/CandleWax.asset`). Материалы воска — готовые ассеты в игнорируемом `AmnesiaImported/Resources/HplCandleWax/` (`<материал>` и `<материал> enhanced` для каждого материала моделей `Models/entities/lamp`; `Editor/EnsureCandleWaxProfile.cs`: при загрузке редактора, если папки нет, перед каждой сборкой, меню Tools > RTXMnesia > Build candle wax materials, batch `RunBatch`): пропускание HDRP/Lit — shader_feature, и материал, созданный в игре, в билде рисовался без него (в редакторе работало). Без готового материала — копия в игре и `PortError` в билде; проба пишет `not generated N` на слое освещения `HplLighting.WaxRenderingLayer` (6). Внутри воска, 1.5 см под фитилём, — свет без теней только для этого слоя, `WaxGlowShare` = 2% пламени, следует за светом лампы (зажжена, потушена, мерцание): RT-тени HDRP считают обращённую от света поверхность затенённой, и само пламя сквозь воск с ними не светит. Свет самой карты (не сущности) без CastShadows — заполняющий: без теней, и «тени от всех источников» его не трассируют, слоты RT остаются настоящим источникам. Общие правила действуют и на картах без оверлея (пустой оверлей; до 2026-10-24 такая карта оставалась классической). Светящиеся материалы освещают окружение через RTGI (`World/HplEnhancedEmission.cs`, только при RTGI): эмиссия HPL2 — экранное значение (белое ≈ 9.6 нит), поднять её нельзя — цветное свечение выгорело бы в белое без тонмаппинга; поэтому у рендереров материалов таблицы `Resources/HplEnhancedLighting/Emitters.json` (имя классического `.mat` → `gain`: грибы, сферы, монолиты, машина барьера, камни эмоций, фонари колонн хора; окон и ламп нет) — невидимая копия на слое 28 (`HplRayTracing.GiOnlyLayer`: камеры, RTAO, RT-отражения и path tracing его исключают), без теней, эмиссия × gain, меш выдвинут на 3 мм по нормалям; копия следует за видимостью и материалами оригинала, статически батченные пропускаются. Карты теней улучшенного освещения (`World/HplEnhancedShadows.cs`, флажки «Мягкие тени (PCSS)» и «Контактные тени» вкладки «Графика», по умолчанию вкл, только при улучшенном освещении и включённых тенях): PCSS — фильтрация теней HDRP «High» (глобальное ключевое слово шейдеров + поле ассета в памяти, в редакторе возвращается при выходе из Play), размер источника — `sourceRadius` / пламя, иначе 4 см, прямоугольные не меняются; классика остаётся на «Medium». Сборка оставляет только варианты фильтрации своих ассетов HDRP, поэтому варианты PCSS приносит `Assets/Settings/HDRP_PcssVariants.asset` — копия ассета с «High» и меткой `HDRP:IncludeInBuild` (её включают глобальные настройки HDRP), никуда не назначена; её синхронизирует `Assets/Editor/EnsurePcssVariants.cs` (загрузка редактора, перед сборкой, меню Tools > RTXMnesia > Update PCSS variants asset). Контактные тени (Volume, 15 см) — только у источников вне модели сущности: модель лампы не отбрасывает ни карту теней, ни RT-тень, а экранный луч её видит (факел темнел). Флажок «Тень фонаря» (по умолчанию вкл): основной источник фонаря в руке получает карту теней среднего разрешения (`HplEnhancedLighting.HandLight`, пламя 1.5 см — и для RT-тени фонаря); при трассировке фонаря — RT-тень. Проба: `nopcss`, `nocontact`, `nolanternshadow`. Список «Отражённый свет (SSGI)» той же вкладки (выкл / низкое / среднее / высокое, по умолчанию «Среднее»; поле `ssgi`): экранный GI HDRP — тот же компонент `GlobalIllumination`, что у RTGI, но лучи идут по буферу глубины (`HplRayTracing.ScreenGi`, только при улучшенном освещении и без RTGI; при RTGI список серый). Свой уровень качества: 32 / 48 / 64 шага, «высокое» — полное разрешение. Он заменяет заполняющий свет так же, как RTGI (записи `gi` / `nogi` оверлеев): на `01_old_archives` растр с SSGI без заполняющего света по средней яркости совпал с RTGI (печь 14.6 / 15.1, вид от окон 14.3 / 14.2, зал 19.1 / 17.8, коридор 21.7 / 20.8), с половиной заполняющего — светлее на 2–4; прибавка самого SSGI мала (2–3%, как у RTGI), стоимость в редакторе 0.8–2 мс (RTX 5080, 1080p). Проба: `ssgi` (`ssgi1` / `ssgi3` — низкое / высокое). Флажок «Кэш теней» (по умолчанию вкл; поле `shadowCache`; `World/HplShadowCache.cs`): неподвижный источник рисует карту теней один раз в кэшированный атлас HDRP (`ShadowUpdateMode.OnDemand`, атлас 8192², `ConfigureHDRP`) и перерисовывает её, только когда в его радиусе сдвинулся больше чем на 2 мм, появился или пропал рендерер сущности карты (пропы, двери, враги, критеры, NPC, созданные скриптом, копии растворения), сдвинулся сам источник или изменился его радиус; после смены текстур и разведения стен (`SeparateSharedWalls`) перерисовываются все. Фонарь в руке и прямоугольные источники — каждый кадр. Атлас вмещает ~150 ламп по 256 или ~40 по 512 (точечный источник — шесть карт), меньше, чем на карте: места раз в 0.5 с получают ближайшие к камере источники, остальные рисуются каждый кадр (вне кадра это ничего не стоит). На `01_old_archives` картинка с кэшем совпадает с картинкой без него в пределах шума частиц, перерисовок в зале с факелами 0–4 за 40 кадров; выигрыш по времени кадра в редакторе — в пределах шума (до 1.5 мс). Проба: `nocache`, `moved` (на середине прогона ближайшая к цели модель сущности сдвигается на 0.4 м), `again` (повтор режима для оценки шума); в отчёте — число кэшированных источников, перерисовок, что двигалось и попиксельная разница. Предел карт теней в кадр (2026-10-25): у ламп улучшенного освещения тени всегда и дальность до 25 м, и вид зала `00_rainy_hall` требовал до ~260 карт, а HDRP выделяет не больше `maxShadowRequests` (было 128) и молча отбрасывает остальные: источник без карты светил сквозь стены, а какие отбрасывались — менялось от кадра к кадру («стробоскоп» у печи, в коридорах и кладовой; в классике 30–95 карт). Теперь `ConfigureHDRP.ShadowRequests` = 1024 (с 2026-10-27; 512 — 2026-10-25), кэш-атлас 8192², атлас карт теней сам уменьшает их, если не помещаются; на видах зала, печи и верхнего яруса HDRP выделяет 136–171 карт, кэшировано 56 источников, время кадра не выросло. Самая плотная карта — `ptest/03_dungeon` (124 лампы с тенями, в основном свечи): до 472 карт. Проба: режим `scan` вместо видов (`-Views scan`) — под каждой лампой четыре направления взгляда, оценка нужных карт по пирамиде видимости (завышает: HDRP отсекает точнее), затем пять самых плотных мест 4 с неподвижной камерой — сколько HDRP выделил, сколько раз сменился набор RT, скачок средней яркости; итог в `<карта>_scan.txt`. Скачки яркости в `scan` бывают от самой пробы: игрок, поставленный под лампой, застревает в геометрии и камеру дёргает (`03_archives`, `04_final`) — проверять режимом `frames` (кадры 60–62 серии в PNG). Прогон всех 37 карт 2026-10-26: предел нигде не достигнут. В отчёте пробы — строка `shadow budget` (источники с тенями в кадре, нужные карты, сколько HDRP выделил из предела).
- `HplMap.Build` (Play) вызывает `Attach`; `HplGraphics.Apply` — `Refresh` (снять и наложить заново: классика ↔ улучшенное и смена RT без перезагрузки). Изменённый свет хранит прежние значения и возвращается; добавленные — под «Enhanced lights» карты, не сохраняются. Логика игры видит классику: `AmnesiaLight.LightLevelAt` пропускает добавленные и меряет перенесённые из их локальной позы карты (`classicLocalPose`, следует за качающимся родителем), множитель яркости на неё не влияет.
- Проверка: `RTXMnesia.EditorDev.EnhancedLightingPreview.RunBatch` (без -quit/-nographics; `-amnesiaMap`, `-lightViews "имя:ноги_x y z цель_x y z;…"` в координатах HPL2, `-lightModes classic_raster,classic_rt,enhanced_raster,enhanced_rt`, в режиме `lantern` — фонарь в руке, `noshadow` — без его RT-теней, `only` — весь свет выключен, кроме зажжённых ламп `-lightLit` и фонаря, `nofill` — без заполняющего света, `tex` — улучшенные текстуры, `mats` — материалы у цели вида, `noemit` / `emitx` — без копий светящихся материалов / их gain × 30, `_pt` — path tracing 64 сэмпла; мерцание выключается; у вида свой список после `|`; `-lightLit лампа,…` — зажечь лампы; `-lightSize`) → `Logs/EnhancedLighting/<карта>_<вид>_<режим>.png` и отчёт: источники у каждого вида (тип, яркость, тени, трассируется ли, радиус источника).
- Готово: `01_old_archives` — комната с печью (окна — прямоугольные источники и лунный луч от стекла; заполняющий свет в центре без теней, при RTGI выключен) и зал с факелами (тёплый заполняющий `LightOff_1…4` при RTGI выключен, без GI — 0.6). **Трассировка лучей** (2026-10-18; с 2026-10-21 не вид освещения, а отдельный переключатель — решение пользователя: «улучшенное освещение будет другим») — `Hpl/HplRayTracing.cs`; переключатель «Трассировка лучей» (вкладка «Трассировка», поле `lighting` = 1, только при `SystemInfo.supportsRayTracing`) включает DXR, настройки эффектов — на той же вкладке (серые, пока она выключена; все новые RT-настройки добавлять туда же).
- Ассет HDRP (`ConfigureHDRP` задаёт то же): `supportRayTracing`, экранные тени (`supportScreenSpaceShadows`), 16 слотов экранных теней. Камеры: `HplRayTracing.ConfigureCamera` в `beginContextRendering` (через `HplGraphics`) переопределяет frame settings RayTracing / ScreenSpaceShadows игровых камер (зеркала воды никогда не трассируют). При классическом освещении лучи не идут.
- RT-тени (`rtShadows` в `HplUserSettings`: выкл / низкое / среднее / высокое / ультра = до 4 / 8 / 12 / 16 источников, 1 / 1 / 2 / 4 луча на пиксель, по умолчанию «Среднее»): каждый кадр источники карты с тенями сортируются по тому, насколько их тени видны в кадре (анализ источников `World/HplLightAnalysis.cs`, с 2026-10-24 вместо расстояния от камеры: сетка 16 × 9 лучей из камеры находит видимые поверхности, в каждой точке — освещённость каждого источника (кандела / ниты HDRP-света, 1/d², окно радиуса HDRP, конус, N·L; box-свет — своей постоянной освещённостью), если луч от точки доходит до него (стена между комнатами закрывает, своя лампа — нет); источник считается в точке, где даёт не меньше 15% её света, точки взвешены по яркости — получается примерно доля экрана, где видна его тень; оценка раз в 0.2 с со сдвигом сетки и сглаживанием, лучи — пачкой `RaycastCommand`, 0.6–0.7 мс основного потока на оценку; источник, чья тень не видна нигде, RT-тень не получает, даже если слоты остались; уже трассируемые получают запас ×1.25, чтобы не переключались, и держат слот 6.4 с — два полных цикла 16 смещений сетки — после того, как их важность в последний раз дошла до порога (даже если упала до нуля): комнату, видную издалека в узкую дверь, сетка задевает лишь на части смещений, и её источники каждые несколько кадров переходили между RT-тенью и картой теней — свет комнаты с печью `00_rainy_hall` то появлялся, то исчезал (2026-10-25); слоты делятся по важности, сглаженной за 3.2 с (`RankTime`; источник, которого в кадре нет совсем, теряет её сразу): одна оценка дальнего источника меняется вчетверо от смещения сетки, и при занятых слотах дальняя свеча `09_back_hall` и свет окна менялись местами каждые полсекунды (2026-10-27); проба: режим `series` — 120 кадров неподвижной камеры, средняя яркость и смена трассируемых, `series-<часть имени>` — ещё и важность / состояние этих источников, в строке — занято слотов из кандидатов; `frames` — кадры 60–62 в PNG), самым заметным ставится `useRayTracedShadows`, денойзер и `Light.shapeRadius` = 4 см (мягкость; у HPL2 размера источника нет), остальные остаются на картах теней; при выключении радиус возвращается. Настройка «Тени: выкл» на «Графике» выключает и RT-тени. Выбор источников сбрасывается в `Apply`, иначе смена настроек в том же кадре не действовала.
- Тени от всех источников (`rtAllShadows`, по умолчанию вкл, недоступно при выключенных RT-тенях) — в выбор RT-теней входят и источники без `CastShadows` (большинство свечей; на стартовом виде `00_rainy_hall` 11 → 53 источника в кадре). Пока такой источник трассируется, у него включены тени с картой минимального разрешения и обновлением по запросу (`ShadowUpdateMode.OnDemand`): HDRP рисует карту теней и для RT-источников, так она рисуется один раз; выпав из выбора, источник снова без теней. Свет в руке, box-свет и свет темноты игрока в общий выбор не входят. Настройка «Тени: выкл» на «Графике» выключает и их.
- Тени от фонаря (`rtLanternShadows`, по умолчанию вкл): источники предмета в руке (`AmnesiaLight.handHeld`, ставит `PlayerHands.CreateHandLight`; у фонаря их два) трассируются всегда, пока горят, вне общего числа: общий выбор получает min(уровень, 16 − источников в руке) слотов. Руки и модель фонаря теней не отбрасывают (`HandsConverter`), копия света для рук — без теней. Руки и предмет в руке — на слое 27 (`HplRayTracing.HandsLayer`), его исключает маска RTGI: свет фонаря в нескольких сантиметрах от его модели и кисти, лучи GI пикселей руки сразу попадали в них, и руки с фонарём светились оранжевым (средняя яркость кадра 31 против 20 без RTGI, после — 19); из структуры лучей они не убраны — path tracing рисует только её.
- RTAO (`rtAo`: выкл / низкое / среднее / высокое = уровни качества RTAO HDRP 0–2, по умолчанию «Среднее»): компонент `ScreenSpaceAmbientOcclusion` (rayTracing) в глобальном Volume настроек (`HplRayTracing.ApplyVolume` из `HplGraphics.ApplyVolume`), при классике он неактивен. HDRP применяет AO только к непрямому свету, которого в картах HPL2 нет, поэтому `directLightingStrength` = 0.35 (затенение и прямого света ламп), а box-свет умножается на AO кадра (`_HplBoxAo` из `HplBoxLightPass`, текстура `_AmbientOcclusionTexture`, которую HDRP оставляет глобальной после проходов освещения) — как SSAO у box-света HPL2.
- RT-отражения (`rtReflections`: выкл / низкое / среднее / высокое, по умолчанию «Среднее»): компонент `ScreenSpaceReflection` с трассировкой лучей (режим Performance, своё качество вместо уровней ассета: минимальная гладкость 0.55 / 0.45 / 0.35, начало затухания + 0.1, длина луча 10 / 25 / 50 м, «низкое» — половинное разрешение, денойзер). Гладкость материалов HPL2 после пересчёта спекулярной карты 0.3–0.6, а порог HDRP по умолчанию 0.9 не отражал бы ничего. Ассет поддерживает SSR (`supportSSR`) только ради этих отражений: frame setting SSR включается лишь у камер с RT-отражениями, классика и зеркала воды без SSR. В отражениях нет box-света, тумана и полупрозрачных (свои шейдеры); вода отражает по-прежнему своей камерой-зеркалом.
- RTGI (`rtGi`: выкл / низкое / среднее / высокое, по умолчанию «Среднее» — ремастер): компонент `GlobalIllumination` с трассировкой лучей (Performance, своё качество: длина луча 50 м, денойзер; «низкое» — половинное разрешение и половинный денойзер, «среднее» — половинное разрешение и второй проход денойзера, «высокое» — полное разрешение). Ассет поддерживает SSGI (`supportSSGI`) ради него и экранного GI улучшенного освещения: frame setting SSGI — лишь у камер с RTGI или с SSGI вкладки «Графика». Свет в точках попадания лучей (отражения, GI) берётся из кластера источников: `LightCluster.cameraClusterRange` = 40 м (у HDRP 10), до 16 источников на ячейку (`maxLightsPerClusterCell`, предел HDRP 24). Отражённый свет дают только HDRP-источники и эмиссия; box-свет (custom pass) не отражается. На стартовых видах `00` / `01` прибавка средней яркости 2–3%.
- Path tracing (`rtPathTracing`: выкл / 64 / 256 / 1024 сэмпла, по умолчанию выкл; секция «Режимы» вкладки «Трассировка», только при включённой трассировке): компонент `PathTracing` HDRP (глубина 4, предел яркости 10, денойзер OptiX пакета `com.unity.rendering.denoising` 1.0.5 по окончании накопления, асинхронно). HDRP копит по сэмплу за кадр игрового цикла и начинает заново при любом изменении: камера, трансформы объектов в структуре лучей (критеры, физика), CRC материалов. Поэтому кадр чистый только пока всё стоит; полоса внизу — индикатор накопления HDRP. В path tracing нет custom pass: box-света (в улучшенном освещении `01_old_archives` его заменяют окна, на остальных картах он пропадает), тумана мира и областей. Чтобы стоящий игрок не сбрасывал накопление, камера (`AmnesiaPlayer.UpdateCameraTransform`: положение, поворот, FOV, aspect), руки (`PlayerHands.UpdateTransform`) и свет темноты (`PlayerDarkness`) пишутся только при изменении больше 0.1 мм / 0.001°, эмиссия пропов (`HplProp.SetIlluminationAmount`) — только при новом значении.
- Структура лучей без поддельных эффектов: рендереры шейдеров `RTXMnesia/*` (частицы, ореолы, Mul-декали, вода) и меш-декали (`DBufferMesh`) получают `rayTracingMode = Off` (`HplRayTracing.Exclude` при загрузке сцены и при сборке карты `HplMap.Build` — карта, открытая в редакторе до Play, не «загружается», и её Mul-декали грязи path tracer рисовал чёрными многоугольниками на полу; частицы и билборды — при создании, билборды всегда). Без этого path tracer рисовал их чёрными, а билборды, меняющие цвет каждый шаг, сбрасывали накопление. Так же исключаются плоские прозрачные меши тоньше 2 см в собственных осях меша (`FlatTransparentThickness`: следы крови `trail_amnesia_floor` в сантиметре над полом; наклонённый на 2° и растянутый вдвое след в мировых осях толщиной 7 см). Статические объекты Unity склеивает (static batching), и склеенный рендерер своего меша уже не знает, поэтому решение принимается до склейки: `Editor/RayTracingExclusionProcessor.cs` вызывает `Exclude` для копии каждой сцены при сборке и входе в Play: лучи считали полосу сплошной, и её RT-тень и RTAO рисовали под кровью чёрный квадрат.
- Генерация кадров: во встроенном HDRP нет ни DLSS-G, ни FSR 3 FG. Решение пользователя — NVIDIA Smooth Motion (драйвер, RTX 40/50): включается вручную в NVIDIA App для `UMnesiaRTX.exe` (API NVIDIA App его не переключает, сборки в списке приложений нет), на вкладке «Изображение» — примечание. Свой плагин Streamline DLSS-G — отдельная большая задача.
- Сравнение графики (`Effects/HplRtxCompare.cs`, 2026-10-28): C переключает трассировку лучей (`lighting`, только при DXR), L — классическое / улучшенное освещение (`lightingSet`), T — классические / улучшенные текстуры (`textures`). Все три действия переназначаются в «Управление → Конфигурация клавиш → Разное» (основной и дополнительный ввод, сохранение в профиле); L и T работают и без DXR. Во время паузы, загрузки, титульного экрана и ввода в сторонней панели переключение не запускается. Кадр сохраняется (`HplScreenEffectsPass`, проход «Raw copy» до эффектов HPL), на следующем обновлении меняется только выбранная настройка, применяется и сохраняется; окно настроек показывает новое состояние. За 0.9 с наклонная линия (белая, с зелёным свечением) проходит слева направо: слева новый живой кадр, справа сохранённый (проход «Compare wipe»); слева вверху HUD — название нового режима (русский / английский). Повторный ввод во время сравнения игнорируется. Подсказки с фактически назначенными клавишами — у освещения и текстур на вкладке «Графика», у трассировки — на вкладке «Трассировка».
