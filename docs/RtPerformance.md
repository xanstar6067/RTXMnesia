# Производительность трассировки лучей (задача 08, 2026-11-05)

Исследование по отчётам F1 от 2026-11-02 (`docs/tasks/bug_08_rt_performance.md`): RTX 5080, вывод 2560×1440, HDR,
улучшенные свет и текстуры, RT: тени «Ультра», AO «Высокое», отражения «Среднее», GI «Высокое».
В зале `00_rainy_hall` было 35 FPS при DLSS «Производительность» (рендер 1280×720) и 44.5 FPS при «Качестве»
(1792×1008); у двери в начале зала — 103 FPS.

Исправлений кода нет, только замер. Решение об изменениях — за пользователем.

## Лучи теней по размеру источника и свой уровень RTAO (2026-11-11) — исправлено

Жалоба: с настройками «тени Ультра, RTAO Высокое, отражения Среднее, RTGI Высокое» на RTX 5080 при 1440p
режим DLSS почти не меняет FPS.

**Замер до правки** (тестовый плеер, HDR, отчёты `Logs/RtPlayer/*_2026-11-11_report.txt`), FPS:

| Место | Макс. произв. | Произв. | Баланс (1536×865) | Качество | Баланс, RT по умолчанию |
|---|---|---|---|---|---|
| Зал a2026 | 84 | 71 | 61 | 49 | 98 |
| Зал b2122 | 92 | 73 | 57 | 46 | 88 |
| Хор, старт | 68 | 58 | 53 | 47 | 71 |
| Хор, r22 | 86 | 81 | 72 | 59 | 97 |

**Причина.**
- HDRP считает RT-тень каждого источника отдельно: запуск лучей на каждый сэмпл и свой денойзер, всё на
  полный экран (`HDRenderPipeline.ScreenSpaceShadowsPunctual.cs`).
- Каждый запуск лучей стоит потоку рендера 0.2–0.3 мс. При «Ультра» (4 сэмпла) и 6–7 источниках это
  24–28 запусков из ~30 в кадре: поток рендера занят 10–12 мс при любом разрешении рендера.
- RTAO «Высокое» было уровнем 2 HDRP: 8 лучей по 20 м на пиксель.
- Поправка к разделу «Причины (по плееру)» ниже: «общие ~5 мс трассировки» завышены. Вариант «без RTGI»
  включал SSGI, поэтому почти ничего не экономил; с выключенным SSGI полное RTGI стоит 1.5–3 мс.

**Исправление** (`HplRayTracing`).
- `SamplesFor`: лучи источника — по его радиусу, не больше числа уровня. До 8 см (свеча, факел, обычный
  свет карты) — 1, до 20 см (печь, костёр) — 2, больше (люстры) — число уровня. Прямоугольные — число уровня.
- RTAO «Высокое» — своё качество: 4 луча, 8 м (`AoHighSamples`, `AoHighRayLength`).

## Хор `24_torture_choir_east` и отсечение структуры лучей (2026-11-08) — исправлено

Жалоба: при первом входе на карту, пока звучит голос Александра, около 35 FPS, при ходьбе 40–50.
Тестовый плеер (2560×1440, DLSS «Производительность», набор отчётов) подтвердил 27–34 FPS на старте:
GPU 30–37 мс, поток рендера CPU 25–31 мс.

**Голос и флешбэк ни при чём.**
- Флешбэк у колеса и вспышка эмоции стоят столько же, сколько само место: с растром — те же FPS.
- Медленное движение и взгляд на старте — замысел оригинала: `OnStart` ставит скорость движения 0.2, бег 0,
  взгляд 0.2 и радиальное размытие, а `TimerPipeEvent` возвращает их по шагам 0.4 → 0.6 → 0.8 → 1.0.

**Причина.**
- Структура лучей HDRP по умолчанию отсекает объекты расширенной пирамидой глубиной в дальнюю плоскость
  камеры, то есть держит почти всю карту. Хор — около 130 м.
- Цена каждого прохода лучей (тени каждого трассируемого источника, AO, GI, отражения) растёт с размером
  структуры — и на GPU, и в потоке рендера CPU.
- Поэтому в хоре один трассируемый источник стоил до ~5 мс, а в зале `00_rainy_hall` — ~1.7.

**Исправление.**
- `HplRayTracing.StructureRadius` = 50 м: компонент `RayTracingSettings` в общем Volume настроек, режим
  отсечения `Sphere` (`HplRayTracing.ApplyVolume`).
- 50 м — длина лучей RTGI и больше дальности кластера источников (40 м).
- При path tracing отсечение выключено: path tracer рисует саму структуру, и дальние стены пропали бы.

## Причины (по плееру)

1. **Общая цена трассировки ~5 мс GPU** — появляется, как только включён хоть один RT-эффект.
   - Все эффекты выкл — 4.7 мс, только RT-тени выкл (AO, отражения, GI вкл) — 9.9 мс.
   - Выключение каждого эффекта по одному даёт лишь 0–2 мс: цена не складывается из эффектов.
     Это общая подготовка: кластер источников для лучей, структура лучей для эффектов, свет в точках попадания.
   - Подробнее без отладочной сборки или Nsight не разложить.
2. **RT-тени: GPU и CPU.**
   - GPU: тени «Ультра» +3–4.6 мс к «выкл» при 720p, +6–7 мс при «Качестве».
   - Поток рендера CPU: ~1 мс на каждый трассируемый источник (a2026: 3.6 → 11.3 мс при 7 источниках).
     При «Производительности» он почти догоняет GPU (11.3 против 12.9).
   - «Высокое» вместо «Ультра» снимает 2.5–3 мс CPU и 1.5–3 мс GPU, а FPS «Производительности» почти
     не меняется (упор в CPU и общую часть). При «Качестве» — +10–16%.
3. **Разница между местами** — число трассируемых источников в кадре (1 у двери, 6–7 в зале).
4. **Карты теней (150–340) и видеопамять** — не узкие места.

## Причины (по редактору, 2026-11-05; разбивка по проходам)

1. **Главная — RT-тени «Ультра».**
   - Стоят 8–11 мс при 720p и 14 мс при 1008p, хотя источников в кадре всего 5–6 и слоты (16) не заполнены.
   - Цена на источник — ~1.7–1.9 мс при 720p.
   - Из неё на сами лучи (4 на пиксель) приходится половина.
   - Вторая половина — денойзер: HDRP фильтрует каждый источник отдельно, ~0.75 мс на источник при 1008p.
     Эта часть не зависит от числа лучей.
   - Ещё около 4–5 мс разницы кадра не попадают ни в один маркер `HDProfileId`. Есть только при
     включённых RT-тенях.
2. **Разница между местами — число трассируемых источников в кадре, а не карта.**
   - В зале с лампами — 5–6 источников.
   - У двери в начале — 1, поэтому там 103 FPS.
3. **Остальные эффекты вместе стоят меньше одних теней.**
   - RTAO — 1.7 мс (720p) / 3.4 (1008p).
   - RT-отражения — 1–1.7 мс.
   - RTGI — ~1 мс.
   - Сама включённая трассировка без эффектов (структура лучей: 1319 рендереров из 1518) — 0 мс GPU.
4. **Карт теней 150–340,** но кэш теней держит их рисование около 1 мс GPU (CPU 1.6–2.9 мс в редакторе).
   Не узкое место.
5. В редакторе GPU и CPU завышены: те же места в плеере — 12.9–14.1 мс GPU вместо 18.3–22.7.

## Предложения (не сделаны)

По плееру:
- **Поток рендера RT-теней.** Найти, что HDRP делает на CPU на каждый источник (настройка проходов,
  привязка ресурсов, карта теней по запросу у источников «всех теней»). При «Производительности» это сейчас
  упор кадра.
- **Общие ~5 мс трассировки** — разобрать снимком Nsight / RenderDoc. Кандидаты: кластер источников 40 м
  и 16 на ячейку (`LightCluster`), свет в точках попадания (`RaytracingDeferredLighting`).

   `numRayTracingSamples` одинаков для всех трассируемых.
3. Денойзер: для источников с малой долей экрана — меньший `filterSizeTraced` или без фильтра (у HDRP фильтр
   на источник — главная постоянная цена).
4. Найти неучтённые ~4–5 мс при RT-тенях — снимок кадра в RenderDoc / Nsight или профайлер редактора.
5. Замер плеером — сделан (раздел выше).
6. До правок пользователю на 5080 при 1440p: тени «Высокое» вместо «Ультра». По плееру при «Качестве» это
   +10–16% FPS в зале, при «Производительности» — 0–13%.
