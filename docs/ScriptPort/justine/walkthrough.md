# Justine — сквозная проверка проходимости пешком

Дата: 2026-10-18. Прежние проверки Justine (README) вызывали двери уровня как API и проверяли скрипты по сценариям; пешком карты никто не проходил. Эта проверка идёт настоящим контроллером игрока.

## Инструмент

`Assets/Editor/Dev/JustineWalkthrough.cs` (вне git — только код, ресурсов нет):

1. Поиск по сетке 0.5 м цилиндром игрока (стоя / присев, ступени 0.4 м, лестницы-области как связи этажей, падения по параметру) от каждой стартовой области. Двери и лёгкие пропы считаются проходимыми; запертые двери блокируют только «строгий» проход.
2. Настоящий контроллер игрока (`HplCharacterBody`) идёт по найденному пути: двери перед проходом распахиваются, застрявшие лёгкие ящики сдвигаются, присед включается в тоннелях. В конце — взгляд на цель, текст фокуса и прицел.
3. Отчёты: состав связных областей по стартам, двери уровня, предметы, рычаги; «разрывы» (ближайший подход области без двери к области с дверью и что стоит между); недостижимые цели.
4. Команды `walkto` / `pull` в `PlayerSimulation` — шаги настоящих сценариев с пешим ходом и настоящим рычагом.

Запуск и флаги — в CLAUDE.md, раздел «Прогон». Отчёты: `Logs/Justine_Walk_<карта>.txt`.

## Результаты

| Карта | Итог |
|---|---|

Стартовая камера, коридоры и лестницы-области в одну связную область не входят: выход из камеры и подъём требуют решения загадки (рычаг ×3 / лестница) и подъёма по лестнице, лестницы по-прежнему не подтверждены. |
| 02_library | Все три двери уровня пройдены пешком: `level_wood_1` (0.4 с от старта), `level_celler_1` и `level_celler_2` (от нижних стартов 4/5, 10.6 с). Фокус «Камеры» / «Подземелье» / «Туннели». |
| 03_dungeon | Первое звено цепочки пройдено настоящими действиями: поднять рукоятку (скрипт `UseLeverOnMount` вместо предмета), настоящий рычаг `slide_door01_fixedlever` тянется мышью (состояние 0 → −1), первая раздвижная дверь открылась, пешком дошли до `slide_door02_lever_open`. Со всеми раздвижными дверями, открытыми скриптом, обе зоны единые, к выходу `level_dungeon_2` ведёт лестница, которую настоящий контроллер поднимает за 4 с и доходит до двери. Не пройдено пешком с настоящими действиями: колёсико-шестерня и починка машины (вместо них вызван `PuzzleOpenDoor02_FixMachine`), вторая и третья раздвижные двери. |
| 04_final | Дверь уровня `level_wood_1` («Подземелье») — 0.2 с от старта. Область кладбища (старты 3 и 6) отрезана подвижной стеной `crush_wall_2` — достижима только событием комнаты-давилки (скрипт), пешком без него — нет (так задумано оригиналом). |

## Найденные расхождения (не ошибки порта, если не указано)

- Поиск по сетке даёт ложные «недостижимо» на лестницах и тесных проёмах (проверено: `03_dungeon` — лестница к `level_dungeon_2`, `01_cells` — угол тоннеля): настоящий контроллер там проходит. Поиск — предфильтр, решает контроллер.
- Враг Suitor в `03_dungeon` включается открытием первой двери и убивает ходящего без укрытия — это поведение игры; для проверки маршрута ИИ выключен флагом `-noEnemyAI`.
- Двери `cellar_wood01_slow*` (масса 2 кг, затухание 10) после захвата и толчка мышью открываются только до 50–86° и могут снова прикрываться; контроллеру удаётся пройти, но с несколькими попытками. Причина не выяснена (может быть как свойством двери, так и ошибкой моего захвата в тесте); порт не менялся — стоит проверить руками.
- Падение в дыру тоннеля `01_cells` сбрасывает 10 здоровья.

## Что осталось вне пеших проходов

Подъём по лестницам (`PlayerStateLadder` на `01_cells`), шестерня и машина `03_dungeon` (сцена с липкой зоной), комната-давилка `04_final` с её стенами и выход в кладбище, полное пешее прохождение всех четырёх карт подряд с настоящими предметами и использованием из инвентаря.
