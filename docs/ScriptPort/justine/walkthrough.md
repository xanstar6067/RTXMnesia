# Justine — сквозная проверка проходимости пешком

Дата: 2026-10-18, закрыто 2026-10-29. Прежние проверки Justine (README) вызывали двери уровня как API и проверяли скрипты по сценариям; пешком карты никто не проходил. Эта проверка идёт настоящим контроллером игрока.

**Итог 2026-10-29:** все четыре карты пройдены подряд одним прогоном настоящими действиями (пешком, мышью, предметами из инвентаря), через три настоящие двери уровня, до финальных титров. Маршрут — `tools/Justine-Walkthrough.sim`.

## Инструмент

`Assets/Editor/Dev/JustineWalkthrough.cs` (только код, ресурсов нет):

1. Поиск по сетке 0.5 м цилиндром игрока (стоя / присев, ступени 0.4 м, лестницы-области как связи этажей, падения по параметру) от каждой стартовой области. Двери и лёгкие пропы считаются проходимыми; запертые двери блокируют только «строгий» проход.
2. Настоящий контроллер игрока (`HplCharacterBody`) идёт по найденному пути: двери перед проходом распахиваются, застрявшие лёгкие ящики сдвигаются, присед включается в тоннелях. В конце — взгляд на цель, текст фокуса и прицел.
3. Отчёты: состав связных областей по стартам, двери уровня, предметы, рычаги; «разрывы» (ближайший подход области без двери к области с дверью и что стоит между); недостижимые цели.
4. Команды `PlayerSimulation` — шаги настоящих сценариев (Simulation.md):
   - `walkto Имя [падение]` — пешком;
   - `pull Рычаг [состояние]` — потянуть мышью до смены состояния (до заданного);
   - `climb Лестница [up|down]` — подойти, interact, держать вперёд (назад) до схода;
   - `pick Предмет` — подойти, навести, взять; успех — сущность исчезла и предмет в инвентаре;
   - `use Предмет Цель` — подойти, предмет из инвентаря (`HplInventory.Use` → состояние UseItem), клик по цели;
   - `carry Проп Цель` — схватить (interact удерживается) и донести;
   - `wheel Колесо направление секунды` — круги мышью;
   - `door ДверьУровня` — открыть настоящую `PropLevelDoor` и пройти штатный переход `HplMapChange` в следующую карту (сцена открывается в редакторе, новая карта принимает Arrival: игрок, эффекты, музыка, старт; экран загрузки пропускается);
   - `credits` — идут ли титры.

   `-scriptFile путь` — сценарий из файла (команда на строку, `#` — комментарий).

Уточнения помощника 2026-10-29 (как делает человек; порт не трогают): дверь, открывающуюся к игроку, тянуть с шагом назад; у рычага отойти на длину руки (рукоять упиралась в тело); путь сначала с настоящим радиусом тела 0.4, широко открытые створки — препятствие (запасной поиск с 0.3 и сквозь створки); дверь проходить «перед проёмом → середина → за проёмом»; при застревании — новый поиск от текущей точки; прыжок на слишком высокую ступень (`block_box` в 03_dungeon) и за предметом на высоком шкафу; если сетка не видит ступени — до ближайшего пола и дальше прямо; круги мышью по 8° за кадр (распознавание круга `cLuxPlayerState_InteractWheel` работает только на малой дуге последних 10 движений).

## Запуск

```
Unity.exe -batchmode -nographics -quit -projectPath UnityProj/UMnesiaRTX -executeMethod RTXMnesia.EditorDev.PlayerSimulation.RunBatch -amnesiaMap maps/ptest/01_cells.map -seed 1 -noEnemyAI -scriptFile tools/Justine-Walkthrough.sim
```

Без `-scriptDebug`: в отладочном режиме скрипты сами выдают предметы (`03_dungeon` — рукоять, `02_library` — трафареты). ~4 минуты; лог — последний раздел `Logs/AmnesiaImport.log` (прогон 2026-10-29 сохранён как `Logs/JR_route1.txt`).

## Сквозной прогон 2026-10-29

Exit 0, исключений нет; единственная ошибка — известная `CharacterTalkOver` (README). Исходы: VictorIsDead=1 (рычаг), HectorIsDead=0, FelixIsDead=0; титры `ACTIVE`.

| Карта | Настоящими действиями |
|---|---|
| 01_cells | полное вступление (40 с) → фонограф мышью → фонарь `pick` (замок камеры выдёргивается) → двери `prison_section_6`, `prison_1` → рычаг ×3 до состояния 1 (люк выбит, лестница съехала, Victor погиб) → **подъём по `LadderArea_1`** (0 → 7.5 м, 9 с, на верху скрипт телепортирует в тоннель) → лаз, прыжок в дыру (−10 здоровья) → `door level_wood_1` |
| 02_library | `pick stencil04`, `pick stencil03` (на верху шкафа — в прыжке) → оба в прорези из инвентаря → рычаг `slot_machine_1` → «Save prisoner!», потайной шкаф → вниз → `door level_celler_1` |
| 03_dungeon | рукоять `pick` → `use` на крепление → `pull slide_door01_fixedlever` → **шестерня руками** через три двери и ступени до машины, липкая зона её приняла (`MachineFixed`=1) → `pull slide_door02_lever_open` → вентиль камеры Феликса (дверь опущена, FelixIsDead=0) → вентиль выходной двери → `pull slide_door03_lever_close` → по ступеням к `door level_dungeon_2` |
| 04_final | кладбище и лабиринт по пути → **комната-давилка**: стены сходятся (≈70 с), обморок и пробуждение, стены расходятся → вторая дверь → `AreaClarice_1` → скрипт ведёт наверх → `StartCredits` |

Между картами переносятся инвентарь (фонарь), здоровье (90), глобальные переменные.

## Найденные расхождения

- **Ошибка порта, исправлена:** `AmnesiaPlayer.PlaceAtStart` не переводил игрока в Normal, как `cLuxPlayer::PlaceAtStartNode` (`LuxPlayer.cpp:823`). После телепорта `CollideAreaLadderUp` (01_cells) игрок оставался в состоянии Ladder и не мог сойти — поэтому прежние попытки подъёма «не подтверждались».
- Враги Suitor: `There is no node container in enemy 'enemy_suitor_*'` на всех картах — узлы и анимации Suitor не импортируются (README, «Ограничение врагов»). Маршрут идёт с `-noEnemyAI`; погони и атаки Suitor пешим проходом не проверены.
- Поиск по сетке даёт ложные «недостижимо» на лестницах и тесных проёмах (`03_dungeon` — ступени к `level_dungeon_2`, `01_cells` — угол тоннеля, `02_library` — `level_celler_1`): настоящий контроллер там проходит.
- Двери `cellar_wood01_slow*` сами не закрываются (после отпускания стоят, проверено 71.9°); прежние «прикрывания» — игрок толкал створку плечом, идя вдоль петли. Исправлено в помощнике, порт не менялся.
- Падение в дыру тоннеля `01_cells` сбрасывает 10 здоровья.
- Обморок в давилке наступает ≈20 с спустя схождение стен и длится ещё ≈70 с — в сценарии 2026-10-17 его вызывали вручную, теперь он наступил сам.

## Что осталось вне пеших проходов

Другие ветви: спасение Victor (опрокинуть люк брошенным предметом / сложенными ящиками, лестница из инвентаря), убийство Hector и Felix — проверены прежними сценариями скриптов, пешком не проходились. Враги с ИИ — см. выше. Проверка в редакторе (без Play); Play-маршрут дверей — README.
