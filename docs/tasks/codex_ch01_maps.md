# Задача для Codex: импорт и перенос скриптов карт главы 1 (03–14)

Прочитай целиком перед началом. Сначала прочитай `CLAUDE.md` в корне репозитория: там правила проекта, структура и соглашения. Всё, что ниже, их не отменяет.

## Что сделать

Для каждой карты **текущей партии** (см. ниже):
1. **импортировать** карту готовым импортёром (сцена Unity);
2. **перенести скрипт уровня** `.hps` на C# — вручную, функция за функцией, 1:1, по образцу уже готовых карт 00, 01, 02;
3. **написать журнал** переноса `docs/ScriptPort/ch01/<карта>.md`;
4. **проверить** сверкой, прогоном и регрессией (раздел «Проверка»).

Движок **не трогаем**. Всё, чего в движке ещё нет (враги, липкие области, события безумия, кнопки, анимации пропов, сохранения, скайбокс…), уже объявлено в API заглушкой (`NotPorted`): она пишет одно предупреждение в лог. Скрипт просто вызывает эти функции как в оригинале. Когда движок до них дорастёт, порт заработает без изменений. **Все функции движка, которые вызывают карты 03–14, в API уже объявлены** (проверено), добавлять ничего не нужно.

Переходы между картами подключать **не нужно**: импорт сам добавляет сцену в список сборки, а двери уровня и `ChangeMap` находят её по имени.

## Где что лежит

- **Оригиналы скриптов:** `source/maps/main/ch01/<карта>.hps` (AngelScript; кодировка Latin-1). Карта: `<карта>.map` (XML), рядом файлы `.nodes` (пути врагов — не нужны). **Только читать.**
- **Готовые порты-образцы:** `UnityProj/UMnesiaRTX/Assets/Scripts/Levels/Ch01/RainyHall.cs`, `OldArchives.cs`, `EntranceHall.cs`. Открой оригинал и порт рядом и посмотри, как переведено: порядок функций, комментарии, `nameof`, `switch`, циклы, массивы, `Str(...)`.
- **Готовые журналы-образцы:** `docs/ScriptPort/ch01/00_rainy_hall.md`, `01_old_archives.md`, `02_entrance_hall.md`. Формат — `docs/ScriptPort/README.md`.
- **API движка для скриптов:** `UnityProj/UMnesiaRTX/Assets/Scripts/ScriptApi/HplScript*.cs` — функции с оригинальными именами и параметрами. Базовый класс `HplScript`: `OnStart`, `OnEnter`, `OnLeave` (`public override void`). Статусы функций — `docs/ScriptPort/api.md`.
- **Импортированные сцены:** `UnityProj/UMnesiaRTX/Assets/AmnesiaImported/Levels/maps/main/ch01/<карта>.unity` (папка не в git, там ресурсы игры).
- **Сверка оригинал ↔ порт:** `tools/Check-ScriptPort.ps1` (раздел «Проверка», шаг 2).

## Как переносить (правила перевода)

Порт должен читаться как `.hps`: тот же порядок функций, те же имена функций, переменных, строк, те же числа, **те же комментарии** оригинала (они на английском — переносить как есть). Ничего не «улучшать», не объединять, не переупорядочивать, не выбрасывать «ненужное» (отладочные `AddDebugMessage`, `if(ScriptDebugOn())`, неиспользуемые функции — переносить тоже).

1. **Файл:** `Assets/Scripts/Levels/Ch01/<Класс>.cs`, namespace `RTXMnesia.Levels.Ch01`, `using RTXMnesia.ScriptApi;`. Над классом:
   ```csharp
   /// <summary>
   /// Port of maps/main/ch01/<карта>.hps: <1–3 строки, что происходит на карте>.
   /// Journal: docs/ScriptPort/ch01/<карта>.md.
   /// </summary>
   [HplMapScript("maps/main/ch01/<карта>.map")]
   public class <Класс> : HplScript
   ```
2. **Функции.** `void OnStart()` / `OnEnter()` / `OnLeave()` → `public override void ...`. Остальные функции — обычные методы (без модификатора, как в образцах) **с теми же именами и типами параметров**. Сигнатуры коллбэков движка менять нельзя: коллизия `(string asParent, string asChild, int alState)`, таймер `(string asTimer)`, взаимодействие `(string asEntity)`, предмет `(string asItem, string asEntity)` и т.д. — ровно как в `.hps`. Движок вызывает их по имени и проверяет число аргументов.
3. **Коллбэки по имени:** если в вызов передаётся имя функции строкой, а функция объявлена в этом же скрипте — писать `nameof(Имя)` (`AddTimer("t", 1, nameof(TimerX))`). Собираемые строки (`"Timer" + i`) остаются строками. Пустая строка `""` — остаётся `""`.
4. **Глобальные переменные** скрипта (объявленные вне функций) → поля класса с тем же именем и начальным значением. Массивы AngelScript `string[] a = {...}` → `string[] a = {...}`; `int[] a;` + `a.resize(n)` → `int[] a;` + `a = new int[n]` (или `System.Array.Resize`), `a.length()` → `a.Length`.
5. **Числа:** `0.7` → `0.7f`. `int x = RandFloat(...)` → `int x = (int)RandFloat(...)` (AngelScript отбрасывает дробную часть). Целочисленное деление `iX/2` оставить целочисленным, как в оригинале.
6. **Логика:** `or`/`and`/`not` → `||`/`&&`/`!`. `a == false ? true : false` — так и оставить.
7. **`switch`:** в AngelScript `case` без `break` проваливается в следующий; C# так не умеет. Если в оригинале есть провал — писать `goto case N;` и комментарий `// falls through, as in the original`. Каждый `case` переносить полностью, ни одного не пропускать.
8. **Строки с числами.** `"текст" + int` — как есть. `"текст" + float` — **только** через помощник, иначе в русской локали будет запятая:
   ```csharp
   /// <summary>AngelScript string + float (scriptstring addon: ostream, 6 significant digits).</summary>
   static string Str(float f) => f.ToString("G6", CultureInfo.InvariantCulture);
   ```
   (`using System.Globalization;`, как в `EntranceHall.cs`). Это касается и `"..." + GetLocalVarFloat(...)`, и `"..." + RandFloat(...)`.
9. **Ошибки оригинала сохранять.** Если в оригинале выход за границы массива, деление на ноль, неверное имя сущности, функция-коллбэк, которой нет, — порт ведёт себя так же, как игра. Особый случай: в AngelScript исключение (например, индекс за пределами массива) **молча прерывает текущую функцию**. В C# надо повторить именно это поведение (не падать с исключением, а выйти из функции в той же точке) и написать комментарий — см. цикл `aSlime` в `EntranceHall.TimerGuardSlime` и раздел «Особенности» в `02_entrance_hall.md`. Каждую такую ошибку — в журнал.
10. **Комментарии в коде порта** — только оригинальные плюс короткие пояснения на английском там, где перевод неочевиден (`// (int): AngelScript truncates`).
11. **Не копировать код оригинала в документацию** (журналы `.md`) — только ссылки `файл:строка` и описание словами.

## Как делать по шагам (для каждой карты партии)

1. **Импорт карты** (Unity должен быть закрыт — проверь, что нет `UnityProj/UMnesiaRTX/Temp/UnityLockfile`; процесс `unity.exe serve` — это Hub, он не мешает):
   ```
   "C:/Program Files/Unity/Hub/Editor/6000.6.2f1/Editor/Unity.exe" -batchmode -nographics -quit -projectPath UnityProj/UMnesiaRTX -executeMethod RTXMnesia.Importer.ImportMenu.ConvertLevelBatch -amnesiaMap maps/main/ch01/<карта>.map -logFile Logs/Import_<карта>.log
   ```
   Первая карта может импортироваться несколько минут (недостающие модели и звуки импортируются сами). Если сцена уже есть (04, 05 импортированы раньше) — всё равно импортировать заново.
   Результат — в `UnityProj/UMnesiaRTX/Logs/AmnesiaImport.log`: **0 ошибок**. Предупреждения нормальны (FogArea, скайбокс, gobo точечных источников и т.п. — пропускаются импортёром); выписать в отчёт их виды и количество.
   **Если в импорте есть ошибки или исключение — остановиться и написать в отчёт.** Импортёр (`Assets/Editor/Importer/*`) не править.
2. **Порт скрипта** по правилам выше. Идти по `.hps` сверху вниз, без пропусков. Не писать «по смыслу» — переводить строку за строкой.
3. **Сверка** (обязательно, после каждой правки порта):
   ```
   powershell -ExecutionPolicy Bypass -File tools/Check-ScriptPort.ps1 -Map <карта> -Port UnityProj/UMnesiaRTX/Assets/Scripts/Levels/Ch01/<Класс>.cs
   ```
   Что проверяет: все функции `.hps` есть в порте; все строковые константы есть в порте; число вызовов каждой функции совпадает; числа оригинала встречаются в порте; коллбэки, заданные в самой карте `.map`, есть в порте. Нужно **«ошибок 0»**. На готовых 00/01/02 сверка даёт 0 ошибок и 0 предупреждений — у новых карт должно быть так же. Каждое оставшееся предупреждение объяснить в журнале. **Сверку не обманывать** (не вставлять строки и вызовы в комментарии ради счётчика — комментарии она и так не читает, не добавлять фиктивный код). Скрипт сверки не менять.
4. **Прогон карты со скриптом** (без `-nographics`: нужен GPU для снимков; Unity закрыт):
   ```
   "C:/Program Files/Unity/Hub/Editor/6000.6.2f1/Editor/Unity.exe" -batchmode -quit -projectPath UnityProj/UMnesiaRTX -executeMethod RTXMnesia.EditorDev.PlayerSimulation.RunBatch -amnesiaMap maps/main/ch01/<карта>.map -seed 1 -script "watch 30 2; shot start" -logFile Logs/Sim_<карта>.log
   ```
   В `Logs/AmnesiaImport.log` (раздел Player simulation) и в `Logs/Sim_<карта>.log`:
   - **нет исключений** и строк `PortError` / `Exception` / `does not exist in` / `takes N arguments`;
   - строки `[Script] ERROR: ...` — для каждой проверить по `.map` (поиском имени), что такой сущности/света/звука действительно нет в карте. Если **нет** в карте — это ошибка оригинала: записать в журнал. Если **есть** — это ошибка порта (опечатка), исправить;
   - строки `[Script] X: skipped, needs ...` — нормальны, выписать список в журнал (раздел «Не перенесено движком»).
5. **Вызов основных событий.** Во втором прогоне вызвать командой `call` 5–10 главных функций карты (коллизии с областями, взаимодействия, таймеры событий), по одной, с `watch 10 2` после каждой. Формат: `call Функция арг1 арг2 ...`, например `call CollideAreaX Player AreaX 1`. Функции, которые вызывают `ChangeMap`, не вызывать. Цель — убедиться, что нет исключений и `[Script] ERROR` от опечаток. Какие функции вызваны и что получилось — в отчёт.
6. **Журнал** `docs/ScriptPort/ch01/<карта>.md` по образцу `02_entrance_hall.md`:
   - шапка: оригинал, порт (файл, класс, атрибут), статус;
   - таблица **всех** функций и глобальных переменных: оригинал (строка), порт, статус, примечание;
   - «Особенности оригинала» — найденные ошибки оригинала и как они сохранены;
   - «Не перенесено движком» — список функций-заглушек `NotPorted`, которые вызывает карта, и что из-за этого не работает (например: «враг не появляется», «липкая область не держит предмет»);
   - «Проверка» — команды и итог (сверка, прогон, вызванные события).

## Проверка партии (в конце, обязательно, с результатами)

1. Сверка всех карт партии: «ошибок 0».
2. Прогоны всех карт партии: без исключений, все `[Script] ERROR` разобраны.
3. **Регрессия** — запустить и приложить строки PASS:
   - `RTXMnesia.EditorDev.MapChangePreview.RunBatch` (без `-quit` и без `-nographics`): ожидается `PASS: 66 ...`;
   - `RTXMnesia.EditorDev.MainMenuPreview.RunBatch` (так же): ожидается 27 / 50 / 36 / 14 / 14 PASS.

   Если что-то упало — **не чинить движок и не отключать проверку**, а остановиться и написать в отчёт, что упало и после какой карты.

## Что НЕ трогать и чего НЕ делать

- **Менять можно только:** новые файлы `Assets/Scripts/Levels/Ch01/<Класс>.cs` (+ `.meta`, его создаёт Unity), новые `docs/ScriptPort/ch01/<карта>.md`, строку плана в `CLAUDE.md`/`AGENTS.md` (см. «Документация»).
- **Не менять** ничего в `Assets/Scripts/ScriptApi/`, `Player/`, `Props/`, `Effects/`, `Sound/`, `World/`, `Dynamics/`, `Particles/`, `Ui/`, `Assets/Editor/`, `Assets/Shaders/`, `tools/`, настройки HDRP. Даже если кажется, что функция API работает неправильно или заглушка «легко дописывается» — **не трогать**, а написать в отчёте: какая функция, на какой карте, что не так.
- **Не трогать готовые порты** `RainyHall.cs`, `OldArchives.cs`, `EntranceHall.cs`, `InventoryScript.cs` и их журналы.
- **Не удалять, не переименовывать и не «чистить»** чужой код, ассеты, сцены, предметы, тесты, импортированные ресурсы. Никаких массовых замен по проекту.
- **Не менять** установленную игру `E:\SteamLibrary\...`, папки `src/` и `source/`.
- **Не коммитить** и не пушить (коммитит пользователь). Ресурсы Amnesia (`source/`, `Assets/AmnesiaImported/`) в git не попадают никогда; в `git status` их быть не должно.
- Импорт карты сам дописывает её сцену в `ProjectSettings/EditorBuildSettings.asset` и `Assets/Settings/Build Profiles/Windows.asset` — **это ожидаемо, не откатывать**. Если Unity сам пересохранит `ProjectSettings/TimeManager.asset` — вернуть: `git checkout -- UnityProj/UMnesiaRTX/ProjectSettings/TimeManager.asset`. Другие изменения в `ProjectSettings` — откатить и упомянуть в отчёте.
- Не переносить «по смыслу», не пропускать функции «потому что движок не умеет», не заменять вызовы заглушек своими обходами. Заглушка вызывается как в оригинале — и всё.
- Не запускать Unity, пока открыт редактор (lock-файл).

## Отчёт в конце партии

1. Список новых и изменённых файлов.
2. По каждой карте: импорт (0 ошибок, виды предупреждений), итоговая строка сверки, `[Script] ERROR` и как разобраны, список заглушек `skipped, needs`, вызванные события и результат.

6. Вывод `git status --short`.
