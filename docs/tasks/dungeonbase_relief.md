# Задание: объёмный матовый `dungeonbase` и следующие стены (план на 2026-10-25)

Отдельный чат. Перед началом прочитать `CLAUDE.md`, `docs/EnhancedRelief.md` (особенно «Проба: стена, пол
и доски по исходным картам HPL» и «Атлас dungeonbase»), `docs/DevRoom.md`, `docs/TextureBatch.md` («Проход ×2»).

## Цель

Довести стены подземелья до качества трёх уже утверждённых материалов главы 1 — замковая стена
`castlebase_wall`, каменный пол `castlebase_floor`, доски `cellarbase_wood_floor`: настоящий объём
(утопленные швы, скосы, тени от камней) и **матовый камень без «стеклянного» блеска**. Простой
замены текстур на новые PBRify ×2 мало: их шероховатость и высота повторяют яркость альбедо (у
`castlebase_wall` корреляция 0.95 / 0.97), тёмные крапины становятся глянцевыми ямками.

## Что уже есть (2026-10-24, не закоммичено)

- Набор PBRify ×2 для атласа: `sourceRTXRemix/static_objects/dungeonbase/dungeonbase/pbrify-x2-batch-v1/`
  (albedo, normal_ogl, roughness, height, 4096), импортирован как «Улучшенные» (`HplEnhancedMaterials/.../dungeonbase.mat`,
  DDS в `AmnesiaImported/Enhanced/static_objects/dungeonbase/`).
- Ручной рельеф по карте глубины HPL: `tools/Build-ManualRelief.py dungeon` →
  `.../dungeonbase/manual-relief-v1/` (2048, шесть каменных участков атласа, маска камней, высота, нормаль, маска).
  Сейчас строится из **классических** альбедо / нормали / маски.
- Стенд `DungeonReliefDevRoomStand` в `dev_room` (x 9.6 / 12.0 / 14.4): классика, рельеф при бюджете
  игры (92 тыс. треуг.), сетка 1 см. Первые образцы 1–3 стенда рельефа удалены по решению пользователя.
- Замечания со снимков: лица блестят сильнее классики; на боковых гранях обрамления — «капли» швов
  из карты глубины HPL; тонкая светлая линия на стыке граней с разрывом UV (T-стык подразделения).

## Шаги

1. **Эталон блеска.** На стенде `dev_room` снять при одном скользящем свете (растр и RT-отражения
   «Среднее») утверждённую замковую стену (образец 5), классический `dungeonbase` и новый улучшенный
   `dungeonbase` без рельефа. Посчитать среднюю яркость бликов на лицах и в швах — числовой ориентир
   «не стекло». Проверить, что у утверждённых профилей реально стоит: F0 0.04, шероховатость лиц
   0.76–0.9, швы 0.93–0.95, LitSpecular или нет.
2. **Источники карт ×2.** В `Build-ManualRelief.py dungeon` перейти на 4096: альбедо — новый PBRify,
   мелкая деталь нормали — из `normal_ogl` PBRify (вместо классической нормали), маска камней и
   высота — по-прежнему из глубины HPL (масштаб ×2). Шероховатость PBRify **не брать напрямую**:
   лица — свой диапазон по образцу утверждённых (с разбросом, но с полом не ниже ~0.75), швы ~0.95,
   ямки и тёмные пятна — не глаже лица. В G маски — затенение шва (AO), как у стены.
3. **Объём.** Сохранить профиль замковой стены (лица ±1–3 мм, скос 16 мм, шов 20 мм), проверить, не
   стоит ли углубить швы бута (`rubble`, `rubble2`) — у них камни крупнее. Исправить «капли» на боковых
   гранях обрамления (сгладить/обрезать края участка `ashlar`) и T-стык на разрывах UV в
   `HplReliefMeshBuilder` (если он не только стенда).
4. **Стенд.** Обновить `DungeonReliefDevRoomStand`: 1 — классика, 2 — улучшенные без рельефа, 3 — рельеф
   при бюджете игры, 4 — сетка 1 см; скользящий свет, снимки `InstallAndRenderBatch` (растр, RT, path
   tracing по возможности). Показать пользователю, **ждать решения** перед шагом 5.
5. **Игра (после одобрения).** Запись `dungeonbase` в `ApprovedReliefProfiles` (ручные карты),
   `EnhancedReliefConverter.ConvertApprovedBatch`. Внимание к объёму: ~9200 экземпляров на 16 картах —
   посчитать варианты, треугольники и память каталога, при необходимости снизить бюджет на модуль.
   Проверить `SeparateSharedWalls` (стены спина к спине), декали, углы и проёмы на одной карте главы 2
   (например `15_prison_north`) снимками `PlayViewPreview` / `EnhancedLightingPreview` (`tex`).
   Тесты: `EnhancedReliefTests.RunBatch`, `ApprovedLevelReliefTests.RunBatch` / `RunPlayBatch`, `BuildCheck`.
6. **Следующие материалы** по рейтингу площади глав 2–3 и Justine (подсчёт 2026-10-24): `torture_chancel`,
   `stone_round`, `castlebase_wall_extension`, плоскости `cobbled_stone`, `dungeonbase_floor`, `dirt_mould`.
   Для каждого — та же схема: форма из карты глубины / нормали HPL, матовость по утверждённым профилям.
   Можно сделать общий режим в `Build-ManualRelief.py`, если карты HPL позволяют.

## Правила

- Ресурсы Amnesia и результаты апскейла не коммитятся; коммит — только по просьбе пользователя.
- Unity для batch закрыт (`Temp/UnityLockfile`); снимок `ProjectSettings` до и сверка после каждого прогона.
- Фоновые проверки без звука. Классическое освещение и классические материалы не трогать.
- Стенд рельефа (`DevRoomReliefBuilder`) не перестраивать: из него читается профиль досок.
- Python с numpy/scipy/Pillow — `%USERPROFILE%/AppData/Local/Comfy-Desktop/ComfyUI-Installs/ComfyUI/ComfyUI/.venv/Scripts/python.exe`.
- Итоги — в `docs/EnhancedRelief.md` / `docs/DevRoom.md`; при изменении правил — `CLAUDE.md` и `AGENTS.md` одинаково.
